Recognition rules

The judgment calls that separate these problems from each other.

1

Swap "for each i, its divisors" for "for each d, its multiples". The harmonic sum ∑ X/d = O(X log X). See Counting Divisors, Common Divisors, and Sum of Divisors (∑σ(i) = ∑ d·⌊n/d⌋).

2

When n reaches \(10^{12}\)–\(10^{15}\), count contributions, not numbers: per bit position (Counting Bits), or per block of equal ⌊n/d⌋ (Sum of Divisors).

3

An exponent of \(10^{9}\) or more means square-and-multiply in O(log b). See Exponentiation, Exponentiation II, and the inverse of 2 in Sum of Divisors (\(\text{mpow}(b, \text{MOD}-2)\)).

4

A product of two values near \(10^{9}\) or larger must be shrunk first: divide before multiplying (a / gcd * b in Next Common Height), or reduce both operands mod p (mmul in Sum of Divisors).

5

When the answer is the one thing that doesn't cancel, fold everything into one accumulator and store nothing. Missing Number uses XOR pairs. Weird Algorithm uses a plain state loop, with the terminal value printed outside it.

1 · Simulation & bits

No clever structure, just a scalar accumulator. Sometimes the process really is short (Collatz). Sometimes it isn't, and each bit is counted as a periodic pattern.

Weird Algorithm

\(O(\text{steps})\)
The ask

Question. Start from a positive integer \(n\). If \(n\) is even, divide it by \(2\); if it is odd, replace it by \(3n + 1\). Repeat until \(n = 1\). Print every value \(n\) takes, including the first value and the final \(1\).

Input
One integer \(n\).
Output
All values of \(n\) in order, separated by spaces.
Limits
\(1 \le n \le 10^6\)
Sample
\(3\) → 3 10 5 16 8 4 2 1
Breakdown
  1. State the sequence exactly: \[ n_0 = n, \qquad n_{k+1} = \begin{cases} n_k / 2 & \text{if } n_k \text{ is even} \\ 3 n_k + 1 & \text{if } n_k \text{ is odd} \end{cases}, \qquad \text{stop when } n_k = 1 \]
  2. There is nothing to optimise: the output is every value, so simulate.
  3. Simplest form: loop while \(n \ne 1\), print, apply the rule; print \(1\) after the loop. For \(n \le 10^6\) the values reach \(56\,991\,483\,520 \gt 2^{31}\), so use long long.
Key observations
  1. There is nothing to add up, so print every value.
  2. \(1\) must not enter the rule (\(1 \to 4 \to 2 \to 1\) loops forever), so print it after the loop.
  3. For \(n \le 10^6\), the longest run is \(524\) steps (from \(837799\)). The values peak at \(56\,991\,483\,520\) (from \(704511\)), which overflows int.
Brute force → why it dies
naiveSimulate.
cost\(O(\text{steps})\), at most \(524\).
dies atNothing on time. int overflows at the \(5.7\cdot 10^{10}\) peak.
thereforeThe simulation is the solution. Only the type matters: long long.
Implementation

The loop is while (n != 1): print, then transform. The final 1 prints outside the loop, which also makes input 1 correct with no special case.

// Problem: Weird Algorithm (Collatz sequence)
// Link: CSES 1068
// Pattern: simulate with a loop, print each state, exit right after the terminal value
// Time: O(steps) per input, steps bounded by known Collatz behavior for n <= 1e6
// Space: O(1)
//
// n even -> n/2, n odd -> 3n+1, repeat until n == 1. Print every value n
// takes, including the initial n and the final 1.
//
// Example:
//     3 -> 3 10 5 16 8 4 2 1

#include <iostream>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    long long n;
    cin >> n;

    while (n != 1) {
        cout << n << ' ';
        if (n % 2 == 0) n /= 2;
        else n = 3 * n + 1;
    }
    cout << 1 << '\n';

    return 0;
}
import sys
tok = iter(sys.stdin.read().split())

def main():
    n = int(next(tok))
    out = []
    while n != 1:
        out.append(n)
        if n % 2 == 0: n //= 2              # n /= 2 -> n //= 2 (keeps it an int)
        else: n = 3 * n + 1
    out.append(1)
    print(' '.join(map(str, out)))

Missing Number

\(O(n)\)
The ask

Question. You are given all numbers \(1, 2, \dots, n\) except one, in any order. Find the missing number.

Input
\(n\), then \(n - 1\) distinct numbers from \(1..n\).
Output
The missing number.
Limits
\(2 \le n \le 2\cdot 10^5\)
Sample
\(n = 5\), 2 3 1 5 → 4
Breakdown
  1. Use bitwise XOR, written \(\oplus\). It has three useful rules: \[ v \oplus v = 0, \qquad v \oplus 0 = v, \qquad \text{order does not matter} \]
  2. XOR all of \(1..n\) together with all the given numbers. Every present number appears twice and cancels; the missing number \(x\) appears once: \[ x = \big(1 \oplus 2 \oplus \cdots \oplus n\big) \oplus \big(a_1 \oplus \cdots \oplus a_{n-1}\big) \]
  3. Simplest form: one running XOR while reading, no array. (The sum \(\frac{n(n+1)}{2} - \sum a_i\) works too.)
Key observations
  1. \(v \oplus v = 0\), and XOR does not care about order.
  2. Every present number appears twice and cancels. Only the missing one survives.
  3. Fold each number in as it is read, with no array.
Brute force → why it dies
naiveSort, or use a seen[] array, and look for the gap.
cost\(O(n \log n)\) time or \(O(n)\) memory.
dies atIt passes at \(n \le 2\cdot 10^5\); it only loses on memory and code length.
thereforeXOR accumulator: \(O(n)\) time, \(O(1)\) space.
Diagram
Implementation

The first loop XORs 1..n. The second XORs the n−1 inputs as they are read. x is long long, which isn't needed because XOR never exceeds \(2^{18}\).

// Problem: Missing Number
// Link: CSES 1083
// Pattern: XOR 1..n with the given values — duplicates cancel, only the missing one survives
// Time: O(n)  Space: O(1)
//
// Given n and n-1 distinct values from 1..n, find the missing one.
//
// Example:
//     n=5, [2 3 1 5] -> 4

#include <iostream>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n;
    cin >> n;

    long long x = 0;
    for (int i = 1; i <= n; i++) x ^= i;

    int v;
    for (int i = 0; i < n - 1; i++) {
        cin >> v;
        x ^= v;
    }

    cout << x << '\n';
    return 0;
}
import sys
tok = iter(sys.stdin.read().split())

def main():
    n = int(next(tok))
    x = 0
    for i in range(1, n + 1): x ^= i
    for i in range(n - 1):
        v = int(next(tok))
        x ^= v
    print(x)

Recognize"everything appears in pairs except one" → XOR everything together.

Counting Bits

\(O(\log n)\)
The ask

Question. Count the total number of one bits in the binary forms of all integers from \(1\) to \(n\).

Input
One integer \(n\).
Output
The total number of one bits.
Limits
\(1 \le n \le 10^{15}\)
Sample
\(7\) → 12 (\(1, 10, 11, 100, 101, 110, 111\))
Breakdown
  1. Count bit by bit. Going \(0, 1, 2, \dots\), bit \(i\) repeats a pattern of length \(B = 2^{i+1}\): \(2^i\) zeros, then \(2^i\) ones.
  2. In \(0..n\) there are \(\lfloor n / B \rfloor\) full patterns, each with \(B/2\) ones. The leftover part has length \((n \bmod B) + 1\), and its ones start at position \(B/2\): \[ \text{ones}_i = \left\lfloor \frac{n}{B} \right\rfloor \cdot \frac{B}{2} \;+\; \max\!\Big(0,\ (n \bmod B) - \frac{B}{2} + 1\Big) \]
  3. Simplest form: add over the bits; \(n \le 10^{15} \lt 2^{50}\), so about \(50\) terms: \[ \text{ans} = \sum_{i \ge 0,\ 2^i \le n} \text{ones}_i \] Sample \(n = 7\): bits \(0, 1, 2\) give \(4 + 4 + 4 = 12\).
Key observations
  1. Counting from \(0\), bit \(i\) has period \(2^{i+1}\): \(2^i\) zeros, then \(2^i\) ones.
  2. Full periods in \(0..n\) contribute \(\lfloor n/B \rfloor \cdot B/2\).
  3. The leftover part has length \((n \bmod B) + 1\), and its ones start at offset \(B/2\).
  4. \(n \le 10^{15}\) needs about \(50\) bits, so there are about \(50\) terms.
Brute force → why it dies
naiveAdd __builtin_popcountll(i) for every \(i\).
cost\(O(n)\)
dies at\(n = 10^{15}\) iterations.
thereforeCount per bit position: \(O(\log n)\).
Diagram
Implementation

The loop runs while (1LL << i) <= n, so only bits that can be set are counted. It counts over 0..n, and 0 adds nothing. The commented-out popcount loop above it is the brute force.

2 · GCD / LCM

Two periodic events line up every lcm steps. Euclid gives the gcd in O(log), and \(\operatorname{lcm} = a / \gcd \cdot b\) keeps the product small.

Next Common Height

\(O(\log \min (a,b))\)
The ask

Question. Two climbers both start at height \(x\). One goes up by \(a\) each move and the other by \(b\) each move. What is the next height strictly above \(x\) that both of them will stand on? There are \(T\) test cases.

Input
\(T\), then \(T\) lines \(x\ a\ b\).
Output
For each case, the next common height.
Limits
Not given in the file.
Sample
\((1,1,2) \to 3\); \((1,19,19) \to 20\); \((17,2,3) \to 23\)
Breakdown
  1. Climber 1 visits \(x + ka\), climber 2 visits \(x + jb\) (\(k, j \ge 1\)). A shared height needs \[ ka = jb = t \;\Longrightarrow\; t \text{ is a common multiple of } a \text{ and } b \]
  2. The smallest positive common multiple is the least common multiple: \[ \operatorname{lcm}(a, b) = \frac{a \cdot b}{\gcd(a, b)} \]
  3. Simplest form, dividing first so the product does not overflow: \[ \text{ans} = x + \frac{a}{\gcd(a, b)} \cdot b \] Sample \((17, 2, 3)\): \(\operatorname{lcm} = 6\), so \(23\).
Key observations
  1. A shared height is \(x + k a = x + j b\), so the offset is a common multiple of \(a\) and \(b\).
  2. The smallest positive common multiple is \(\operatorname{lcm}(a, b)\).
  3. \(\gcd\) by Euclid: a %= b; swap until \(b = 0\).
Brute force → why it dies
naiveStep \(h = x + a, x + 2a, \dots\) until \((h - x) \bmod b = 0\).
cost\(O(b / \gcd(a, b))\) per test.
dies atCoprime \(a, b\) near \(10^9\) give \(10^9\) steps per test.
thereforeClosed form via \(\gcd\): \(O(\log \min(a, b))\).
Diagram
Implementation

This is a hand-written iterative gcd, not std::gcd. The one line that matters is a / gcd(a, b) * b: divide first.

// Problem: Next Common Height (Nandu and Chandu)
// Pattern: LCM of two step sizes — divide-before-multiply to avoid overflow
// Time: O(log(min(a,b))) per test case  Space: O(1)
//
// Both start at height x. One jumps up by a each move, the other by b each
// move. T test cases, each (x, a, b). Output the next height (strictly above
// x) both will visit.
//
// Example:
//     (1, 1, 2)  -> 3
//         (1, 19, 19) -> 20
//         (17, 2, 3) -> 23

#include <iostream>
using namespace std;

long long gcd(long long a, long long b) {
    while (b) {
        a %= b;
        swap(a, b);
    }
    return a;
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int t; cin >> t;
    while (t--) {
        long long x, a, b;
        cin >> x >> a >> b;
        long long lcm = a / gcd(a, b) * b;
        cout << x + lcm << '\n';
    }
    return 0;
}
import sys
tok = iter(sys.stdin.read().split())

def gcd(a, b):                              # built-in: math.gcd(a, b)
    while b:
        a %= b
        a, b = b, a                         # swap(a, b)
    return a

def main():
    out = []
    t = int(next(tok))
    for _ in range(t):
        x, a, b = int(next(tok)), int(next(tok)), int(next(tok))
        lcm = a // gcd(a, b) * b            # divide-first matters for overflow in C++; Python never overflows
        out.append(x + lcm)
    print('\n'.join(map(str, out)))

3 · Modular exponentiation

Square the base and halve the exponent each round, multiplying the base into the result when the low bit is set. For a tower of powers mod a prime p, reduce the upper exponent mod p−1.

Exponentiation

\(O(n \log b)\)
The ask

Question. Answer \(n\) queries: for each pair \(a, b\), compute \(a^b \bmod (10^9 + 7)\). Assume \(0^0 = 1\).

Input
\(n\), then \(n\) lines \(a\ b\).
Output
For each query, \(a^b \bmod (10^9 + 7)\).
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 0 \le a, b \le 10^9\)
Sample
\((3, 4) \to 81\); \((2, 8) \to 256\); \((123, 123) \to 921450052\)
Breakdown
  1. Write \(b\) in binary, \(b = \sum_j b_j 2^j\) with \(b_j \in \{0, 1\}\). Then \[ a^b = \prod_{j : b_j = 1} a^{2^j} \]
  2. Each power \(a^{2^j}\) is the square of the previous one: \(a^{2^{j+1}} = \big(a^{2^j}\big)^2\).
  3. Simplest form, about \(30\) rounds since \(b \lt 2^{30}\): \[ \text{if } b \text{ odd: } r \leftarrow r \cdot a; \qquad a \leftarrow a^2; \qquad b \leftarrow \lfloor b/2 \rfloor \] All values stay below \(p \approx 10^9\), so each product is below \(10^{18}\) and fits in long long.
Key observations
  1. \(b\) in binary picks which of \(a, a^2, a^4, a^8, \dots\) to multiply together.
  2. Each is the square of the previous one, so a loop of about \(30\) rounds is enough.
  3. Operands are below \(p \approx 10^9\), so each product is below \(10^{18}\) and fits ll.
Brute force → why it dies
naiveMultiply by \(a\), \(b\) times.
cost\(O(b)\) per query.
dies at\(b = 10^9\), \(n = 2\cdot 10^5\) gives \(2\cdot 10^{14}\).
thereforeBinary exponentiation: \(O(\log b)\) per query.
Diagram
Implementation

mmul does (a*b) % MOD without reducing the operands first. That is safe here only because every input a is ≤ \(10^{9}\) < MOD. This file has no pasted statement block (CSES 1095).

Exponentiation II

\(O(n \log p)\)
The ask

Question. Answer \(n\) queries: for each triple \(a, b, c\), compute \(a^{(b^c)} \bmod p\) with \(p = 10^9 + 7\). Assume \(0^0 = 1\).

Input
\(n\), then \(n\) lines \(a\ b\ c\).
Output
For each query, \(a^{(b^c)} \bmod (10^9 + 7)\).
Limits
\(1 \le n \le 10^5,\ \ 0 \le a, b, c \le 10^9\)
Sample
\((3,7,1) \to 2187\); \((15,2,2) \to 50625\); \((3,4,5) \to 763327764\)
Breakdown
  1. \(p\) is prime. Fermat's little theorem: if \(p \nmid a\), then \[ a^{p-1} \equiv 1 \pmod p \]
  2. So the exponent only matters modulo \(p - 1\). Write \(b^c = q(p-1) + e\): \[ a^{(b^c)} = \big(a^{p-1}\big)^q \cdot a^{e} \equiv a^{e} \pmod p, \qquad e = b^c \bmod (p - 1) \]
  3. Since \(a \le 10^9 \lt p\), the condition \(p \nmid a\) fails only for \(a = 0\). Then the answer is \(1\) if \(b^c = 0\) (that is, \(b = 0\) and \(c \ge 1\)) and \(0\) otherwise.
  4. Simplest form: two fast powers with different moduli: \[ e = \text{mpow}(b, c, p - 1), \qquad \text{ans} = \text{mpow}(a, e, p) \]
Key observations
  1. Fermat: \(a^{p-1} \equiv 1 \pmod p\) when \(p \nmid a\), so exponents can be taken mod \(p - 1\).
  2. The inner power is mpow(b, c, p-1): the same function with a different modulus.
  3. \(a \le 10^9 \lt p\), so \(p \mid a\) only when \(a = 0\). Handle \(a = 0\) by hand.
  4. \(0^{(b^c)}\) is \(1\) exactly when \(b^c = 0\), which means \(b = 0\) and \(c \ge 1\).
Brute force → why it dies
naiveCompute \(b^c\) exactly, then \(a\) to that power.
cost\(b^c\) has up to about \(3\cdot 10^{10}\) bits.
dies at\(b, c \le 10^9\): the number cannot even be stored.
thereforeReduce the exponent mod \(p - 1\), then two fast powers: \(O(\log p)\) per query.
Diagram
Implementation

mmul and mpow take a default mod = MOD parameter, so one pair serves both levels. The two zero guards run before Fermat is applied. Case a = 0, b = 0, c = 0 gives bc = 1, so 01 = 0.

4 · Divisors & multiples

Every divisor question can be turned around: instead of asking what divides i, ask which multiples each d reaches. Loop d over its multiples in O(X log X) total. For n up to \(10^{12}\), group the d with equal ⌊n/d⌋.

Counting Divisors

\(O(X \log X + n)\)
The ask

Question. You are given \(n\) integers. For each one, print how many divisors it has. For example, \(18\) has \(6\) divisors: \(1, 2, 3, 6, 9, 18\).

Input
\(n\), then \(n\) integers \(x\).
Output
For each \(x\), the number of its divisors \(\tau(x)\).
Limits
\(1 \le n \le 10^5,\ \ 1 \le x \le 10^6\)
Sample
\(16 \to 5\); \(17 \to 2\); \(18 \to 6\)
Breakdown
  1. State it exactly, where \(i \mid x\) means "\(i\) divides \(x\)": \[ \tau(x) = \#\{\, i : 1 \le i \le x,\ i \mid x \,\} \]
  2. Turn it around: \(i \mid j\) exactly when \(j\) is a multiple of \(i\). So each \(i\) adds \(1\) to every multiple of itself: \[ \text{for } i = 1..X: \quad \text{for } j = i, 2i, 3i, \dots \le X: \quad \tau[j] \mathrel{+}= 1 \]
  3. The total work is a harmonic sum: \[ \sum_{i=1}^{X} \frac{X}{i} \approx X \ln X \approx 1.4\cdot 10^7 \quad (X = 10^6) \]
  4. Simplest form: build \(\tau[1..10^6]\) once, then each query is a lookup.
Key observations
  1. \(i\) divides \(j\) iff \(j\) is a multiple of \(i\), so each \(i\) adds \(1\) to all its multiples.
  2. \(\sum_{i \le X} X/i \approx X \ln X \approx 1.4\cdot 10^7\) for \(X = 10^6\).
  3. Build the table once; then each query is a lookup.
Brute force → why it dies
naiveTrial division up to \(\sqrt{x}\) for each query.
cost\(O(n \sqrt{X})\)
dies at\(n = 10^5,\ X = 10^6\) gives \(10^8\) modulo operations, borderline at 1 s.
thereforeHarmonic sieve: \(O(X \log X)\) once, \(O(1)\) per query.
Diagram
Implementation

pre() runs once after reading t. d is a global ll[1000001], which is 8 MB, zero-initialised, and off the stack. The commented-out solve is the √x brute force.

Common Divisors

\(O(X \log X)\)
The ask

Question. You are given an array of \(n\) positive integers. Choose two of them so that their greatest common divisor is as large as possible, and print that gcd.

Input
\(n\), then \(x_1, \dots, x_n\).
Output
One integer: the largest \(\gcd(x_i, x_j)\) over \(i \ne j\).
Limits
\(2 \le n \le 2\cdot 10^5,\ \ 1 \le x_i \le 10^6\)
Sample
3 14 15 7 9 → 7 (\(\gcd(14, 7)\))
Breakdown
  1. If \(g\) divides two elements, their gcd is at least \(g\). And the gcd itself divides both. So \[ \max_{i \ne j} \gcd(x_i, x_j) = \max \big\{\, g : \#\{ i : g \mid x_i \} \ge 2 \,\big\} \]
  2. With a count array \(\text{freq}[v]\), the number of elements divisible by \(g\) is \[ \text{cnt}(g) = \sum_{k \ge 1} \text{freq}[k g] \]
  3. Simplest form: try \(g = 10^6, 10^6 - 1, \dots\) and stop at the first \(g\) with \(\text{cnt}(g) \ge 2\). Even the full scan is a harmonic sum, \(O(X \log X)\).
Key observations
  1. If \(g\) divides two elements, their gcd is \(\ge g\). So the answer is the largest \(g\) that divides at least two elements.
  2. Count the elements divisible by \(g\) with a count array: \(\sum_k \text{freq}[k g]\).
  3. Try \(g\) from the maximum down and stop at the first count \(\ge 2\). The whole scan is still harmonic, \(O(X \log X)\).
Brute force → why it dies
naive\(\gcd\) of every pair.
cost\(O(n^2 \log X)\)
dies at\(n = 2\cdot 10^5\) gives \(2\cdot 10^{10}\) pairs.
thereforeLoop over the answer \(g\) and count multiples: \(O(X \log X)\), \(X = 10^6\).
Diagram
Implementation

freq is sized to the actual max, not \(10^{6}\). The downward loop returns on the first hit. g = 1 always has cnt = n ≥ 2, so the loop always prints.

Sum of Divisors

\(O(\sqrt n \log p)\)
The ask

Question. Let \(\sigma(i)\) be the sum of the divisors of \(i\); for example \(\sigma(12) = 1 + 2 + 3 + 4 + 6 + 12 = 28\). Compute \(\sigma(1) + \sigma(2) + \dots + \sigma(n)\) modulo \(10^9 + 7\).

Input
One integer \(n\).
Output
\(\sum_{i=1}^{n} \sigma(i) \bmod (10^9 + 7)\).
Limits
\(1 \le n \le 10^{12}\)
Sample
\(5\) → 21 (\(1 + 3 + 4 + 7 + 6\))
Breakdown
  1. Swap the order of summation. Each \(d\) is a divisor of the \(\lfloor n/d \rfloor\) numbers \(d, 2d, \dots \le n\), and adds \(d\) to each: \[ \sum_{i=1}^{n} \sigma(i) = \sum_{i=1}^{n} \sum_{d \mid i} d = \sum_{d=1}^{n} d \left\lfloor \frac{n}{d} \right\rfloor \]
  2. \(\lfloor n/d \rfloor\) takes at most \(2\sqrt{n}\) different values. Group the \(d\) with the same value \(v\) into a block \([l, r]\): \[ v = \left\lfloor \frac{n}{l} \right\rfloor, \qquad r = \left\lfloor \frac{n}{v} \right\rfloor \]
  3. Inside a block, \(\sum d\) is an arithmetic series: \[ \sum_{d=l}^{r} d \cdot v = v \cdot \frac{(l + r)(r - l + 1)}{2} \]
  4. Simplest form: walk the blocks \(l = 1,\ l \leftarrow r + 1\). About \(2\cdot 10^6\) blocks for \(n = 10^{12}\). The \(/2\) is done mod \(p\) by multiplying with \(2^{-1}\).
Key observations
  1. \(d\) divides exactly \(\lfloor n/d \rfloor\) numbers \(\le n\), and adds \(d\) to each of them.
  2. \(\lfloor n/d \rfloor\) takes at most \(2\sqrt{n}\) different values, so group the \(d\) into blocks.
  3. Inside a block, \(\sum d\) is an arithmetic series.
  4. The series needs \(/2\). After reducing mod \(p\) that means multiplying by the inverse of \(2\).
Brute force → why it dies
naive\(\sum_d d \lfloor n/d \rfloor\) one \(d\) at a time, or a \(\sigma\) sieve.
cost\(O(n)\)
dies at\(n = 10^{12}\) iterations.
thereforeQuotient blocks: \(O(\sqrt{n})\), about \(2\cdot 10^6\) blocks.
Diagram
Implementation

Every helper reduces its operands before combining them, which is needed because l and r reach \(10^{12}\). mdiv(…, 2) multiplies by \(\text{mpow}(2, \text{MOD}-2)\). l = r + 1 jumps to the next block.
