Recognition rules

The judgment calls that separate these problems from each other.

1

Answer is "count the arrangements, mod \(10^{9}+7\)" → the same fact / invfact block every time. Write it once, then the problem is one ncr call: Binomial Coefficients, Creating Strings II, Distributing Apples.

2

"Distribute m identical things into n distinct boxes" → stars and bars, C(m+n−1, n−1). Size MAXN for m + n, not for n: Distributing Apples.

3

No closed form but the n case reduces to n−1 and n−2 by a case split on one element → write the recurrence and iterate it: Christmas Party.

4

"Count pairs with gcd = 1" or any condition over divisors → count pairs sharing a divisor d for every d, then inclusion–exclusion by ω(d): Counting Coprime Pairs.

5

n up to \(10^{12}\) but t small → sieve to √n once, then trial-divide each query by the sieved primes: Next Prime. A sieve to n itself is not an option.

1 · Factorials mod p

Everything here runs on one precomputed block: fact[i], and invfact[i] built backwards from a single modular inverse of fact[MAXN-1], using \(\text{invfact}[i] = \text{invfact}[i+1] \cdot (i+1)\). One mpow, not MAXN of them. After that ncr is three multiplications.

Binomial Coefficients

\(O(\text{MAX} + t)\)
The ask

Question. Answer \(t\) queries: for each pair \(a, b\), compute the binomial coefficient \(\binom{a}{b}\) (the number of ways to choose \(b\) items out of \(a\)) modulo \(10^9 + 7\).

Input
\(t\), then \(t\) lines \(a\ b\).
Output
For each query, \(\binom{a}{b} \bmod (10^9 + 7)\).
Limits
\(1 \le t \le 10^5,\ \ 0 \le b \le a \le 10^6\)
Sample
\((5,3) \to 10\); \((2,1) \to 2\); \((10,5) \to 252\)
Breakdown
  1. The formula: \[ \binom{n}{r} = \frac{n!}{r!\,(n-r)!} \]
  2. Modulo a prime \(p\), dividing means multiplying by an inverse. By Fermat, \(x^{p-1} \equiv 1\), so \[ x^{-1} \equiv x^{p-2} \pmod p, \qquad \binom{n}{r} \equiv n! \cdot (r!)^{-1} \cdot ((n-r)!)^{-1} \pmod p \]
  3. Precompute \(\text{fact}[i] = i!\). For the inverses, compute only the last one with a power, then walk down, because \(\frac{1}{i!} = \frac{1}{(i+1)!} \cdot (i + 1)\): \[ \text{invfact}[N] = \text{fact}[N]^{\,p-2}, \qquad \text{invfact}[i] = \text{invfact}[i+1] \cdot (i + 1) \]
  4. Simplest form: each query is two multiplications, \(\text{fact}[a] \cdot \text{invfact}[b] \cdot \text{invfact}[a-b]\).
Key observations
  1. \(p = 10^9 + 7\) is prime, so by Fermat \(a^{-1} \equiv a^{p-2}\). That is what minv computes.
  2. One inverse costs \(O(\log p)\); doing that for all \(10^6\) values is about \(3\cdot 10^7\) multiplications. Instead invert only fact[MAXN-1] and walk down: \(\text{invfact}[i] = \text{invfact}[i+1] \cdot (i+1)\), because \((i!)^{-1} = ((i+1)!)^{-1} \cdot (i+1)\).
  3. Guard \(r \gt n\) and \(r \lt 0\) inside ncr, or invfact[n-r] reads out of bounds.
  4. fill() runs once in main, not once per test.
Brute force → why it dies
naivePascal's triangle up to \(n\), or a fresh mpow inverse per query.
cost\(O(n^2)\) memory for the triangle; \(O(t \log p)\) for per-query inverses.
dies at\(n = 10^6\): the triangle has about \(10^{12}\) cells.
thereforeTwo arrays of size MAXN, built in \(O(\text{MAXN})\) with exactly one mpow.
Diagram
Implementation

This is the reusable block — madd/msub/mmul/mpow/minv/mdiv, then fact, invfact, ncr. The problem itself is the last two lines of solve().

Creating Strings II

\(O(\text{MAX} + n)\)
The ask

Question. You are given a string of length \(n\). Count how many different strings can be made by rearranging its characters, modulo \(10^9 + 7\).

Input
One string of lowercase letters.
Output
The number of different rearrangements \(\bmod\ (10^9 + 7)\).
Limits
\(1 \le n \le 10^6\)
Sample
aabac → 20
Breakdown
  1. There are \(n!\) orderings of the positions. Swapping two copies of the same letter gives the same string, so every distinct string is counted \(\prod_c \text{cnt}_c!\) times: \[ \text{ans} = \frac{n!}{\prod_{c = a}^{z} \text{cnt}_c!} \]
  2. Modulo \(p\), each division is a multiplication by a precomputed inverse factorial: \[ \text{ans} \equiv \text{fact}[n] \cdot \prod_{c} \text{invfact}[\text{cnt}_c] \pmod p \]
  3. Simplest form: count the 26 letters, then 27 multiplications. Sample: \(\frac{5!}{3!\,1!\,1!} = 20\).
Key observations
  1. \(n!\) counts all orderings. Swapping two copies of one letter gives the same string, so divide by \(\text{cnt}_c!\) for each letter.
  2. Division mod \(p\) is multiplication by the inverse, and invfact already holds every inverse needed, so no mdiv call is required.
  3. \(\text{invfact}[0] = 1\), so letters that do not occur contribute nothing and need no special case.
  4. Same problem as Creating Strings, with a bigger limit: \(n \le 10^6\) makes listing impossible, so only the count is asked for.
Brute force → why it dies
naiveGenerate the rearrangements and count them, as in Creating Strings.
cost\(O(n!)\).
dies at\(n = 10^6\): the list could not even be stored.
thereforeThe multinomial formula, using precomputed factorials.
Implementation

Count into b[26], fold the 26 inverse factorials, then multiply by fact[n] at the end.

Distributing Apples

\(O(\text{MAX})\)
The ask

Question. There are \(n\) children and \(m\) identical apples. Count the ways to hand out all the apples (a child may get none). Print the count modulo \(10^9 + 7\).

Input
\(n,\ m\).
Output
The number of ways \(\bmod\ (10^9 + 7)\).
Limits
\(1 \le n, m \le 10^6\)
Sample
\(n = 3,\ m = 2\) → 6 (\([0,0,2], [0,1,1], [0,2,0], [1,0,1], [1,1,0], [2,0,0]\))
Breakdown
  1. State it exactly: count the solutions in non-negative integers of \[ x_1 + x_2 + \dots + x_n = m, \qquad x_i \ge 0 \]
  2. Stars and bars: write the \(m\) apples as stars in a row and add \(n - 1\) bars that split the row into \(n\) groups. Each arrangement of \(m\) stars and \(n - 1\) bars is exactly one distribution.
  3. Simplest form: choose which of the \(m + n - 1\) positions are bars: \[ \text{ans} = \binom{m + n - 1}{n - 1} \] Sample: \(\binom{4}{2} = 6\). The factorial table must reach \(m + n - 1 \le 2\cdot 10^6\).
Key observations
  1. Write the \(m\) apples in a row as stars, and place \(n - 1\) bars among them to cut the row into \(n\) groups. Every arrangement is one distribution.
  2. There are \(m + (n - 1)\) symbols in total. Choosing where the bars go gives \(\binom{m+n-1}{n-1}\).
  3. Children may get zero, which is exactly why bars may be next to each other. No extra rule is needed.
  4. MAXN must cover \(m + n - 1\), so with \(n, m \le 10^6\) it is \(2\cdot 10^6\), not \(10^6\).
Brute force → why it dies
naiveDP over (child, apples left): \(dp[i][j] = \sum_{k \le j} dp[i-1][j-k]\).
cost\(O(n \cdot m)\) even with prefix sums.
dies at\(n = m = 10^6\) gives \(10^{12}\).
thereforeThe closed form: one ncr, \(O(1)\) after precomputation.
Diagram
Implementation

st and br name the stars and bars explicitly, so the ncr(tot, br) line reads as the identity rather than as index arithmetic.

2 · Counting recurrences

No closed form is available, but a case split on one element expresses the n case in terms of smaller ones. Derive the recurrence, then iterate it bottom-up.

Christmas Party

\(O(n)\)
The ask

Question. \(n\) children each bring a gift. The gifts are redistributed so that every child gets exactly one gift, and nobody gets their own. In how many ways can this be done? Print the count modulo \(10^9 + 7\).

Input
One integer \(n\).
Output
The number of ways \(\bmod\ (10^9 + 7)\).
Limits
\(1 \le n \le 10^6\)
Sample
\(4\) → 9
Breakdown
  1. State it exactly: count the permutations \(\pi\) of \(\{1..n\}\) with no fixed point (derangements): \[ D(n) = \#\{\, \pi : \pi(i) \ne i \ \text{ for all } i \,\} \]
  2. Child \(1\)'s gift goes to some child \(j \ne 1\): \(n - 1\) choices. Now split on what child \(j\) gets: (a) Child \(j\)'s gift goes to child \(1\). Then \(1\) and \(j\) have swapped, and the other \(n - 2\) children form a derangement: \(D(n-2)\) ways. (b) Child \(j\)'s gift does not go to child \(1\). The \(n - 1\) gifts left (all except child \(1\)'s) go to the \(n - 1\) children left (all except \(j\)), and each child has exactly one forbidden gift (child \(1\) cannot get \(j\)'s, everyone else cannot get their own). That is a derangement of \(n - 1\): \(D(n-1)\) ways.
  3. So: \[ D(n) = (n - 1)\big(D(n-1) + D(n-2)\big), \qquad D(1) = 0,\ \ D(2) = 1 \]
  4. Simplest form: fill \(D\) upward to \(n\). Sample: \(D(3) = 2 \cdot 1 = 2\), \(D(4) = 3 \cdot (2 + 1) = 9\).
Key observations
  1. Child \(1\)'s gift goes to some child \(j \ne 1\). There are \(n - 1\) choices of \(j\).
  2. Split on where \(j\)'s gift goes. If it goes to child \(1\), the two have swapped and the rest is \(D(n-2)\). If it is forbidden from going to child \(1\), the remaining \(n - 1\) children form a derangement-shaped problem: \(D(n-1)\).
  3. Hence \(D(n) = (n-1)\big(D(n-1) + D(n-2)\big)\), with \(D(1) = 0\) and \(D(2) = 1\).
  4. \(n \le 10^6\) makes recursion a stack overflow, so loop upwards.
Brute force → why it dies
naiveList all permutations and reject those with a fixed point, or recurse on the formula without memoisation.
cost\(O(n!)\) for listing; the plain recursion grows like \(O(\varphi^n)\) because of the double call.
dies at\(n = 10^6\). Even the recursion blows the stack.
thereforeOne upward loop over a dp array: \(O(n)\).
Implementation

The commented-out rec at the top is the derivation the loop was built from; it is kept as written. The two base cases are handled with continue inside the loop rather than before it.

3 · Prime-factor counting

The answer is a sum indexed by primes or by divisors. A sieve up to the value bound — not up to n — is the shared setup; what differs is what is summed over it.

Trailing Zeros

\(O(\log _{5} n)\)
The ask

Question. How many zeros does \(n!\) end with? For example, \(20! = 2432902008176640000\) ends with \(4\) zeros.

Input
One integer \(n\).
Output
The number of trailing zeros of \(n!\).
Limits
\(1 \le n \le 10^9\)
Sample
\(20\) → 4
Breakdown
  1. Each trailing zero is a factor \(10 = 2 \cdot 5\). Let \(v_p(x)\) be the number of times prime \(p\) divides \(x\). Factors of \(2\) are more common than factors of \(5\), so \[ \text{zeros}(n!) = \min\big(v_2(n!),\ v_5(n!)\big) = v_5(n!) \]
  2. Count the 5s: \(\lfloor n/5 \rfloor\) numbers up to \(n\) are multiples of \(5\); \(\lfloor n/25 \rfloor\) of those give a second \(5\); and so on (Legendre's formula): \[ v_5(n!) = \sum_{i \ge 1} \left\lfloor \frac{n}{5^i} \right\rfloor \]
  3. Simplest form: loop over \(5, 25, 125, \dots \le n\), at most \(\log_5 10^9 \approx 13\) terms. Sample: \(\lfloor 20/5 \rfloor + \lfloor 20/25 \rfloor = 4 + 0 = 4\).
Key observations
  1. A trailing zero is a factor \(10 = 2 \cdot 5\). Factors of \(2\) are far more common than factors of \(5\), so the number of 5s decides.
  2. \(\lfloor n/5 \rfloor\) numbers up to \(n\) are divisible by \(5\); \(\lfloor n/25 \rfloor\) of them give a second \(5\); and so on. Adding the floors counts each factor exactly once.
  3. The loop is over powers of \(5\), so it runs at most \(\log_5(10^9) \approx 13\) times.
  4. No factorial is ever computed; \(n!\) for \(n = 10^9\) could not be stored.
Brute force → why it dies
naiveCompute \(n!\) and strip zeros, or loop \(i = 1..n\) dividing out 5s.
cost\(n!\) is astronomically large; the per-\(i\) loop is \(O(n \log n)\).
dies at\(n = 10^9\).
thereforeLegendre's formula: about \(13\) divisions.
Implementation

Three lines. i *= 5 with i <= n ends the loop naturally once the power exceeds n.

Next Prime

\(O(X \log \log X + t\cdot g\cdot \pi (\sqrt n))\)
The ask

Question. For each of \(t\) positive integers \(n\), print the smallest prime number strictly greater than \(n\).

Input
\(t\), then \(t\) integers \(n\).
Output
For each \(n\), the next prime after it.
Limits
\(1 \le t \le 20,\ \ 1 \le n \le 10^{12}\)
Sample
\(1 \to 2\); \(2 \to 3\); \(3 \to 5\); \(42 \to 43\); \(1337 \to 1361\)
Breakdown
  1. State it exactly: \[ \text{ans}(n) = \min \{\, q \gt n : q \text{ is prime} \,\} \]
  2. A number \(x\) is prime iff no prime \(d \le \sqrt{x}\) divides it. For \(x\) around \(10^{12}\), \(\sqrt{x} \approx 10^6\), so a sieve up to \(10^6\) lists every prime needed for testing.
  3. Check the odd candidates \(n + 1, n + 2, \dots\) in order. Gaps between primes near \(10^{12}\) are only a few hundred, so only a few hundred candidates are tested.
  4. Simplest form: if \(n \lt 10^6\), the answer is in the sieve list (upper_bound). Otherwise test odd candidates by dividing by sieve primes while \(d^2 \le x\).
Key observations
  1. A sieve up to \(10^{12}\) is impossible. A sieve up to \(10^6\) is 1 MB of bool and gives every prime up to \(\sqrt{10^{12}}\), which is enough to test any candidate by trial division.
  2. Two cases. If \(n\) is inside the sieved range, the answer is already in the prime list: upper_bound. Otherwise test candidates one at a time.
  3. Candidates skip even numbers: start at \(n + 1\) or \(n + 2\) so the start is odd, then step by \(2\).
  4. Trial division stops once x*x > ans. Prime gaps near \(10^{12}\) are about \(300\), so \(t = 20\) queries cost at most a few thousand primality tests.
Brute force → why it dies
naiveSieve up to \(n\), or trial-divide each candidate by every integer \(\le \sqrt{n}\).
cost\(10^{12}\) memory for the sieve; otherwise \(O(\sqrt{n}) = 10^6\) divisions per candidate.
dies atThe big sieve dies on memory at once; dividing by all integers is about \(13\times\) slower than dividing by primes only (there are \(78498\) primes below \(10^6\)).
thereforeSieve up to \(\sqrt{\max n}\) once, and reuse the prime list for every query.
Implementation

sieve() marks composites; main then collects the primes into a vector before reading t. The n < 1000100 branch answers from the list directly.

Counting Coprime Pairs

\(O(X \log X)\)
The ask

Question. You are given \(n\) positive integers. Count the pairs \(i \lt j\) whose greatest common divisor is \(1\) (coprime pairs).

Input
\(n\), then \(x_1, \dots, x_n\).
Output
One integer: the number of coprime pairs.
Limits
\(1 \le n \le 10^5,\ \ 1 \le x_i \le 10^6\)
Sample
5 4 20 1 16 17 5 15 → 19
Breakdown
  1. State it exactly: \[ \text{ans} = \#\{\, i \lt j : \gcd(x_i, x_j) = 1 \,\} \]
  2. Pairs that share a divisor \(d\) are easy to count. With \(c(d) = \#\{ i : d \mid x_i \}\): \[ \#\{\, i \lt j : d \mid x_i \text{ and } d \mid x_j \,\} = \binom{c(d)}{2} \]
  3. Inclusion–exclusion over the shared primes. The sign is the Möbius function: \(\mu(d) = (-1)^{\omega(d)}\) if \(d\) is squarefree with \(\omega(d)\) distinct primes, and \(0\) otherwise: \[ \text{ans} = \sum_{d \ge 1} \mu(d) \binom{c(d)}{2} \] (\(d = 1\) counts all pairs; \(d = 2, 3, 5, \dots\) subtract; \(d = 6, 10, \dots\) add back, and so on.)
  4. Simplest form: \(c(d) = \sum_k \text{freq}[k d]\) for all \(d\) is a harmonic sum, \(O(X \log X)\) with \(X = 10^6\).
Key observations
  1. Counting coprime pairs directly is hard; counting pairs that share a divisor \(d\) is easy: \(\binom{c(d)}{2}\).
  2. Those counts overlap, so use inclusion–exclusion over the prime divisors: add for an even number of distinct primes, subtract for an odd number. That sign is the Möbius function.
  3. Only squarefree \(d\) contribute. Replacing each \(x_i\) by its radical (the product of its distinct primes) with reduce makes every remaining \(d\) squarefree, so no \(\mu\) table is needed; nopd(d) counts the distinct primes and decides the sign.
  4. \(c(d)\) for every \(d\) comes from the harmonic sum for d: for j = d, 2d, …: dp[d] += freq[j]: \(X \log X\), not \(X^2\).
  5. spf (smallest prime factor) from a sieve makes reduce and nopd \(O(\log x)\) each.
Brute force → why it dies
naiveAll pairs, __gcd on each.
cost\(O(n^2 \log X)\).
dies at\(n = 10^5\) gives \(5\cdot 10^9\) gcd calls.
thereforeCount by divisor and correct the overlaps with Möbius signs: \(O(X \log X)\) over the value range, whatever \(n\) is.
Diagram
Implementation

reduce maps each input to its radical, freq counts radicals, dp[d] is the divisor-multiple sum, and the final loop applies the signs.
