Recognition rules

The judgment calls that separate these problems from each other.

1

If a node's answer depends only on its subtree, one post-order DFS does it: children first, then combine. See Subordinates and Tree Matching. Counting Paths uses the same idea for its final pass.

2

If the answer for every node depends on the whole tree, don't run n DFS passes. Run an in-DP (downward) and then an out-DP pushed from parent to child. See Tree Distances I and II.

3

A child often needs the parent's total without its own share. For a sum, subtract it (Tree Distances II, other_children_matching in Tree Matching). For a max, keep the top two values (Tree Distances I).

4

"k levels up" or "lowest common" with q ≤ \(2\cdot 10^{5}\) queries means a binary lifting table: \(\text{up}[v][j] = \text{up}[\text{up}[v][j-1]][j-1]\), with node 0 standing for "above the root". See Company Queries I and II, Distance Queries and Counting Paths.

5

Reduce path questions to the LCA. Distance is \(d[a]+d[b]-2d[\text{lca}]\) (Distance Queries). To count paths through each node, add +1 at both ends, −1 at the lca and −1 at its parent, then sum over subtrees (Counting Paths).

1 · Subtree DP

One DFS. A node's value is computed from its children's finished values on the way back up. The state is the node, plus one flag when the node itself can be used or left free.

Subordinates

\(O(n)\)
The ask

Question. A company has \(n\) employees; employee \(1\) is the director and every other employee has one direct boss. For each employee, count their subordinates: everyone below them in the hierarchy, directly or indirectly.

Input
\(n\), then the bosses of employees \(2, \dots, n\).
Output
\(n\) integers: the number of subordinates of each employee.
Limits
\(1 \le n \le 2\cdot 10^5\)
Sample
bosses 1 1 2 3 → 4 1 1 0 0
Breakdown
  1. The hierarchy is a tree rooted at \(1\). Let \(s(v)\) be the size of \(v\)'s subtree (\(v\) and everyone below it). The subordinates are that subtree without \(v\): \[ \text{ans}(v) = s(v) - 1 \]
  2. A subtree is \(v\) plus the subtrees of its children: \[ s(v) = 1 + \sum_{c \text{ child of } v} s(c) \]
  3. Simplest form: one post-order DFS, so each child is finished before its parent adds it.
Key observations
  1. The subordinates of \(v\) are the subtree of \(v\), minus \(v\) itself.
  2. A subtree's size is \(1\) plus the sizes of the child subtrees.
  3. In post-order, every child is finished before its parent reads it.
Brute force → why it dies
naiveRun a separate DFS over each employee's subtree.
cost\(O(n^2)\) on a chain.
dies at\(n = 2\cdot 10^5\) gives about \(2\cdot 10^{10}\).
thereforeOne post-order DFS adding child sizes: \(O(n)\).
Diagram
Implementation

Edges are stored only from parent to child (g[x].push_back(i)), so child != par never fails. It is harmless. depth and p are unused.

Tree Matching

\(O(n)\)
The ask

Question. You are given a tree with \(n\) nodes. A matching is a set of edges in which no two edges share a node. What is the largest possible number of edges in a matching?

Input
\(n\), then \(n - 1\) edges \(a\ b\).
Output
One integer: the maximum matching size.
Limits
\(1 \le n \le 2\cdot 10^5\)
Sample
edges \((1,2)(1,3)(3,4)(3,5)\) → 2
Breakdown
  1. Root the tree. For each node \(v\), let \(f_0(v)\) be the best matching in its subtree with \(v\) not matched, and \(f_1(v)\) the best with \(v\) matched to one of its children.
  2. If \(v\) is unmatched, each child independently takes its better state: \[ f_0(v) = \sum_{c} \max\big(f_0(c),\ f_1(c)\big) \]
  3. If \(v\) is matched to child \(c\), that child must be unmatched below, and the other children are unchanged. So swap \(c\)'s term and add the edge \((v, c)\): \[ f_1(v) = \max_{c} \Big( f_0(v) - \max\big(f_0(c), f_1(c)\big) + 1 + f_0(c) \Big) \]
  4. Simplest form: one post-order pass, \(O(\deg v)\) per node. Answer \(\max(f_0(1), f_1(1))\).
Key observations
  1. Inside its subtree, \(v\) is either unmatched (state 0) or matched to exactly one child (state 1).
  2. If \(v\) is unmatched, every child takes its better state.
  3. If \(v\) is matched to \(c\), then \(c\) must be in state 0 and every other child is unchanged. So swap \(c\)'s term in the sum.
  4. The swap is one subtraction from \(f_0(v)\), so there is no inner loop: \(O(\deg v)\) per node.
Brute force → why it dies
naiveTry every subset of edges.
cost\(O(2^{n-1} \cdot n)\)
dies at\(n = 2\cdot 10^5\). It is dead by \(n = 40\).
thereforeTwo-state tree DP: \(O(n)\).
Diagram
Implementation

There are two loops over the children. The first loop must finish dp[node][0] before the second one uses it. other_children_matching is the whole sum minus this child's best, and that subtraction is the swap.

using namespace std;
vector < vector < ll > > g ;
vector < vector < ll > > dp ;

void dfs(ll node, ll par)
{
    // dp[node][0] = maximum matching in the subtree rooted at node when node is not matched
    // dp[node][1] = maximum matching in the subtree rooted at node when node is matched with one of its children
    dp[node][0] = 0 ;
    dp[node][1] = 0 ;
    
    for(auto child : g[node])
    {
        if(child != par)
        {
            dfs(child , node) ;
            // this should fill up node's children's dp values first, then we can calculate node's dp values based on its children's dp values
            dp[node][0] += max(dp[child][0] , dp[child][1]) ;
        }
    }
    // now we have dp[node][0] filled, we can calculate dp[node][1] by considering matching node with one of its children

    for(auto child : g[node])
    {
        if(child != par)
        {
            // if we match node with child, then we cannot take dp[child][1] (because child is matched), but we can take dp[child][0] (because child is not matched)
            // and for all other children, we can take the maximum of dp[other_child][0] and dp[other_child][1]
            ll matched_with_child = 1 + dp[child][0] ; // 1 for the edge between node and child
            // now add the maximum matching from all other children
            ll other_children_matching = dp[node][0] - max(dp[child][0] , dp[child][1]) ; // subtract the contribution of this child from dp[node][0]
            dp[node][1] = max(dp[node][1] , matched_with_child + other_children_matching) ;
        }
    }
}

Tree Diameter

\(O(n)\)
The ask

Question. You are given a tree with \(n\) nodes. Its diameter is the number of edges on the longest path between any two nodes. Find the diameter.

Input
\(n\), then \(n - 1\) edges \(a\ b\).
Output
One integer: the diameter.
Limits
\(1 \le n \le 2\cdot 10^5\)
Sample
edges \((1,2)(1,3)(3,4)(3,5)\) → 3 (path \(2 - 1 - 3 - 4\))
Breakdown
  1. State it exactly, with \(d(u, v)\) the number of edges between \(u\) and \(v\): \[ \text{diam} = \max_{u, v} d(u, v) \]
  2. Key fact: from any start node \(s\), the farthest node \(a\) is an end of some longest path. \[ a = \arg\max_{v} d(s, v) \]
  3. Simplest form: then the diameter is the farthest distance from \(a\). Two DFS/BFS passes: \[ \text{diam} = \max_{v} d(a, v) \]
Key observations
  1. The farthest node from any start is one end of a diameter.
  2. The farthest distance from that end is the diameter.
  3. So run two depth passes, with no DP.
Brute force → why it dies
naiveBFS from every node and take the overall maximum.
cost\(O(n^2)\)
dies at\(n = 2\cdot 10^5\) gives \(4\cdot 10^{10}\).
thereforeTwo DFS passes: \(O(n)\).
Diagram
Implementation

The same dfs and d[] are reused. The second call overwrites every depth because the tree is connected. The first scan keeps the first strict maximum. The second scan only needs the value.

2 · Rerooting

An answer for every node. in[v] covers v's subtree. out[v] covers everything else and is pushed from parent to child. The answer is in combined with out. The whole trick is how the parent excludes the child it is pushing into.

Tree Distances I

\(O(n)\)
The ask

Question. You are given a tree with \(n\) nodes. For each node, find the largest distance (in edges) from it to any other node.

Input
\(n\), then \(n - 1\) edges \(a\ b\).
Output
\(n\) integers: the maximum distance from each node.
Limits
\(1 \le n \le 2\cdot 10^5\)
Sample
edges \((1,2)(1,3)(3,4)(3,5)\) → 2 3 2 3 3
Breakdown
  1. Root the tree at \(1\). The farthest node from \(v\) is either below \(v\) or reached through its parent. Define \[ \text{in}(v) = \text{farthest distance going down}, \qquad \text{out}(v) = \text{farthest distance going up first}, \qquad \text{ans}(v) = \max\big(\text{in}(v),\ \text{out}(v)\big) \]
  2. Going down, take the best child (leaves have \(\text{in} = 0\)): \[ \text{in}(v) = \max_{c} \big( \text{in}(c) + 1 \big) \]
  3. For child \(c\) of \(v\), going up first means one step to \(v\), then either keep going up, or go down into a different child \(s \ne c\): \[ \text{out}(c) = \max\Big( \text{out}(v) + 1,\ \ \max_{s \ne c} \text{in}(s) + 2 \Big), \qquad \text{out}(1) = 0 \]
  4. Simplest form: \(\max_{s \ne c}\) is the top \(\text{in}\) value among \(v\)'s children, or the second one if \(c\) holds the top. Keep the top two. Two DFS passes, \(O(n)\).
Key observations
  1. The farthest node from \(v\) either lies in \(v\)'s subtree or is reached through \(v\)'s parent.
  2. Going up from child \(c\), the path either continues above \(v\) (\(\text{out}(v) + 1\)) or turns down into a sibling (\(\text{in}(s) + 2\)).
  3. The best sibling other than \(c\) is the top \(\text{in}\) value, or the second one when \(c\) holds the top. So keep two maxima.
  4. Starting mx2 = -1 makes an only child get \(-1 + 2 = 1\), which is the distance to \(v\) itself.
Brute force → why it dies
naiveBFS from each node.
cost\(O(n^2)\)
dies at\(n = 2\cdot 10^5\) gives \(4\cdot 10^{10}\).
thereforeThe "in" DP, then the "out" DP with the top two child values: \(O(n)\).
Diagram
Implementation

dfsout finds mx1 and mx2 over the children first, then recurses with max(outval + 1, use + 2). The child is excluded by value (indp[child] == mx1), not by identity.

vector < ll > indp ; 
vector < ll > outdp ;
void dfsin(ll node, ll par)
{
    indp[node] = 0 ;
    // indp[node] = maximum distance from node to any of its descendants
    for(auto child : g[node])
    {
        if(child != par)
        {
            dfsin(child , node) ;
            indp[node] = max(indp[node] , indp[child] + 1) ;
        }
    } 
}
void dfsout(ll node, ll par, ll outval)
{
    // outdp[node] = maximum distance from node to any of its ancestors
    outdp[node] = outval ;
    // here outval is the maximum distance from node to any of its ancestors
    ll mx1 = -1 , mx2 = -1 ;

    {
        if(child != par)
        {
            if(indp[child] >= mx1)
            {

                mx1 = indp[child] ;

            {
                mx2 = indp[child] ;
            }
        }

    {

        {

            if(indp[child] == mx1)
            {
                use = mx2 ;
            }

        }
    }

Tree Distances II

\(O(n)\)
The ask

Question. You are given a tree with \(n\) nodes. For each node, find the sum of its distances (in edges) to all other nodes.

Input
\(n\), then \(n - 1\) edges \(a\ b\).
Output
\(n\) integers: the sum of distances from each node.
Limits
\(1 \le n \le 2\cdot 10^5\)
Sample
edges \((1,2)(1,3)(3,4)(3,5)\) → 6 9 5 8 8
Breakdown
  1. Root at \(1\); let \(s(v)\) be subtree sizes. Split the answer into nodes below \(v\) and nodes outside \(v\)'s subtree: \[ \text{ans}(v) = \text{in}(v) + \text{out}(v) \]
  2. Every node under child \(c\) is one step farther from \(v\) than from \(c\), so \[ \text{in}(v) = \sum_{c} \big( \text{in}(c) + s(c) \big) \]
  3. For child \(c\), the nodes outside \(c\)'s subtree are: (i) the \(n - s(v)\) nodes outside \(v\)'s subtree, each one step farther than from \(v\); (ii) the \(s(v) - s(c)\) nodes in \(v\)'s subtree but not \(c\)'s (including \(v\)), each one step farther than from \(v\): \[ \text{out}(c) = \underbrace{\text{out}(v) + \big(n - s(v)\big)}_{\text{(i)}} + \underbrace{\big(\text{in}(v) - \text{in}(c) - s(c)\big) + \big(s(v) - s(c)\big)}_{\text{(ii)}} \]
  4. Simplest form: one post-order pass for \(s\) and \(\text{in}\), one pre-order pass for \(\text{out}\), with \(\text{out}(1) = 0\).
Key observations
  1. Every node under \(c\) is one step farther from \(v\) than from \(c\), which is why \(+\,s(c)\).
  2. From \(c\), the \(n - s(v)\) nodes outside \(v\)'s subtree are one step farther than from \(v\).
  3. \(v\)'s other branches contribute their \(\text{in}\) total, plus one step for each of their \(s(v) - s(c)\) nodes. That count includes \(v\).
  4. For a sum, leaving out one child is a subtraction, so no top-two trick is needed.
Brute force → why it dies
naiveBFS from each node and add up the distances.
cost\(O(n^2)\)
dies at\(n = 2\cdot 10^5\) gives \(4\cdot 10^{10}\).
thereforeSubtree sizes plus rerooting: \(O(n)\). Sums reach about \(n^2 / 2 = 2\cdot 10^{10}\), so use long long.
Diagram
Implementation

dfsin fills sizes and in[] together. use is built in two lines: first the part above v, then v's other branches. Those are exactly the four terms of the formula.

3 · Binary lifting & LCA

Table up[v][j] holds the 2j-th ancestor of v, and 0 is the sink above the root. Any jump of k steps uses the set bits of k. The LCA step: bring both nodes to equal depth, then jump from high j to low while the ancestors still differ.

Company Queries I

\(O((n+q) \log n)\)
The ask

Question. A company of \(n\) employees forms a tree with employee \(1\) as the director. Answer \(q\) queries: who is employee \(x\)'s boss \(k\) levels higher? Print \(-1\) if there is no such boss.

Input
\(n,\ q\); the bosses \(e_2, \dots, e_n\); then \(q\) lines \(x\ k\).
Output
For each query, the boss or -1.
Limits
\(1 \le n, q \le 2\cdot 10^5,\ \ 1 \le k \le n\)
Sample
bosses 1 1 3 3: \((4, 1) \to 3\); \((4, 2) \to 1\); \((4, 3) \to -1\)
Breakdown
  1. Let \(p(v)\) be the boss of \(v\). The answer is \(p\) applied \(k\) times. Store jumps of \(2^j\) levels: \[ \text{up}_0(v) = p(v), \qquad \text{up}_j(v) = \text{up}_{j-1}\big(\text{up}_{j-1}(v)\big) \]
  2. Write \(k\) in binary and make one stored jump per \(1\)-bit: \[ k = 2^{j_1} + 2^{j_2} + \cdots \;\Longrightarrow\; \text{ans} = \text{up}_{j_1}\big(\text{up}_{j_2}(\cdots x)\big) \]
  3. Simplest form: let the director's boss be \(0\) and \(\text{up}_j(0) = 0\). Overshooting the root lands on \(0\), which is printed as \(-1\). \(k \le 2\cdot 10^5 \lt 2^{18}\), so \(18\) levels are enough (\(20\) is a safe round number).
Key observations
  1. \(k\) is a sum of powers of two, so make one table jump per \(1\)-bit of \(k\).
  2. A \(2^j\) jump is two \(2^{j-1}\) jumps.
  3. up[0][*] = 0, so overshooting the root stays at \(0\), which means \(-1\).
Brute force → why it dies
naiveFollow the boss pointer \(k\) times.
cost\(O(k)\) per query.
dies atA chain with \(n = q = 2\cdot 10^5\) gives \(4\cdot 10^{10}\).
thereforeBinary lifting: \(O(n \log n)\) to build, \(O(\log n)\) per query.
Diagram
Implementation

Parents come straight from input, so no DFS is needed. The level loop i is outermost, so level i−1 is complete for every node before level i reads it. The query stops early once x reaches 0.

Company Queries II

\(O((n+q) \log n)\)
The ask

Question. A company of \(n\) employees forms a tree with employee \(1\) as the director. Answer \(q\) queries: who is the lowest common boss of employees \(a\) and \(b\)? (A person counts as their own boss here, so the answer can be \(a\) or \(b\).)

Input
\(n,\ q\); the bosses \(e_2, \dots, e_n\); then \(q\) lines \(a\ b\).
Output
For each query, the lowest common boss.
Limits
\(1 \le n, q \le 2\cdot 10^5\)
Sample
bosses 1 1 3 3: \((4, 5) \to 3\); \((2, 5) \to 1\); \((1, 4) \to 1\)
Breakdown
  1. State it exactly: the lowest common ancestor is the deepest node that is an ancestor of both (each node is its own ancestor): \[ \operatorname{lca}(a, b) = \arg\max_{v \,:\, v \preceq a,\ v \preceq b} \text{depth}(v) \]
  2. Lift the deeper node by \(\text{depth}(a) - \text{depth}(b)\) levels. If the two are now equal, that node is the answer.
  3. Otherwise, for \(j\) from high to low, jump both by \(2^j\) whenever that keeps them different: \[ \text{up}_j(a) \ne \text{up}_j(b) \;\Rightarrow\; a \leftarrow \text{up}_j(a),\ b \leftarrow \text{up}_j(b) \] This never jumps past the LCA.
  4. Simplest form: afterwards \(a\) and \(b\) are two different children of the LCA, so \(\operatorname{lca} = \text{up}_0(a)\).
Key observations
  1. Lift the deeper node by \(d(a) - d(b)\). If the two nodes are now equal, that node is the LCA.
  2. For \(j = 19\) down to \(0\), jump both while up[a][j] != up[b][j]. That can never pass the LCA.
  3. Afterwards \(a\) and \(b\) are children of the LCA, so the answer is up[a][0].
Brute force → why it dies
naiveWalk both nodes up one level at a time.
cost\(O(n)\) per query.
dies atA chain with \(n = q = 2\cdot 10^5\) gives \(4\cdot 10^{10}\).
thereforeLift to equal depth, then jump down the powers of two: \(O(\log n)\).
Diagram
Implementation

The DFS only computes depth, because up[i][0] comes straight from input. After the descent, the code checks a == b first (b was an ancestor of a) and otherwise takes the shared parent. The final else is unreachable.

Distance Queries

\(O((n+q) \log n)\)
The ask

Question. You are given a tree with \(n\) nodes. Answer \(q\) queries: what is the distance (in edges) between nodes \(a\) and \(b\)?

Input
\(n,\ q\); \(n - 1\) edges; then \(q\) lines \(a\ b\).
Output
For each query, the distance.
Limits
\(1 \le n, q \le 2\cdot 10^5\)
Sample
edges \((1,2)(1,3)(3,4)(3,5)\): \((1,3) \to 1\); \((2,5) \to 3\); \((1,4) \to 2\)
Breakdown
  1. Root the tree and let \(d(v)\) be the depth of \(v\). The path from \(a\) to \(b\) goes up to \(\ell = \operatorname{lca}(a, b)\) and back down.
  2. The up part has \(d(a) - d(\ell)\) edges and the down part has \(d(b) - d(\ell)\): \[ \text{dist}(a, b) = \big(d(a) - d(\ell)\big) + \big(d(b) - d(\ell)\big) = d(a) + d(b) - 2\,d(\ell) \]
  3. Simplest form: depths from one DFS, the LCA exactly as in Company Queries II. Sample \((2, 5)\): \(d = 1, 2\), \(\ell = 1\) with \(d = 0\), so \(1 + 2 - 0 = 3\).
Key observations
  1. The path from \(a\) to \(b\) goes up to the LCA and back down.
  2. Depths from the root measure both halves once the LCA's depth is subtracted twice.
  3. The LCA is found exactly as in Company Queries II.
Brute force → why it dies
naiveBFS from \(a\) for each query.
cost\(O(n)\) per query.
dies at\(n = q = 2\cdot 10^5\) gives \(4\cdot 10^{10}\).
thereforeDepths plus LCA: \(O(\log n)\) per query.
Diagram
Implementation

This table is indexed up[level][node], the reverse of Company Queries II, with the same recurrence. The parent is recorded in the DFS because the input is an edge list. node_a and node_b save the originals before lifting overwrites a and b.

Counting Paths

\(O((n+m) \log n)\)
The ask

Question. You are given a tree with \(n\) nodes and \(m\) paths, each given by its two end nodes. For every node, count how many of the paths pass through it.

Input
\(n,\ m\); \(n - 1\) edges; then \(m\) lines \(a\ b\).
Output
\(n\) integers: the number of paths through each node.
Limits
\(1 \le n, m \le 2\cdot 10^5\)
Sample
edges \((1,2)(1,3)(3,4)(3,5)\), paths \((1,3)(2,5)(1,4)\) → 3 1 3 1 1
Breakdown
  1. Root the tree. Use a "difference" value \(\delta(v)\) on nodes, and read the answer as a subtree sum: \[ \text{ans}(v) = \sum_{u \in \text{subtree}(v)} \delta(u) \]
  2. A \(+1\) at node \(a\) then counts on every node from \(a\) up to the root. For a path \(a \leftrightarrow b\) with \(\ell = \operatorname{lca}(a, b)\), the two marks overlap from \(\ell\) upward. Fix that: \[ \delta(a) \mathrel{+}= 1, \quad \delta(b) \mathrel{+}= 1, \quad \delta(\ell) \mathrel{-}= 1, \quad \delta(\text{par}(\ell)) \mathrel{-}= 1 \]
  3. Check: a node on the \(a\)-side below \(\ell\) gets \(1\); \(\ell\) gets \(1 + 1 - 1 = 1\); above \(\ell\) gets \(1 + 1 - 1 - 1 = 0\).
  4. Simplest form: four marks per path (one LCA each), then one post-order pass adding each child's sum into its parent.
Key observations
  1. After the subtree sums, \(+1\) at \(a\) marks every node from \(a\) up to the root.
  2. The two marks overlap from the LCA upward. \(-1\) at the LCA leaves it counted once, and \(-1\) at its parent clears everything above.
  3. This is a 1-D difference array, with "prefix" replaced by "subtree".
  4. Subtree sums are post-order: add each child into its parent once the child is final.
Brute force → why it dies
naiveWalk each path and add \(1\) to every node on it.
cost\(O(n)\) per path.
dies at\(n = m = 2\cdot 10^5\) on a chain gives \(4\cdot 10^{10}\).
thereforeFour marks per path using the LCA, then one summing pass: \(O((n + m) \log n)\).

topo records nodes in post-order, since each node is pushed after its children. Iterating it adds every node into its parent only after the node itself is final. The root adds into cnt[0], which is a harmless sink.

GotchaPut −1 at both the lca and its parent, not −2 at the lca. −2 zeroes the lca itself, even though the path passes through it. When lca is the root its parent is 0, which is guarded.
Recognize"for each node or edge, how many of m paths cover it" → tree difference array: +1 at a and b, −1 at lca and parent(lca), then subtree sums.
