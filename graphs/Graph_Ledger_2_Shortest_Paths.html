Recognition rules

The judgment calls that separate these problems from each other.

1

Pick by weights and query shape: non-negative, one source → Dijkstra (Shortest Routes I); negative edges or cycles → Bellman-Ford (High Score, Cycle Finding); all pairs with \(n \le 500\) → Floyd (Shortest Routes II).

2

Extend the vertex, not the algorithm: Flight Discount doubles vertices by coupon state; Flight Routes lets each vertex be finalised k times.

3

Aggregates over shortest paths ride along Dijkstra: reset on strictly shorter, merge on equal. Investigation; the same reset rule is what Shortest Routes I does with dist alone.

4

A negative cycle only matters where the question looks: High Score filters to 1→n walks, Cycle Finding seeds all distances at 0 to see every cycle.

1 · Dijkstra and variants

Min-heap over tentative distances. The variants change the state (Flight Discount), the pop limit (Flight Routes) or what is carried (Investigation).

Shortest Routes I

\(O((n+m) \log m)\)
The ask

Question. There are \(n\) cities and \(m\) one-way flights; flight \(i\) goes from \(a\) to \(b\) and has length \(c\). Find the length of the shortest route from city \(1\) to every city. Every city can be reached.

Input
\(n,\ m\), then \(m\) lines \(a\ b\ c\).
Output
\(n\) integers: the shortest distance from city \(1\) to cities \(1, \dots, n\).
Limits
\(1 \le n \le 10^5,\ \ 1 \le m \le 2\cdot 10^5,\ \ 1 \le c \le 10^9\)
Sample
flights \((1,2,6)(1,3,2)(3,2,3)(1,3,4)\) → 0 5 2
Breakdown
  1. State it exactly, where a route is a sequence of flights: \[ \text{dist}(v) = \min_{\text{routes } 1 \to v} \sum_{\text{flights}} c, \qquad \text{dist}(1) = 0 \]
  2. The last flight of a shortest route to \(v\) comes from some \(u\): \[ \text{dist}(v) = \min_{(u, v, c)} \big( \text{dist}(u) + c \big) \]
  3. All lengths are \(\ge 0\). So the unfinished city with the smallest tentative distance can never be improved later: any other route to it passes through a city that is at least as far.
  4. Simplest form (Dijkstra): repeatedly take the smallest tentative distance from a min-heap, fix it, and relax its edges: \(\text{dist}(v) \leftarrow \min(\text{dist}(v),\ \text{dist}(u) + c)\).
Key observations
  1. All weights are \(\ge 0\), so the smallest tentative distance is final when it is popped.
  2. Lazy deletion: push duplicates into the heap, and skip a city that is already finalised.
  3. Each edge is relaxed once, when its start city is finalised, so there are at most \(m\) pushes.
Brute force → why it dies
naiveBellman–Ford: relax all edges \(n\) times.
cost\(O(n \cdot m)\)
dies at\(n = 10^5\), \(m = 2\cdot 10^5\) gives \(2\cdot 10^{10}\).
thereforeDijkstra with a binary heap: \(O((n + m) \log m)\).
Diagram
Implementation

vis[node] guards against stale heap entries. The relaxation uses dist[node], which equals the popped d for the first (valid) pop.

Flight Discount

\(O((n+m) \log m)\)
The ask

Question. There are \(n\) cities and \(m\) one-way flights with prices. Find the cheapest route from city \(1\) to city \(n\). You have one coupon: on one flight of your choice, a price \(c\) becomes \(\lfloor c/2 \rfloor\). The coupon can be used only once.

Input
\(n,\ m\), then \(m\) lines \(a\ b\ c\).
Output
One integer: the cheapest price from \(1\) to \(n\).
Limits
\(2 \le n \le 10^5,\ \ 1 \le m \le 2\cdot 10^5,\ \ 1 \le c \le 10^9\)
Sample
flights \((1,2,3)(2,3,1)(1,3,7)(2,1,5)\) → 2 (\(\lfloor 3/2 \rfloor + 1\))
Breakdown
  1. Add one bit to the state: has the coupon been used? Vertices become pairs \((v, u)\) with \(u \in \{0, 1\}\).
  2. Each flight \(a \to b\) with price \(c\) becomes three edges: \[ (a, 0) \xrightarrow{\,c\,} (b, 0), \qquad (a, 0) \xrightarrow{\,\lfloor c/2 \rfloor\,} (b, 1), \qquad (a, 1) \xrightarrow{\,c\,} (b, 1) \]
  3. Simplest form: one Dijkstra from \((1, 0)\) on \(2n\) vertices and \(3m\) edges. The answer is \(\text{dist}(n, 1)\), since using the coupon never costs more.
Key observations
  1. "Have I used the coupon yet?" is one extra bit of state.
  2. Make two copies of every city; the coupon edge goes from copy 0 to copy 1.
  3. Run plain Dijkstra on this layered graph. The answer is \((n, 1)\), because halving never hurts.
Brute force → why it dies
naiveFor each flight, halve it and rerun Dijkstra.
cost\(O(m \cdot (n + m) \log m)\)
dies at\(m = 2\cdot 10^5\) gives about \(10^{11}\).
thereforeOne Dijkstra on \(2n\) vertices and \(3m\) edges.
Diagram
Implementation

encode(a, b) = 2a + b packs the layer into the vertex id; the array is sized 2n + 2. Only layer-0 vertices get the c / 2 edge.

Flight Routes

\(O(k \cdot (n+m) \log (km))\)
The ask

Question. There are \(n\) cities and \(m\) one-way flights with prices. Find the prices of the \(k\) cheapest routes from city \(1\) to city \(n\). A route may visit a city more than once, and two different routes with the same price are both counted.

Input
\(n,\ m,\ k\), then \(m\) lines \(a\ b\ c\).
Output
\(k\) integers: the \(k\) cheapest route prices, in increasing order.
Limits
\(2 \le n \le 10^5,\ \ 1 \le m \le 2\cdot 10^5,\ \ 1 \le c \le 10^9,\ \ 1 \le k \le 10\)
Sample
the 6 flights in the file, \(k = 3\) → 4 4 7
Breakdown
  1. Run Dijkstra on (city, cost) pairs, but allow each city to be popped up to \(k\) times instead of once.
  2. With non-negative prices, pops come out in non-decreasing cost. So the \(j\)-th time city \(v\) is popped, its cost is the \(j\)-th cheapest route to \(v\).
  3. A route among the \(k\) cheapest to \(n\) only passes through prefixes that are among the \(k\) cheapest to their own city. (If a prefix to \(v\) were not, swapping in any of the \(k\) cheaper prefixes would give \(k\) cheaper routes to \(n\).) So pops beyond \(k\) can be thrown away.
  4. Simplest form: stop after the \(k\)-th pop of \(n\). There are at most \(k \cdot n\) pops and \(k \cdot m\) pushes.
Key observations
  1. The \(j\)-th pop of a city from a min-heap is its \(j\)-th cheapest route.
  2. The \(k\)-th cheapest route to \(n\) only extends routes that are among the \(k\) cheapest at each city.
  3. Cap pops per city at \(k\); stop after \(k\) pops of \(n\).
Brute force → why it dies
naiveList routes in order of cost.
costunbounded (routes may repeat cities).
dies at\(n = 10^5\), \(m = 2\cdot 10^5\).
thereforeDijkstra with a pop counter per city: \(O(k \cdot m \log(k m))\).
Diagram
Implementation

vis[node] is a pop counter, not a flag. Pushes to a child already popped k times are pruned since they can never be used.

Investigation

\(O((n+m) \log m)\)
The ask

Question. There are \(n\) cities and \(m\) one-way flights with prices. For routes from city \(1\) to city \(n\), answer four questions: (1) the minimum price; (2) how many routes have that minimum price, modulo \(10^9 + 7\); (3) the fewest flights on a minimum-price route; (4) the most flights on a minimum-price route.

Input
\(n,\ m\), then \(m\) lines \(a\ b\ c\).
Output
Four integers: price, count, min flights, max flights.
Limits
\(1 \le n \le 10^5,\ \ 1 \le m \le 2\cdot 10^5,\ \ 1 \le c \le 10^9\)
Sample
flights \((1,4,5)(1,2,4)(2,4,5)(1,3,2)(3,4,3)\) → 5 2 1 2
Breakdown
  1. A flight \(u \to v\) with price \(c\) lies on some cheapest route exactly when \[ \text{dist}(u) + c = \text{dist}(v) \] These edges form a graph with no cycles (prices are \(\ge 1\)).
  2. On those edges, carry three values for each city: number of cheapest routes \(W\), fewest flights \(F_{\min}\), most flights \(F_{\max}\): \[ W(v) = \sum_{u} W(u), \qquad F_{\min}(v) = 1 + \min_u F_{\min}(u), \qquad F_{\max}(v) = 1 + \max_u F_{\max}(u) \]
  3. Dijkstra finalises cities in order of distance, which is a valid order for these sums. When a relaxation is strictly better, reset the three values; when it ties, merge them.
  4. Simplest form: start with \(W(1) = 1,\ F_{\min}(1) = F_{\max}(1) = 0\). Print \(\text{dist}(n), W(n), F_{\min}(n), F_{\max}(n)\).
Key observations
  1. Keep only the cheapest-route edges: those with \(\text{dist}(u) + c = \text{dist}(v)\).
  2. Dijkstra finalises cities in order of distance, which is a topological order of that subgraph.
  3. A strictly better arrival resets the three values; an equal arrival merges them.
Brute force → why it dies
naiveList all cheapest routes.
costexponential
dies atThe count can be huge (hence the modulo), and \(m = 2\cdot 10^5\).
thereforeCarry \((W, F_{\min}, F_{\max})\) through Dijkstra: \(O((n + m) \log m)\).
Diagram
Implementation

The equality branch does not push: the child is already in the heap with this distance. All three aggregates are updated in both branches, reading from the popped node.

2 · Bellman-Ford

Relax every edge n−1 times; anything still relaxable afterwards is on or behind a negative cycle.

High Score

\(O(n\cdot m)\)
The ask

Question. A game has \(n\) rooms and \(m\) one-way tunnels. Going through tunnel \(a \to b\) changes your score by \(x\), which may be negative. Tunnels can be reused. Starting at room \(1\) with score \(0\), walk to room \(n\). What is the maximum score? Print \(-1\) if the score can be made arbitrarily large.

Input
\(n,\ m\), then \(m\) lines \(a\ b\ x\).
Output
One integer: the maximum score, or -1.
Limits
\(1 \le n \le 2500,\ \ 1 \le m \le 5000,\ \ -10^9 \le x \le 10^9\)
Sample
tunnels \((1,2,3)(2,4,-1)(1,3,-2)(3,4,7)(1,4,4)\) → 5
Breakdown
  1. Maximising a sum is minimising its negative. Give every tunnel weight \(w = -x\): \[ \max \sum x \;=\; -\min \sum w \]
  2. Weights can be negative, so use Bellman–Ford. After \(n - 1\) rounds, every shortest path without a negative cycle is final.
  3. If an edge \(u \to v\) can still be relaxed in round \(n\), it touches a negative cycle (a positive-score loop). The score is unbounded only if that loop can be reached from \(1\) and can reach \(n\): \[ \text{ans} = -1 \iff \exists\, u \to v \text{ relaxable in round } n,\ \ 1 \leadsto u,\ \ v \leadsto n \]
  4. Simplest form: a reverse BFS from \(n\) marks which rooms can reach \(n\). Otherwise \(\text{ans} = -\text{dist}(n)\).
Key observations
  1. A maximum-sum path is a shortest path with the weights negated.
  2. The score is unbounded iff a negative cycle (after negation) is reachable from \(1\) and can reach \(n\).
  3. A reverse BFS from \(n\) marks which rooms can reach \(n\).
Brute force → why it dies
naiveDijkstra on the negated weights.
costwrong
dies atNegative edges break Dijkstra's "popped means final" rule.
thereforeBellman–Ford, \(n\) rounds plus one check round: \(O(n \cdot m) \approx 1.25\cdot 10^7\) at \(n = 2500,\ m = 5000\).
Diagram
Implementation

vis comes from BFS on the reversed graph from n. Relaxations only happen into vis vertices and from finite dist, so cycles that are unreachable from 1 or cannot reach n are ignored.

Cycle Finding

\(O(n\cdot m)\)
The ask

Question. You are given a directed graph with \(n\) nodes and \(m\) weighted edges (weights may be negative). Does it contain a negative cycle, that is, a cycle whose total weight is below \(0\)? If yes, print one.

Input
\(n,\ m\), then \(m\) lines \(a\ b\ c\).
Output
YES and the nodes of one negative cycle in order, or NO.
Limits
\(1 \le n \le 2500,\ \ 1 \le m \le 5000,\ \ -10^9 \le c \le 10^9\)
Sample
the 5 edges in the file → YES, 1 2 4 1 (weight \(1 + 1 - 3 = -1\))
Breakdown
  1. Start every distance at \(0\). That is the same as adding a new source with a \(0\)-weight edge to every node, so every cycle is reachable: \[ \text{dist}(v) = 0 \quad \text{for all } v \]
  2. Run \(n\) rounds of Bellman–Ford, \(\text{dist}(b) \leftarrow \min(\text{dist}(b),\ \text{dist}(a) + c)\), recording \(\text{par}(b) = a\) on each improvement. Without a negative cycle, nothing improves in round \(n\).
  3. If node \(x\) improves in round \(n\), following \(\text{par}\) from \(x\) eventually loops. After \(n\) steps you are certainly on that loop, because a path of \(n\) steps must repeat a node.
  4. Simplest form: from that node \(y\), follow \(\text{par}\) until \(y\) appears again, then print the nodes in reverse.
Key observations
  1. Starting all distances at \(0\) acts like a virtual source with \(0\)-edges to every node, so every cycle is reachable.
  2. If round \(n\) still improves something, a negative cycle exists.
  3. Following par \(n\) times from that node guarantees you land on the cycle.
Brute force → why it dies
naiveList all cycles and add up their weights.
costexponential
dies at\(n = 2500\), \(m = 5000\).
thereforeBellman–Ford with parents: \(O(n \cdot m)\).
Diagram
Implementation

x is reset each round, so after the loop it is the last vertex relaxed in round n. The collection loop starts at x and stops when it returns, then reverses to get edge direction.

3 · Floyd–Warshall

All-pairs by allowing intermediates one at a time.

Shortest Routes II

\(O(n^{3} + q)\)
The ask

Question. There are \(n\) cities and \(m\) two-way roads with lengths. Answer \(q\) queries: the length of the shortest route between cities \(a\) and \(b\), or \(-1\) if there is none.

Input
\(n,\ m,\ q\); then \(m\) lines \(a\ b\ c\); then \(q\) lines \(a\ b\).
Output
For each query, the shortest distance or -1.
Limits
\(1 \le n \le 500,\ \ 1 \le m \le n^2,\ \ 1 \le q \le 10^5,\ \ 1 \le c \le 10^9\)
Sample
roads \((1,2,5)(1,3,9)(2,3,3)\); queries → 5 5 8 -1 3
Breakdown
  1. Let \(d_k(i, j)\) be the shortest route from \(i\) to \(j\) whose intermediate cities all lie in \(\{1, \dots, k\}\). \(d_0\) is the direct road (the shortest one if there are several), or \(\infty\).
  2. A best route using cities up to \(k\) either avoids \(k\), or goes through \(k\) once: \[ d_k(i, j) = \min\big( d_{k-1}(i, j),\ \ d_{k-1}(i, k) + d_{k-1}(k, j) \big) \]
  3. Simplest form (Floyd–Warshall): one table updated in place, with \(k\) as the outer loop. After \(k = n\), each query is a lookup.
Key observations
  1. After phase \(k\), g[i][j] is the best route using only cities \(1..k\) in between.
  2. \(n \le 500\) gives \(n^3 = 1.25\cdot 10^8\) steps of a tiny inner loop.
  3. For repeated roads between the same pair, keep the minimum when reading.
Brute force → why it dies
naiveDijkstra for every query.
cost\(O(q \cdot m \log m)\)
dies at\(q = 10^5\), \(m\) up to \(n^2/2\): about \(10^{10}\).
thereforeCompute all pairs once: \(O(n^3)\), then each query is \(O(1)\).
Diagram
Implementation

INF is 1e18, so \(\text{INF} + \text{INF} = 2\cdot 10^{18}\) still fits in long long and no guard is needed. Diagonal set to 0 after reading edges.
