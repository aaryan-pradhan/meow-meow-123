Recognition rules

The judgment calls that separate these problems from each other.

1

Question asks for a count of regions or pieces → count flood-fill launches: Counting Rooms, Building Roads.

2

Unweighted "fewest steps" → BFS; "print the route" → parent array + reverse: Message Route, Labyrinth, Monsters.

3

Several simultaneous starts → one BFS seeded with all of them: Monsters (all M); Frog Minimum Jumps replaces the queue entirely because layers are intervals.

4

Undirected cycle → skip the parent; directed cycle → gray/black states, and do not skip the parent: Round Trip vs Round Trip II.

5

Constraint between endpoints of every edge → propagate a label along DFS and fail on contradiction: Building Teams (colours), Round Trip (open/closed).

1 · Flood fill

Label connected components; the answer is a count or a function of the count.

Counting Rooms

\(O(n\cdot m)\)
The ask

Question. You are given a map of a building, \(n \times m\) squares, where each square is floor (.) or wall (#). You can walk left, right, up and down through floor squares. A room is a group of floor squares you can walk between. How many rooms are there?

Input
\(n,\ m\), then \(n\) lines of \(m\) characters.
Output
One integer: the number of rooms.
Limits
\(1 \le n, m \le 1000\)
Sample
the \(5 \times 8\) map in the file → 3
Breakdown
  1. Make a graph: each floor square is a vertex, and two floor squares sharing a side are joined by an edge.
  2. A room is exactly a connected component of this graph: \[ \text{ans} = \#\{\text{connected components of the floor graph}\} \]
  3. Simplest form: scan all squares. Each time you meet an unvisited floor square, add \(1\) and flood-fill (DFS/BFS) its whole room. Every square is visited once, so \(O(nm)\).
Key observations
  1. A room is a connected component of the grid graph.
  2. Each DFS started from an unvisited floor square marks exactly one whole room.
  3. Every square is visited once, so the work is linear in the grid size.
Brute force → why it dies
naiveFor every pair of floor squares, test whether they are connected.
cost\(O((nm)^2)\)
dies at\(n = m = 1000\) gives \(10^6\) squares and \(10^{12}\) pairs.
thereforeOne flood fill per room, marking as you go: \(O(n \cdot m)\).
Diagram
Implementation

vis[x][y] stores the room id c, and the answer is read back as the maximum id — equivalent to just printing c. Neighbours are pruned on bounds, visited and wall before recursing.

Building Roads

\(O(n+m)\)
The ask

Question. There are \(n\) cities and \(m\) two-way roads. Build the fewest new roads so that every city can reach every other city, and print which roads to build.

Input
\(n,\ m\), then \(m\) lines \(a\ b\).
Output
The number of new roads \(k\), then \(k\) lines \(a\ b\). Any valid answer is accepted.
Limits
\(1 \le n \le 10^5,\ \ 1 \le m \le 2\cdot 10^5\)
Sample
\(n = 4\), roads \((1,2), (3,4)\) → 1, road 2 3
Breakdown
  1. Let \(c\) be the number of connected components. A new road joins at most two components, so it lowers \(c\) by at most \(1\). Getting to \(c = 1\) needs: \[ k \ge c - 1 \]
  2. \(c - 1\) roads are enough: pick one city \(r_1, \dots, r_c\) from each component and join neighbours in that list: \[ (r_1, r_2),\ (r_2, r_3),\ \dots,\ (r_{c-1}, r_c) \]
  3. Simplest form: \(k = c - 1\). Find components with one DFS pass, keep the first city of each.
Key observations
  1. Each new road merges at most two components, so at least \(c - 1\) roads are needed.
  2. \(c - 1\) are enough: chain one city from each component to the next.
  3. Any city of a component works as its representative.
Brute force → why it dies
naiveKeep adding roads between pairs and re-checking connectivity.
cost\(O(n^2)\) candidate pairs.
dies at\(n = 10^5\) gives \(10^{10}\) pairs.
thereforeLabel components once, chain the representatives: \(O(n + m)\).
Diagram
Implementation

DFS labels every vertex with component id col. comp[c][0] is the smallest vertex of component c, and consecutive components are linked.

Message Route

\(O(n+m)\)
The ask

Question. A network has \(n\) computers and \(m\) two-way connections. Can computer \(1\) send a message to computer \(n\)? If yes, find a route that passes through the fewest computers, and print it. Otherwise print IMPOSSIBLE.

Input
\(n,\ m\), then \(m\) lines \(a\ b\).
Output
The number of computers \(k\) on the route, then the route; or IMPOSSIBLE.
Limits
\(2 \le n \le 10^5,\ \ 1 \le m \le 2\cdot 10^5\)
Sample
edges \((1,2)(1,3)(1,4)(2,3)(5,4)\) → 3, route 1 4 5
Breakdown
  1. Every connection has the same cost, so we want the fewest edges from \(1\) to \(n\). Let \(d(v)\) be that number for vertex \(v\).
  2. BFS visits vertices in order of \(d\): first \(d = 0\), then all with \(d = 1\), and so on. When \(v\) is first reached from \(u\): \[ d(v) = d(u) + 1, \qquad \text{par}(v) = u \]
  3. Simplest form: \(k = d(n) + 1\) computers. The route is \(n,\ \text{par}(n),\ \text{par}(\text{par}(n)), \dots, 1\), printed in reverse.
Key observations
  1. All edges cost the same, so BFS layers are distances.
  2. The first time a vertex is reached is along a shortest path. Record that parent.
  3. Walk par back from \(n\) and reverse.
Brute force → why it dies
naiveDFS over all simple paths, keep the shortest.
costexponential
dies at\(n = 10^5\), \(m = 2\cdot 10^5\).
thereforeBFS: \(O(n + m)\).
Diagram
Implementation

vis is set on push, not pop, so each vertex enters the queue once. par[1] = -1 terminates the reconstruction loop.

Labyrinth

\(O(n\cdot m)\)
The ask

Question. You are given an \(n \times m\) labyrinth of floor (.) and wall (#) squares, with one start A and one end B. You can move left, right, up and down. Is there a path from A to B? If yes, print the length of a shortest one and its moves as letters L R U D.

Input
\(n,\ m\), then \(n\) lines of \(m\) characters.
Output
YES, the length, and the move string; or NO.
Limits
\(1 \le n, m \le 1000\)
Sample
the \(5 \times 8\) map in the file → YES, 9, LDDRRRRRU
Breakdown
  1. Squares are vertices; neighbouring non-wall squares are joined. Every move costs \(1\), so BFS from A gives the shortest distance \(d(v)\) to every square.
  2. When BFS first reaches square \(v\) from \(u\), store \(\text{par}(v) = u\). The move from \(u\) to \(v\) is fixed by the difference \(v - u\): \[ (0, -1) \to \texttt{L}, \quad (0, +1) \to \texttt{R}, \quad (-1, 0) \to \texttt{U}, \quad (+1, 0) \to \texttt{D} \]
  3. Simplest form: walk \(\text{par}\) from B back to A, collect the letters, and reverse. The length is \(d(\texttt{B})\).
Key observations
  1. Grid BFS: squares are vertices and the 4 neighbours are edges.
  2. Store each square's parent. The move letter is the difference between the square and its parent.
  3. Rebuilding runs from B to A, so the string must be reversed.
Brute force → why it dies
naiveDFS over all paths.
costexponential
dies at\(n = m = 1000\).
thereforeBFS with parents: \(O(n \cdot m)\).
Diagram
Implementation

dist = -INF doubles as the unvisited marker. The letter is chosen by comparing parent to child: parent left of the cell ⇒ the move was R.

Monsters

\(O(n\cdot m)\)
The ask

Question. You (A) and some monsters (M) are in an \(n \times m\) labyrinth. Each time you take a step, every monster may also take a step. You win by reaching any square on the border without ever sharing a square with a monster. The plan must work even if the monsters know your path in advance. Is it possible? If yes, print a path.

Input
\(n,\ m\), then the map: . floor, # wall, A you, M monster.
Output
YES, the path length, and the moves (L R U D); or NO.
Limits
\(1 \le n, m \le 1000\)
Sample
the \(5 \times 8\) map in the file → YES, 5, RRDDR
Breakdown
  1. Let \(d_M(v)\) be the fewest steps for the nearest monster to reach square \(v\), and \(d_A(v)\) the same for you. A monster that knows your path just walks to the square first. So you are safe on \(v\) only if: \[ d_A(v) \lt d_M(v) \]
  2. \(d_M\) for all monsters at once is one BFS that starts with every monster in the queue (a multi-source BFS).
  3. If a border square \(b\) is safe, so is every square \(u\) on your shortest path to it. If \(u\) is \(k\) steps before \(b\), a monster reaching \(u\) could then reach \(b\) in \(k\) more steps, so \(d_M(b) \le d_M(u) + k\): \[ d_M(u) \ge d_M(b) - k \gt d_A(b) - k = d_A(u) \]
  4. Simplest form: run both BFS, find any border square with \(d_A \lt d_M\), and print your BFS path to it.
Key observations
  1. Monsters move optimally towards you, so a square is safe iff you arrive strictly before the nearest monster could: \(d_A(v) \lt d_M(v)\).
  2. All monsters at once is one multi-source BFS.
  3. If the final border square is safe, every earlier square on your shortest path is safe too (see step 3 of the breakdown).
Brute force → why it dies
naiveSimulate every step of every monster.
cost\(O((nm)^2)\) or worse.
dies at\(n = m = 1000\).
thereforeTwo BFS (monsters from all sources, you from one), then scan the border: \(O(n \cdot m)\).

Frog Minimum Jumps

\(O(n+q)\)
The ask

Question. There are \(N\) stones in a row, numbered from \(1\). A frog starts on stone \(1\). From stone \(i\) it can jump forward to any stone in \([i+1,\ i + p_i]\), where \(p_i\) is that stone's jump power. Answer \(Q\) queries: for target stone \(x\), what is the minimum number of jumps from stone \(1\)? (Stone \(1\) itself needs \(0\).)

Input
\(N\); \(p_1, \dots, p_N\); \(Q\); then \(Q\) targets.
Output
For each query, the minimum number of jumps.
Limits
Not given in the file.
Sample
\(p = [1, 2, 4, 5, 3]\): query \(3 \to 2\), query \(1 \to 0\), query \(5 \to 3\)
Breakdown
  1. Let \(J(x)\) be the fewest jumps to stone \(x\). The stones reachable in at most \(k\) jumps always form a prefix \([1, R_k]\), because every jump range is an unbroken interval going right: \[ R_0 = 1, \qquad R_{k+1} = \max_{1 \le i \le R_k} \big(i + p_i\big) \]
  2. So the stones needing exactly \(k\) jumps are the block \((R_{k-1}, R_k]\): \[ J(x) = \min \{\, k : x \le R_k \,\} \]
  3. Simplest form: one left-to-right sweep. Keep curEnd \(= R_k\) and farthest \(= \max (i + p_i)\) so far. When \(i\) passes curEnd, start the next layer. Store \(J(i)\) for every stone; each query is a lookup. Sample: \(R_0 = 1,\ R_1 = 2,\ R_2 = 4,\ R_3 \ge 5\), so \(J(3) = 2,\ J(5) = 3\).
Key observations
  1. BFS layers here are unbroken ranges of stones, because reach only grows to the right.
  2. curEnd closes the current layer; farthest builds the next one.
  3. Work out every stone once; each query is then a lookup.
Brute force → why it dies
naiveBFS that adds every stone in \([i+1, i+p_i]\) as a separate edge.
cost\(O(N^2)\) edges.
dies atevery \(p_i = N\) gives \(N^2\) edge checks.
thereforeSweep the layer boundaries instead of using a queue: \(O(N + Q)\).
Diagram
Implementation

curEnd = farthest = 1 and jumps = 0 make stone 1 come out as 0 with no special case. farthest is updated after recording dp[i], so stone i only extends the next layer.

// Problem: Frog Minimum Jumps (multi-query)
// Pattern: monotonic-reach BFS collapsed into a single sweep — "Jump Game II"
//          boundary/farthest technique
// Time: O(N + Q)  Space: O(N)
//
// N stones, 1-indexed. Frog starts at stone 1. Stone i has a Jump Power
// p[i] — from stone i the frog can jump forward to any stone in
// [i+1, i+p[i]]. Given Q queries, each a target stone, output the minimum
// number of jumps from stone 1 to reach it (0 if the target is stone 1).
//
// Example:
//     N=5, power=[1,2,4,5,3]
//         query 3 -> 2   (1 -> 2 -> 3)
//         query 1 -> 0
//         query 5 -> 3   (1 -> 2 -> 4 -> 5)

#include <iostream>
#include <vector>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n; cin >> n;
    vector<int> power(n + 1);
    for (int i = 1; i <= n; i++) cin >> power[i];

    // dp[i] = min jumps from stone 1 to stone i
    vector<int> dp(n + 1, 0);
    int jumps = 0, curEnd = 1, farthest = 1;

    for (int i = 1; i <= n; i++) {
        if (i > curEnd) {
            jumps++;
            curEnd = farthest;
        }
        dp[i] = jumps;
        farthest = max(farthest, i + power[i]);
    }

    int q; cin >> q;
    while (q--) {
        int x; cin >> x;
        cout << dp[x] << "\n";
    }

    return 0;
}
import sys
tok = iter(sys.stdin.read().split())

def main():
    n = int(next(tok))
    power = [0] * (n + 1)
    for i in range(1, n + 1): power[i] = int(next(tok))
    # dp[i] = min jumps from stone 1 to stone i
    dp = [0] * (n + 1)
    jumps, curEnd, farthest = 0, 1, 1
    for i in range(1, n + 1):
        if i > curEnd:
            jumps += 1
            curEnd = farthest
        dp[i] = jumps
        farthest = max(farthest, i + power[i])

        x = int(next(tok))
        out.append(dp[x])
    print('\n'.join(map(str, out)))

  2. In a component, colouring the first pupil forces everything else.

naiveTry all \(2^n\) team assignments.
cost\(O(2^n \cdot m)\)
dies at\(n = 10^5\).

Round Trip

\(O(n+m)\)
The ask

Question. There are \(n\) cities and \(m\) two-way roads. Find a round trip that starts in a city, visits two or more other cities, and returns to the start, with no city repeated in between. Print it, or IMPOSSIBLE.

Input
\(n,\ m\), then \(m\) lines \(a\ b\).
Output
The number of cities \(k\) on the trip (start counted twice), then the cities; or IMPOSSIBLE.
Limits
\(1 \le n \le 10^5,\ \ 1 \le m \le 2\cdot 10^5\)
Sample
edges \((1,3)(1,2)(5,3)(1,5)(2,4)(4,5)\) → 4, 3 5 1 3
Breakdown
  1. We need a cycle of length \(\ge 3\) in an undirected graph.
  2. Run DFS. Every edge from the current vertex \(u\) goes either to an unvisited vertex (a tree edge) or to a vertex \(v\) that is still open (an ancestor). If \(v\) is an open ancestor and \(v \ne \text{par}(u)\), then \[ v \to \dots \to \text{par}(u) \to u \to v \] is a cycle with at least \(3\) cities.
  3. Skipping \(v = \text{par}(u)\) is what rules out the fake cycle \(u \to v \to u\) along one road.
  4. Simplest form: on finding such an edge, walk \(\text{par}\) from \(u\) up to \(v\), then print \(v, \dots, u, v\).
Key observations
  1. In an undirected DFS, any edge to an already-open vertex other than the parent closes a cycle.
  2. Skipping the parent is what excludes the trivial \(a \to b \to a\).
  3. Walk par from the current vertex back to the open one.
Brute force → why it dies
naiveSearch from every vertex for a path back to itself.
cost\(O(n \cdot (n + m))\)
dies at\(n = 10^5\), \(m = 2\cdot 10^5\).
thereforeOne DFS with states 0/1/2 and parents: \(O(n + m)\).

Implementation

vis is 0 unseen, 1 on the stack, 2 finished. On a back edge to child, walk temp up from node, then append node again to close the loop.

  3. The cycle is the part of the stack from that vertex to the current one.

naiveFrom every vertex, search for a path back to itself.
