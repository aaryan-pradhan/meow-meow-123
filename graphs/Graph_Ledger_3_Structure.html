Course Schedule

\(O(n+m)\)
The ask

Question. You must complete \(n\) courses. There are \(m\) requirements "course \(a\) must be completed before course \(b\)". Print an order that respects all requirements, or IMPOSSIBLE if none exists.

Input
\(n,\ m\), then \(m\) lines \(a\ b\).
Output
An order of all \(n\) courses, or IMPOSSIBLE.
Limits
\(1 \le n \le 10^5,\ \ 1 \le m \le 2\cdot 10^5\)
Sample
\(n = 5\), requirements \((1,2)(3,1)(4,5)\) → 3 4 1 5 2
Breakdown
  1. Draw an edge \(a \to b\) for each requirement. We need an order \(\pi\) of the courses with \[ \pi(a) \lt \pi(b) \quad \text{for every edge } a \to b \]
  2. Such an order exists iff the graph has no directed cycle. (On a cycle, every course would have to come before itself.)
  3. A course with no unmet requirement (in-degree \(0\)) can always go next. Removing it may free others.
  4. Simplest form (Kahn): put all in-degree-\(0\) courses in a queue; pop one, print it, lower its children's in-degrees, and queue any that reach \(0\). If fewer than \(n\) are printed, there is a cycle.
Key observations
  1. A valid order exists iff the requirement graph has no directed cycle.
  2. A course with in-degree \(0\) can always go next.
  3. If the queue empties early, every remaining course lies on or behind a cycle.
Brute force → why it dies
naiveTry every order.
cost\(O(n! \cdot m)\)
dies at\(n = 10^5\).
thereforeKahn's algorithm: \(O(n + m)\).
Diagram
Implementation

In-degrees are counted while reading edges. The size check topo.size() != n is the cycle test.

Game Routes

\(O(n+m)\)
The ask

Question. A game has \(n\) levels and \(m\) one-way teleporters, with no directed cycles. In how many ways can you get from level \(1\) to level \(n\)? Print the count modulo \(10^9 + 7\).

Input
\(n,\ m\), then \(m\) lines \(a\ b\).
Output
The number of routes \(\bmod\ (10^9 + 7)\).
Limits
\(1 \le n \le 10^5,\ \ 1 \le m \le 2\cdot 10^5\)
Sample
teleporters \((1,2)(2,4)(1,3)(3,4)(1,4)\) → 3
Breakdown
  1. Let \(P(v)\) be the number of routes from \(v\) to \(n\). A route from \(v\) starts with one teleporter \(v \to u\), then any route from \(u\): \[ P(n) = 1, \qquad P(v) = \sum_{v \to u} P(u) \]
  2. \(P(v)\) needs its children first. With no cycles, a topological order exists; process vertices in reverse of it.
  3. Simplest form: answer \(P(1) \bmod (10^9 + 7)\). Levels that cannot reach \(n\) get \(0\) automatically.
Key observations
  1. Routes from \(v\) = sum over the first teleporter of the routes from where it lands.
  2. Children must be finished first, so process levels in reverse topological order.
  3. Levels that cannot reach \(n\) get \(0\) with no special case.
Brute force → why it dies
naiveDFS that lists every route.
costexponential
dies atThe number of routes can be exponential in \(n\).
thereforeDP over a topological order: \(O(n + m)\).
Diagram
Implementation

Longest Flight Route

\(O(n+m)\)
The ask

Question. There are \(n\) cities and \(m\) one-way flights, with no directed cycles. Fly from city \(1\) to city \(n\) visiting as many cities as possible. Print that number and the route, or IMPOSSIBLE if city \(n\) cannot be reached.

Input
\(n,\ m\), then \(m\) lines \(a\ b\).
Output
The number of cities \(k\), then the route; or IMPOSSIBLE.
Limits
\(2 \le n \le 10^5,\ \ 1 \le m \le 2\cdot 10^5\)
Sample
flights \((1,2)(2,5)(1,3)(3,4)(4,5)\) → 4, 1 3 4 5
Breakdown
  1. Let \(L(v)\) be the most cities on a route from \(v\) to \(n\), with \(L(v) = 0\) meaning "cannot reach \(n\)": \[ L(n) = 1, \qquad L(v) = 1 + \max_{\substack{v \to u \\ L(u) \gt 0}} L(u) \quad (\text{or } 0 \text{ if no such } u) \]
  2. With no cycles, process cities in reverse topological order, the same shape as Game Routes with \(\max\) instead of \(\sum\).
  3. Simplest form: if \(L(1) = 0\), print IMPOSSIBLE. Otherwise rebuild the route: from \(v\), step to any child with \(L(u) = L(v) - 1\).
Key observations
  1. Longest path is easy on a graph without cycles: the same shape as route counting, with max.
  2. \(L = 0\) must mean "cannot reach \(n\)", so dead ends are skipped, not counted as length \(1\).
  3. Rebuild by following any child with \(L(u) = L(v) - 1\).
Brute force → why it dies
naiveDFS over all routes.
costexponential
dies at\(n = 10^5\), \(m = 2\cdot 10^5\). In general graphs, longest path is NP-hard.
thereforeNo cycles, so DP over reverse topological order: \(O(n + m)\).

Implementation

if (r != 0) filters children that cannot reach n. The walk from 1 always finds a child with \(\text{dp}[\text{node}] - 1\) because dp[1] > 0.

Flight Routes Check

\(O(n+m)\)
The ask

Question. There are \(n\) cities and \(m\) one-way flights. Can you travel from every city to every other city? If not, print two cities \(a, b\) such that \(b\) cannot be reached from \(a\).

Input
\(n,\ m\), then \(m\) lines \(a\ b\).
Output
YES, or NO followed by a pair \(a\ b\).
Limits
\(1 \le n \le 10^5,\ \ 1 \le m \le 2\cdot 10^5\)
Sample
flights \((1,2)(2,3)(3,1)(1,4)(3,4)\) → NO, 4 2
Breakdown
  1. Write \(u \leadsto v\) for "\(v\) can be reached from \(u\)". Every pair works iff everything goes through city \(1\): \[ \big(\forall u, v : u \leadsto v\big) \iff \big(\forall v : 1 \leadsto v \ \text{ and } \ v \leadsto 1\big) \] (\(\Leftarrow\): \(u \leadsto 1 \leadsto v\).)
  2. "\(v \leadsto 1\) in \(G\)" is the same as "\(1 \leadsto v\) in the reversed graph" (every flight turned around).
  3. Simplest form: BFS from \(1\) in \(G\) and in reversed \(G\). If \(v\) is missed in \(G\), print \(1\ v\); if missed in reversed \(G\), print \(v\ 1\).
Key observations
  1. Every pair is reachable iff \(1\) reaches everyone and everyone reaches \(1\).
  2. "Everyone reaches \(1\)" is a BFS from \(1\) on the reversed graph.
  3. A missed city \(i\) gives the answer pair directly: 1 i or i 1.
Brute force → why it dies
naiveBFS from every city.
cost\(O(n \cdot (n + m))\)
dies at\(n = 10^5\), \(m = 2\cdot 10^5\).
thereforeTwo BFS: \(O(n + m)\).

Implementation

\(O(n+m)\)
The ask

Question. \(n\) family members are ordering a pizza with \(m\) possible toppings. Each member makes two wishes, each of the form "topping \(x\) on" (+ x) or "topping \(x\) off" (- x). Every member needs at least one of their two wishes to come true. Choose the toppings, or print IMPOSSIBLE.

Input
\(n,\ m\), then \(n\) lines, each with two wishes like + 1 - 3.
Output
\(m\) symbols +/- (topping on or off), or IMPOSSIBLE.
Limits
\(1 \le n, m \le 10^5\)
Sample
wishes \((+1, +2), (-1, +3), (+4, -2)\) → one valid answer is - + + + -
Breakdown
  1. Let \(x_i\) be true if topping \(i\) is on. Each wish is a literal \(\ell\) (either \(x_i\) or \(\lnot x_i\)). We need \[ \bigwedge_{\text{members}} \big( \ell_1 \lor \ell_2 \big) = \text{true} \] This is 2-SAT.
  2. Each clause is two implications. Draw them as edges on the \(2m\) literals: \[ (\ell_1 \lor \ell_2) \iff (\lnot \ell_1 \Rightarrow \ell_2) \land (\lnot \ell_2 \Rightarrow \ell_1) \]
  3. If \(x_i\) and \(\lnot x_i\) are in the same SCC, each forces the other, so no assignment works: \[ \text{IMPOSSIBLE} \iff \exists i : \text{comp}(x_i) = \text{comp}(\lnot x_i) \]
  4. Simplest form: otherwise set \(x_i\) true iff \(\text{comp}(x_i)\) comes later in topological order than \(\text{comp}(\lnot x_i)\). Implications then never lead from a true literal to a false one.
Key observations
  1. \(a \lor b\) is two implications: \(\lnot a \Rightarrow b\) and \(\lnot b \Rightarrow a\).
  2. If \(x\) and \(\lnot x\) share an SCC, each implies the other, so the wishes cannot all be met.
  3. Otherwise set each literal true if its SCC comes later in topological order. Implications never lead from true to false.
Brute force → why it dies
naiveTry all \(2^m\) topping choices.
cost\(O(2^m \cdot n)\)
dies at\(m = 10^5\).
thereforeImplication graph on \(2m\) literals, then Kosaraju: \(O(n + m)\).

        if self.parent[x] == x:
            return x
        self.parent[x] = self.find(self.parent[x])  # return parent[x] = find(...) is two lines in Python
        return self.parent[x]

    def merge(self, x, y):
        x = self.find(x)
        y = self.find(y)
        if x == y:
            return
        if self.rank[x] < self.rank[y]:
            x, y = y, x                     # swap(x, y)
        # this ensures that the larger set is always the parent of the smaller set, which helps to keep the tree flat and improves the efficiency of the union-find operations.
        self.parent[y] = x
        self.rank[x] += self.rank[y]
        self.maxsz = max(self.maxsz, self.rank[x])
        self.setsz -= 1

    def connected(self, x, y):
        return self.find(x) == self.find(y)

    def size(self, x):
        return self.rank[self.find(x)]

    def sets(self):
        return self.setsz

    def max_size(self):
        return self.maxsz

    uf = UnionFind(n)                       # UnionFind uf(n)
    out = []

Road Reparation

\(O(m \log m)\)
The ask

Question. There are \(n\) cities and \(m\) broken two-way roads; repairing road \(i\) costs \(c_i\). Repair some roads so that every city can reach every other, at minimum total cost. Print the cost, or IMPOSSIBLE.

Input
\(n,\ m\), then \(m\) lines \(a\ b\ c\).
Output
The minimum total cost, or IMPOSSIBLE.
Limits
\(1 \le n \le 10^5,\ \ 1 \le m \le 2\cdot 10^5,\ \ 1 \le c \le 10^9\)
Sample
the 6 roads in the file → 14
Breakdown
  1. The cheapest connecting set of roads has no cycle (dropping a cycle road keeps things connected and costs less), so it is a spanning tree with \(n - 1\) roads. We want the minimum spanning tree (MST): \[ \min_{T \text{ spanning tree}} \sum_{e \in T} c_e \]
  2. Cut rule: for any split of the cities into two groups, the cheapest road crossing the split belongs to some MST.
  3. Take roads in increasing cost. A road joining two different components is the cheapest road across the split between them, so it is safe to take. A road inside one component would make a cycle, so skip it.
  4. Simplest form (Kruskal): sort, take each road whose ends are in different DSU sets. If more than one set is left, print IMPOSSIBLE.
Key observations
  1. The cheapest road crossing any split of the cities is safe to take (the cut property).
  2. Processing roads by cost, a road joining two different components is such a road.
  3. If more than one component remains at the end, no spanning tree exists.
Brute force → why it dies
naiveTry every set of \(n - 1\) roads.
costexponential
dies at\(n = 10^5\), \(m = 2\cdot 10^5\).
thereforeKruskal with DSU: \(O(m \log m)\).

Planets Queries I

\(O((n+q) \log k)\)
The ask

Question. There are \(n\) planets, and planet \(i\) has one teleporter leading to planet \(t_i\) (possibly itself). Answer \(q\) queries: starting on planet \(x\) and using \(k\) teleporters in a row, where do you end up?

Input
\(n,\ q\); then \(t_1, \dots, t_n\); then \(q\) lines \(x\ k\).
Output
For each query, the final planet.
Limits
\(1 \le n, q \le 2\cdot 10^5,\ \ 0 \le k \le 10^9\)
Sample
\(t = [2, 1, 1, 4]\): \((1, 2) \to 1,\ (3, 4) \to 2,\ (4, 1) \to 4\)
Breakdown
  1. Let \(f(v) = t_v\). The answer is \(f\) applied \(k\) times: \[ \text{ans}(x, k) = f^{k}(x) = \underbrace{f(f(\cdots f}_{k}(x)\cdots)) \]
  2. Store jumps of length \(2^j\). A jump of \(2^j\) is two jumps of \(2^{j-1}\): \[ \text{up}_0(v) = t_v, \qquad \text{up}_j(v) = \text{up}_{j-1}\big(\text{up}_{j-1}(v)\big) \]
  3. Write \(k\) in binary, \(k = \sum_j b_j 2^j\) with \(b_j \in \{0, 1\}\). Then do one stored jump per bit that is \(1\): \[ f^{k} = f^{2^{j_1}} \circ f^{2^{j_2}} \circ \cdots, \qquad \{j_1, j_2, \dots\} = \{\, j : b_j = 1 \,\} \]
  4. Simplest form: \(k \le 10^9 \lt 2^{30}\), so \(30\) levels are enough. Each query takes at most \(30\) jumps.
Key observations
  1. Every planet has exactly one outgoing teleporter, so the \(k\)-th successor is well defined.
  2. \(2^j\) steps are two jumps of \(2^{j-1}\) steps, which gives a doubling table.
  3. Any \(k\) is a sum of powers of two: jump once per \(1\)-bit of \(k\).
Brute force → why it dies
naiveFollow \(k\) teleporters, one at a time, per query.
cost\(O(q \cdot k)\)
dies at\(q = 2\cdot 10^5\), \(k = 10^9\) gives \(2\cdot 10^{14}\).
thereforeBinary lifting with \(30\) levels: \(O(30 \cdot (n + q))\).
