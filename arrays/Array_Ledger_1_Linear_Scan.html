The Ledger · Arrays

Linear Scan & Frequency

Every problem here is answered by walking the array once (or once after a sort) while carrying a tiny amount of state — a scalar, a pos[] table, a frequency map, a stack. No windows, no two pointers, no binary search. Reach for this page when the answer is a count or an extremum over a sequence and nothing about the problem forces you to revisit an element you have already passed.

Recognition rules

The judgment calls that separate these problems from each other. Every rule must be demonstrated by at least two entries on this page.

1

Fix the right endpoint and the problem collapses to one carried scalar. Maximum Subarray Sum carries the best sum ending at j, Maximum Difference carries \(\min (a[0..j-1])\), Increasing Array carries the running floor. In all three the recurrence is one line and the seed is where the bugs live.

2

A neutral seed (0) is only safe when the empty answer is legal. Maximum Subarray Sum must seed cur = best = x[0] because the subarray is nonempty; Maximum Difference must start the loop at i=1 with minSoFar = arr[0] so index 0 cannot pair with itself. Both bugs are invisible until the input is all-negative or strictly decreasing — the wrong version returns 0.

3

Splitting by parity gives classes that never interact, so the only thing left is the junction between them. Beautiful Permutation gets every within-half gap ≥ 2 for free and checks exactly one boundary; Parity Constrained Sort sorts each class and ignores cross-class inversions because they are unfixable. Solve each class trivially, then handle the single interaction.

4

When the answer is a sum of independent per-index indicators, maintain it instead of recomputing it. Collecting Numbers computes \(1 + \sum_i \big[\,\text{pos}[i] \lt \text{pos}[i-1]\,\big]\) once; Collecting Numbers II keeps that same sum alive by touching only the ≤4 indicators a swap can flip — subtract each one's old value before the swap, add its new value after.

5

unordered_set/unordered_map on plain integer keys is CSES-unsafe: an anti-hash test forces every key into one bucket. Distinct Values TLE'd exactly this way and moved to sort + adjacent-run scan; Distinct Subsequences uses std::map for its frequency table for the same reason. Comparison-based structures cannot be attacked by input.

6

Ask "does contiguity matter?" before choosing the technique — the titles will not tell you. Maximum Subarray Sum is meaningless without contiguity (Kadane); Distinct Subsequences is pure per-value combinatorics because contiguity is irrelevant (\(\prod_v (f_v+1) - 1\)); Distinct Values ignores position entirely. Three problems about "runs of elements", three unrelated shapes.

1 · Single-pass running state

One left-to-right pass, one or two scalars carried forward, O(1) extra space. The recurrence is never the hard part — picking which running value is sufficient, and seeding it so the degenerate input still answers correctly, is the whole problem.

Maximum Subarray Sum

\(O(n)\)
The ask

Question. You are given an array of \(n\) integers. Find the largest possible sum of a contiguous, non-empty subarray.

Input
\(n\), then \(x_0, x_1, \dots, x_{n-1}\).
Output
One integer: the maximum subarray sum.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ -10^9 \le x_i \le 10^9\)
Sample
-1 3 -2 5 3 -5 2 2 → 9 (the block 3 -2 5 3)
Breakdown
  1. State it exactly: \[ \text{ans} = \max_{0 \le i \le j \lt n} \; \sum_{k=i}^{j} x_k \]
  2. Group the blocks by their right end \(j\): \[ \text{ans} = \max_{0 \le j \lt n} f(j), \qquad f(j) = \max_{0 \le i \le j} \sum_{k=i}^{j} x_k \]
  3. Split off the block that is just \(x_j\); every other block ending at \(j\) is a block ending at \(j-1\), plus \(x_j\): \[ f(j) = \max\big(x_j,\; f(j-1) + x_j\big), \qquad f(0) = x_0 \]
  4. Simplest form, one pass with two variables: \[ \text{cur} \leftarrow \max(x_j,\ \text{cur} + x_j), \qquad \text{best} \leftarrow \max(\text{best},\ \text{cur}) \]
Key observations
  1. Every block ends somewhere, so fixing the right end \(j\) splits the problem into \(n\) smaller questions: what is the best sum ending exactly at \(j\)?
  2. That best sum either extends the best block ending at \(j-1\) or starts fresh at \(j\): \(f(j) = \max(x_j,\ f(j-1) + x_j)\).
  3. Same thing in words: if \(f(j-1) \lt 0\), carrying it only lowers the sum, so restart.
  4. The best block need not end at \(n-1\), so the answer is \(\max_j f(j)\), kept in a separate variable best.
  5. The block must be non-empty, so seed with \(x_0\), not \(0\). An all-negative array must return its largest element.
Brute force → why it dies
naiveTry every pair \((i, j)\) and add up the block. Prefix sums remove the inner addition, but not the pairs.
cost \(O(n^3)\) raw, \(O(n^2)\) with prefix sums.
dies at \(n = 2\cdot 10^5\) gives \(\binom{n}{2} \approx 2\cdot 10^{10}\) pairs. The sum itself can reach \(n \cdot 10^9 = 2\cdot 10^{14}\), which does not fit in int.
therefore Keep \(f(j)\) in one long long and a running max: \(O(n)\) time, \(O(1)\) extra space.
Diagram
Implementation

The array is read into a vector first purely so that x[0] can seed both scalars before the loop starts at i=1; the algorithm itself never looks back. The line to read carefully is cur = max(x[i], cur + x[i]) — the first argument is the restart branch, and it is what makes a negative prefix impossible to carry forward.

// Problem: Maximum Subarray Sum
// Link: CSES 1643
// Pattern: Kadane's — running best-ending-here, extend or restart at each element
// Time: O(n)  Space: O(1)
//
// Max sum of a contiguous nonempty subarray.
//
// Example:
//     -1 3 -2 5 3 -5 2 2 -> 9   (subarray [3, -2, 5, 3])

#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n;
    cin >> n;

    vector<long long> x(n);
    for (int i = 0; i < n; i++) cin >> x[i];

    long long cur = x[0], best = x[0];
    for (int i = 1; i < n; i++) {
        cur = max(x[i], cur + x[i]);
        best = max(best, cur);
    }

    cout << best << '\n';
    return 0;
}
import sys
tok = iter(sys.stdin.read().split())         # every whitespace-separated token, like cin

def main():
    n = int(next(tok))                       # cin >> n

    x = [int(next(tok)) for _ in range(n)]   # vector<long long> x(n); cin >> x[i]

    cur, best = x[0], x[0]                  # Python ints never overflow: no long long needed
    for i in range(1, n):
        cur = max(x[i], cur + x[i])
        best = max(best, cur)

    print(best)

main()
GotchaSeed both cur and best with x[0], not 0 — the subarray must be non-empty, so an all-negative array must return its least-negative single element. best must be tracked separately from cur: the optimal block rarely ends at the last index.
Recognize"maximum sum of a contiguous block" → extend-or-restart running sum, running max kept alongside.

Maximum Difference

\(O(n)\)
The ask

Question. You are given an array of \(N\) integers. Choose two indices \(i \lt j\) so that \(a_j - a_i\) is as large as possible, and print that value. It may be negative, for example when the array strictly decreases.

Input
\(N\), then \(a_0, \dots, a_{N-1}\).
Output
One integer: \(\max (a_j - a_i)\) over \(i \lt j\).
Limits
Not given in the file.
Sample
[1,2,3,4,5] → 4 (\(i = 0,\ j = 4\))
Breakdown
  1. State it exactly: \[ \text{ans} = \max_{0 \le i \lt j \lt N} \big(a_j - a_i\big) \]
  2. Fix \(j\). Then \(a_j\) is a constant, so maximising \(a_j - a_i\) means minimising \(a_i\): \[ \text{ans} = \max_{1 \le j \lt N} \Big(a_j - \min_{0 \le i \lt j} a_i\Big) \]
  3. Name the prefix minimum. It updates in one step: \[ m_j = \min_{0 \le i \lt j} a_i, \qquad m_1 = a_0, \qquad m_{j+1} = \min(m_j,\ a_j) \]
  4. Simplest form: \[ \text{ans} = \max_{1 \le j \lt N} \big(a_j - m_j\big) \]
Key observations
  1. The answer is not \(\max a - \min a\), because the order \(i \lt j\) may forbid that pair. For \([5, 1]\) the only legal pair gives \(1 - 5 = -4\).
  2. Fix \(j\). Its best partner is the smallest value strictly before it, the prefix minimum \(m_j\).
  3. So \(\text{ans} = \max_j (a_j - m_j)\): one pass, one carried value.
  4. Order inside the loop matters. Score \(a_j\) against \(m_j\) before folding \(a_j\) into the minimum. Otherwise \(i = j\) is allowed and you get \(0\).
  5. Do not clamp the answer at \(0\). A strictly decreasing array has a negative answer.
Brute force → why it dies
naiveFor each \(j\), scan every \(i \lt j\) and keep the best difference.
cost \(O(N^2)\): there are \(\frac{N(N-1)}{2}\) pairs.
dies atThe file gives no bound. At a typical \(N = 10^5\) that is \(5\cdot 10^9\) comparisons, too slow.
therefore Replace the inner scan with the running minimum \(m_j\): \(O(N)\) time, \(O(1)\) extra space.
Diagram
Implementation

Two lines in the loop body, and their order is the algorithm: maxDiff is updated first, so minSoFar at that moment still describes \(\text{arr}[0..i-1]\) only. The seeds do the same job from outside the loop — minSoFar = arr[0] and \(\text{maxDiff} = \text{arr}[1] - \text{arr}[0]\) mean the pass begins at i=1 with one real pair already scored, so index 0 is never allowed to pair with itself.

arrays/Maximum_Difference.cppverbatim
// Problem: Maximum Difference
// Pattern: single pass, running min — max(arr[j] - min_so_far) over i < j
// Time: O(N)  Space: O(1)
//
// Given N elements in an array, select two indexes i and j such that i < j
// and arr[j] - arr[i] is maximum possible. Output that maximum difference.
//
// Example:
//     [1,2,3,4,5] -> 4   (i=0, j=4: 5-1=4)

#include <iostream>
#include <vector>
using namespace std;

int maxDifference(vector<int>& arr) {
    int minSoFar = arr[0];
    int maxDiff = arr[1] - arr[0];

    for (int i = 1; i < (int)arr.size(); i++) {
        maxDiff = max(maxDiff, arr[i] - minSoFar);
        minSoFar = min(minSoFar, arr[i]);
    }

    return maxDiff;
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n; cin >> n;
    vector<int> arr(n);
    for (int i = 0; i < n; i++) cin >> arr[i];

    cout << maxDifference(arr) << "\n";
    return 0;
}
import sys
tok = iter(sys.stdin.read().split())

def maxDifference(arr):                     # vector<int>& -> a list is always passed by reference
    minSoFar = arr[0]
    maxDiff = arr[1] - arr[0]

    for i in range(1, len(arr)):
        maxDiff = max(maxDiff, arr[i] - minSoFar)
        minSoFar = min(minSoFar, arr[i])

    return maxDiff

def main():
    n = int(next(tok))
    arr = [int(next(tok)) for _ in range(n)]

    print(maxDifference(arr))

main()
GotchaNot "global max − global min" — that silently ignores i < j. And starting the loop at i=0 with minSoFar already arr[0] lets index 0 pair with itself for a free 0, which inflates the answer above every legal pair on a decreasing array.
Recognize"best pair under an ordering constraint i < j" → running extremum of the prefix, scored before it is updated.

Increasing Array

\(O(n)\)
The ask

Question. You are given an array of \(n\) integers. In one move you may increase any single element by \(1\). Find the minimum number of moves that makes the array non-decreasing (\(a_0 \le a_1 \le \dots \le a_{n-1}\)).

Input
\(n\), then \(a_0, \dots, a_{n-1}\).
Output
One integer: the minimum number of moves.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le a_i \le 10^9\)
Sample
3 2 5 1 7 → 5
Breakdown
  1. Call the final array \(b\). Moves only raise values, and the total cost is the total raise: \[ \min \sum_{i=0}^{n-1} (b_i - a_i) \quad \text{subject to} \quad b_i \ge a_i,\ \ b_i \ge b_{i-1} \]
  2. Each \(b_i\) should be as small as both constraints allow, since a larger \(b_i\) costs more and also raises the floor for later elements: \[ b_0 = a_0, \qquad b_i = \max(a_i,\ b_{i-1}) \]
  3. Unrolling the recurrence shows \(b_i\) is just the prefix maximum: \[ b_i = \max(a_0, a_1, \dots, a_i) \]
  4. Simplest form: \[ \text{ans} = \sum_{i=0}^{n-1} \Big( \max_{k \le i} a_k \;-\; a_i \Big) \] Sample: prefix maxima \(3,3,5,5,7\), so the answer is \(0+1+0+4+0 = 5\).
Key observations
  1. Values can only go up, so \(b_i \ge a_i\) is forced and the answer is a sum of non-negative raises \(b_i - a_i\).
  2. Setting \(b_i\) above \(\max(a_i, b_{i-1})\) never helps: it costs more now and raises the floor for everything after. So \(b_i = \max(a_i, b_{i-1})\) is optimal.
  3. The choice at index \(i\) depends only on \(b_{i-1}\): one left-to-right pass, no lookahead, no DP.
  4. Compare against the raised previous value \(b_{i-1}\), not the original \(a_{i-1}\). A raise carries forward.
Brute force → why it dies
naiveAt each index, rescan the prefix to find its maximum.
cost \(O(n^2)\).
dies at \(n = 2\cdot 10^5\) gives about \(2\cdot 10^{10}\) steps. The answer can reach \(n \cdot 10^9 = 2\cdot 10^{14}\), which does not fit in int.
therefore Carry the prefix maximum in one variable: \(O(n)\) time, \(O(1)\) space, sum in long long.
Diagram
Implementation

prev is the floor and is only ever assigned in the else branch — when a shortfall is paid the element becomes prev conceptually, so leaving prev alone is exactly right. Reading and processing in the same loop keeps space at O(1): the array is never stored.

arrays/Increasing_Array.cppverbatim
// Problem: Increasing Array
// Link: CSES 1094
// Pattern: single-pass greedy — track running previous (post-adjustment), pay the shortfall
// Time: O(n)  Space: O(1)
//
// Only allowed move: increase any element by 1. Minimum total moves to make
// the array non-decreasing.
//
// Example:
//     3 2 5 1 7 -> 5

#include <iostream>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n;
    cin >> n;

    long long prev = 0, cost = 0;
    for (int i = 0; i < n; i++) {
        long long x;
        cin >> x;
        if (x < prev) cost += prev - x;
        else prev = x;
    }

    cout << cost << '\n';
    return 0;
}
import sys
tok = iter(sys.stdin.read().split())

def main():
    n = int(next(tok))

    prev, cost = 0, 0
    for i in range(n):
        x = int(next(tok))
        if x < prev: cost += prev - x
        else: prev = x

    print(cost)

main()
GotchaCompare against the running prev, not a[i-1]. A bump raises the floor for everything after it, and the two differ the moment two dips occur in a row. cost must be long long.
Recognize"one-directional edit only, minimum total change to make a sequence monotone" → single-pass running floor, pay the shortfall.

2 · Parity-based construction

Split the values by parity and the two classes stop interacting: within a class every pair differs by at least 2, and nothing can cross between classes. What is left is one boundary to check (Beautiful Permutation) or one sort per class (Parity Constrained Sort). No search.

Beautiful Permutation

\(O(n)\)
The ask

Question. A permutation of \(1, 2, \dots, n\) is beautiful if no two neighbouring numbers differ by exactly \(1\). Print any beautiful permutation, or NO SOLUTION if none exists.

Input
One integer \(n\).
Output
A beautiful permutation, or NO SOLUTION.
Limits
\(1 \le n \le 10^6\)
Sample
5 → 4 2 5 3 1 (any valid answer is accepted)
Breakdown
  1. State it exactly: \[ \text{find } p \text{ a permutation of } \{1,\dots,n\} \text{ with } |p_k - p_{k+1}| \ne 1 \ \ \text{for all } 1 \le k \lt n \]
  2. Two different numbers of the same parity are at least \(2\) apart: \[ u \equiv v \pmod 2,\ u \ne v \;\Longrightarrow\; |u - v| \ge 2 \]
  3. So print all evens, then all odds. Let \(E\) be the largest even number \(\le n\). The only pair that could fail is the junction \((E, 1)\): \[ p = (2, 4, \dots, E,\ 1, 3, 5, \dots), \qquad |E - 1| = E - 1 \]
  4. Simplest form: \[ E - 1 \ge 2 \iff E \ge 4 \iff n \ge 4 \] Also \(n = 1\) is fine, since there are no neighbours. Checking \(n = 2\) and \(n = 3\) by hand shows no solution exists.
Key observations
  1. Two numbers of the same parity differ by at least \(2\), so any order inside one parity class is already safe.
  2. Print the evens as one run and the odds as another. Then only one neighbouring pair is left to check: the junction between the runs.
  3. Evens ascending, then odds ascending, puts the largest even \(E\) next to \(1\). That gap \(E - 1\) is at least \(3\) once \(n \ge 4\).
  4. Only \(n = 2\) and \(n = 3\) are impossible. Both are small enough to check by hand (\(2! = 2\) and \(3! = 6\) orders).
  5. \(n = 1\) is fine: there is no neighbouring pair at all.
Brute force → why it dies
naiveGenerate every permutation of \(1..n\) and test its neighbours.
cost \(O(n! \cdot n)\).
dies at \(n \le 10^6\) makes this hopeless. It is already dead at \(n = 12\), where \(12! \approx 4.8\cdot 10^8\).
therefore Construct the answer instead of searching. Two counting loops, nothing stored: \(O(n)\) time, \(O(1)\) extra space.
Diagram
Implementation

The whole solution is two for loops stepping by 2, one starting at 2 and one starting at 1 — no array, no permutation object. The only branch is the hard-coded n == 2 || n == 3 guard, which is a proved fact about those two inputs rather than a generic small-n special case: n == 1 deliberately falls through to the construction and prints 1.

// Problem: Beautiful Permutation
// Link: CSES 1070
// Pattern: split by parity — evens ascending then odds ascending, so within
// each half consecutive prints differ by 2, and the halves' boundary values
// (largest even, 1) are far apart
// Time: O(n)  Space: O(n) for output buffer
//
// Permutation of 1..n with no adjacent elements differing by exactly 1.
// Print any valid one, or "NO SOLUTION" if none exists.
//
// Example:
//     5 -> 4 2 5 3 1   (any valid beautiful permutation accepted)

#include <iostream>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n;
    cin >> n;

    if (n == 2 || n == 3) {
        cout << "NO SOLUTION\n";
        return 0;
    }

    for (int i = 2; i <= n; i += 2) cout << i << ' ';
    for (int i = 1; i <= n; i += 2) cout << i << ' ';
    cout << '\n';

    return 0;
}
import sys
tok = iter(sys.stdin.read().split())

def main():

    if n == 2 or n == 3:                    # || -> or,  && -> and,  ! -> not
        print("NO SOLUTION")
        return

    out = []                                # collect output, print once (fast, like one big cout)
    for i in range(2, n + 1, 2): out.append(i)   # for (i = 2; i <= n; i += 2): range stops BEFORE n+1
    for i in range(1, n + 1, 2): out.append(i)
    print(' '.join(map(str, out)))

Recognize"construct a permutation avoiding an adjacent difference of exactly 1" → split by parity, each half is internally safe, check the one junction.

Parity Constrained Sort

\(O(n \log n)\)
The ask

Question. There are \(T\) test cases. Each one gives an array of \(N\) integers. You may swap two elements only if they have the same parity (both even or both odd), as many times as you like. Print the arrangement that is closest to sorted non-decreasing order. If several are tied, any of them is accepted.

Input
\(T\). For each case: \(N\), then \(a_0, \dots, a_{N-1}\).
Output
For each case, the rearranged array.
Limits
Not given in the file.
Sample
[2,3,9,1,2,7] → [2,1,3,7,2,9]; [4,2,8] → [2,4,8]
Breakdown
  1. Split the positions by the parity of the value they hold: \[ P_0 = \{\, i : a_i \text{ even} \,\}, \qquad P_1 = \{\, i : a_i \text{ odd} \,\} \]
  2. A legal swap moves an even value into an even slot, or an odd value into an odd slot. So \(P_0\) and \(P_1\) never change, and inside each class every order can be reached.
  3. Exchange argument. Take slots \(i \lt i'\) in the same class holding values \(u \gt u'\). Swapping them removes the inversion \((i, i')\). For any slot \(j\) of the other class, the number of inversions between \(j\) and the pair \(\{i, i'\}\) does not go up: \[ [u' \gt w] + [w \gt u] \;\le\; [u \gt w] + [w \gt u'] \qquad (w = \text{value at } j,\ i \lt j \lt i') \]
  4. Simplest form: sort each class and write it back into that class's slots, left to right: \[ b\big|_{P_c} = \operatorname{sort}\big(a\big|_{P_c}\big), \qquad c \in \{0, 1\} \]
Key observations
  1. A swap never changes the parity of the value in a slot, so the even slots \(P_0\) and odd slots \(P_1\) are fixed by the input. They are not a choice.
  2. Inside one class every order can be reached, so sorting that class removes every inversion within it.
  3. Inversions between the classes can change, but the exchange step in the breakdown shows that sorting a class never increases them. So sorting each class is optimal.
  4. The two classes are never compared with each other. The output slot order comes straight from the original array, so there is nothing to merge.
  5. Pass 2 can re-read a[i] % 2 from the array it is overwriting, because the value written into a slot has the same parity as the value it replaces.
Brute force → why it dies
naiveBubble sort using only legal swaps, or search all reachable arrangements.
cost \(O(N^2)\) for the bubble sort; \(O(k!)\) for the search.
dies atThe quadratic is paid once per test case. At \(N = 10^5\) that is about \(10^{10}\) swaps for one case.
therefore Bucket by parity, sort each bucket, refill with two cursors: \(O(N \log N)\) per case, \(O(N)\) space.
Diagram
Implementation

Two passes over the same array and no index bookkeeping: pass 1 pushes each value into evens or odds, pass 2 re-tests a[i] % 2 to decide which bucket's cursor (ei / oi) supplies the replacement. The line that looks unsafe — if (a[i] % 2 == 0) a[i] = evens[ei++]; reading the array it is overwriting — is fine because the incoming value always has the same parity as the outgoing one. An all-even or all-odd array needs no special case: one bucket just stays empty and its cursor is never advanced.

arrays/Parity_Constrained_Sort.cppverbatim
// Problem: Parity-Constrained Sort (Boys/Girls Line)
// Pattern: split by parity, sort each group independently, re-merge on a
//          second pass keyed on the same parity check (no stored indices)
// Time: O(N log N) per test case  Space: O(N)
//
// T test cases. Each has N integers. Only same-parity elements may be
// swapped with each other (evens with evens, odds with odds). Output the
// permutation closest to fully non-decreasing achievable under that
// constraint. Multiple answers accepted if tied.
//
// Example:
//     [2,3,9,1,2,7] -> [2,1,3,7,2,9]
//         [4,2,8]       -> [2,4,8]

#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int t; cin >> t;
    while (t--) {
        int n; cin >> n;
        vector<int> a(n);
        vector<int> evens, odds;
        for (int i = 0; i < n; i++) {
            cin >> a[i];
            if (a[i] % 2 == 0) evens.push_back(a[i]);
            else odds.push_back(a[i]);
        }
        sort(evens.begin(), evens.end());
        sort(odds.begin(), odds.end());

        int ei = 0, oi = 0;
        for (int i = 0; i < n; i++) {
            if (a[i] % 2 == 0) a[i] = evens[ei++];
            else a[i] = odds[oi++];
        }

        for (int i = 0; i < n; i++) cout << a[i] << ' ';
        cout << '\n';
    }
    return 0;
}
import sys
tok = iter(sys.stdin.read().split())

def main():
    out = []
    t = int(next(tok))
    for _ in range(t):                      # while (t--)
        n = int(next(tok))
        a = [0] * n                         # vector<int> a(n)
        evens, odds = [], []
        for i in range(n):
            a[i] = int(next(tok))
            if a[i] % 2 == 0: evens.append(a[i])    # push_back -> append
            else: odds.append(a[i])
        evens.sort()                        # sort(evens.begin(), evens.end())
        odds.sort()

        ei, oi = 0, 0
        for i in range(n):
            if a[i] % 2 == 0:
                a[i] = evens[ei]; ei += 1   # evens[ei++]: no post-increment, split in two
            else:
                a[i] = odds[oi]; oi += 1

        out.append(' '.join(map(str, a)))
    print('\n'.join(out))

GotchaStoring the even/odd positions in extra vectors is the reflex and it is wasted work — the parity test is one modulo, cheaper than the bookkeeping. Don't try to merge the buckets by value either: the slot order is dictated by the input, not by comparison.
Recognize"swaps allowed only between elements sharing some predicate" → positions per class are frozen, sort within each class, cross-class inversions are unavoidable and ignorable.

3 · Position-array incremental invariant

Invert the array into pos[value] = index and a question about sweep order becomes \(n-1\) independent one-line comparisons. The first problem sums them once; the second keeps that same sum alive under updates by re-evaluating only the handful of comparisons a change can reach.

Collecting Numbers

\(O(n)\)
The ask

Question. The array holds every number \(1, 2, \dots, n\) exactly once. You must collect the numbers in increasing order. In each round you walk the array from left to right and pick up the next number you need whenever you pass it. How many rounds are needed?

Input
\(n\), then the permutation \(x_0, \dots, x_{n-1}\).
Output
One integer: the number of rounds.
Limits
\(1 \le n \le 2\cdot 10^5\)
Sample
4 2 1 5 3 → 3
Breakdown
  1. Let \(\text{pos}[v]\) be the index where value \(v\) sits.
  2. After picking up \(k-1\), you stand at \(\text{pos}[k-1]\). You can pick up \(k\) in the same round exactly when it lies further right: \[ k \text{ joins the round of } k-1 \iff \text{pos}[k-1] \lt \text{pos}[k] \]
  3. Each place where this fails (a break) starts exactly one new round, and breaks do not affect each other.
  4. Simplest form, where \([\,\cdot\,]\) is \(1\) if true and \(0\) if false: \[ \text{rounds} = 1 + \sum_{k=2}^{n} \big[\, \text{pos}[k] \lt \text{pos}[k-1] \,\big] \] Sample: \(\text{pos} = (2, 1, 4, 0, 3)\) for \(v = 1..5\). Breaks happen at \(k = 2\) and \(k = 4\), so the answer is \(1 + 2 = 3\).
Key observations
  1. Only neighbouring values interact. After taking \(k-1\) you are at \(\text{pos}[k-1]\), and you can still take \(k\) iff it lies to the right.
  2. So \(k-1\) and \(k\) share a round iff \(\text{pos}[k-1] \lt \text{pos}[k]\). Otherwise a new round is forced. Call that a break.
  3. Each break costs exactly one extra round, and no break creates or cancels another. The answer is a plain count.
  4. The first round always happens (value \(1\) is always taken), which is the \(+1\).
  5. pos[] can be filled while reading the input. Nothing else is stored.
Brute force → why it dies
naiveSimulate: walk the array, collect what you can, repeat until done.
cost \(O(n)\) per round, up to \(n\) rounds, so \(O(n^2)\).
dies at \(n = 2\cdot 10^5\). A reversed array needs \(n\) rounds, so about \(4\cdot 10^{10}\) steps.
therefore Build pos[] and count the breaks in one pass: \(O(n)\) time, \(O(n)\) space.
Diagram
Implementation

The read loop never stores the array — it stores the inverse, pos[x] = i, with i running from 1, so pos holds 1-based indices throughout. The counting loop then reads pos in value order, which is why rounds starts at 1 and the loop starts at i = 2: there are only \(n-1\) adjacent pairs to test.

Collecting Numbers II

\(O((n+m) \log n)\)
The ask

Question. Same setup as Collecting Numbers: a permutation of \(1..n\) and the same "rounds" count. Now \(m\) operations arrive. Each one swaps the values at two positions \(a\) and \(b\). After every swap, print the new number of rounds.

Input
\(n, m\); the permutation; then \(m\) lines \(a\ b\) (1-based positions).
Output
\(m\) integers: the number of rounds after each swap.
Limits
\(1 \le n, m \le 2\cdot 10^5\)
Sample
4 2 1 5 3, swaps \((2,3), (1,5), (2,3)\) → 2 3 4
Breakdown
  1. From Collecting Numbers, the answer is a sum of break indicators: \[ R = 1 + \sum_{k=2}^{n} e_k, \qquad e_k = \big[\, \text{pos}[k] \lt \text{pos}[k-1] \,\big] \]
  2. Swapping positions \(a, b\) changes \(\text{pos}\) for only two values: \[ u = x_a, \quad w = x_b \]
  3. \(\text{pos}[v]\) appears only in \(e_v\) and \(e_{v+1}\). So at most four indicators can change: \[ A = \{\, u,\ u+1,\ w,\ w+1 \,\} \cap [2, n], \qquad |A| \le 4 \]
  4. Simplest form: remove the old values of those indicators, do the swap, add the new values: \[ R' = R \;-\; \sum_{k \in A} e_k^{\text{before}} \;+\; \sum_{k \in A} e_k^{\text{after}} \]
Key observations
  1. The answer is \(1\) plus a sum of \(n-1\) independent indicators \(e_k\), one for each pair of values \((k-1, k)\).
  2. A swap of positions \(a, b\) changes \(\text{pos}\) for exactly two values, \(u = x_a\) and \(w = x_b\). The query gives positions, so look the values up first.
  3. Value \(v\) appears in only two indicators, \(e_v\) and \(e_{v+1}\). So at most \(4\) indicators can change per swap, whatever \(n\) is.
  4. Those four can overlap when \(u\) and \(w\) are close (for example \(w = u + 1\)). A set<int> removes duplicates without case analysis.
  5. Subtract each affected indicator before the swap and add it back after. Adding without subtracting counts it twice.
Brute force → why it dies
naiveDo the swap, then rerun the full \(O(n)\) count from Collecting Numbers.
cost \(O(n \cdot m)\).
dies at \(n = m = 2\cdot 10^5\) gives \(4\cdot 10^{10}\) operations.
therefore Keep \(R\) and patch only the \(\le 4\) indicators a swap can touch: \(O(\log n)\) per query for the small set, \(O((n+m) \log n)\) overall.
Diagram
Implementation

isBad(k) is the single indicator, deliberately a lambda so the same expression is used for the initial build and for both sides of every update. Both x[] (position → value) and pos[] (value → position) are maintained, and both are swapped — forgetting swap(x[a], x[b]) corrupts every later query's u, v lookup. The subtract-loop, the two swaps, and the add-loop must stay in that order.

arrays/Collecting_Numbers_II.cppverbatim
// Problem: Collecting Numbers II
// Link: CSES 2217
// Pattern: same break-counting formula as Collecting Numbers I, but
// maintained incrementally — a swap only changes pos[] for the two
// swapped values, so only their up-to-4 adjacent edges can flip status
// Time: O((n + m) log n)  Space: O(n)
//
// Same "rounds" formula as Collecting Numbers I, but m swaps (positions a,
// b) are applied one at a time, reporting rounds after each. Naive O(n) per
// swap is too slow for n, m up to 2e5.
//
// Example:
//     4 2 1 5 3, swaps (2,3) (1,5) (2,3) -> 2 3 4

#include <iostream>
#include <vector>
#include <set>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n, m;
    cin >> n >> m;

    vector<int> x(n + 1), pos(n + 1);
    for (int i = 1; i <= n; i++) {
        cin >> x[i];
        pos[x[i]] = i;
    }

    // edge k means the pair (k-1, k); value w only affects edges k=w and
    // k=w+1, since those are the only pairs w appears in
    auto isBad = [&](int k) {
        return pos[k] < pos[k - 1] ? 1 : 0;
    };

    long long breaks = 1;
    for (int k = 2; k <= n; k++) breaks += isBad(k);

    for (int q = 0; q < m; q++) {
        int a, b;
        cin >> a >> b;
        int u = x[a], v = x[b];

        set<int> edges;
        for (int w : {u, v}) {
            if (w >= 2) edges.insert(w);
            if (w + 1 <= n) edges.insert(w + 1);
        }

        for (int k : edges) breaks -= isBad(k);

        swap(pos[u], pos[v]);
        swap(x[a], x[b]);

        for (int k : edges) breaks += isBad(k);

        cout << breaks  << '\n';
    }

    return 0;
}

def main():
    n, m = int(next(tok)), int(next(tok))     # cin >> n >> m

    x, pos = [0] * (n + 1), [0] * (n + 1)
    for i in range(1, n + 1):
        x[i] = int(next(tok))
        pos[x[i]] = i

    # edge k means the pair (k-1, k); value w only affects edges k=w and
    # k=w+1, since those are the only pairs w appears in
    def isBad(k):                           # lambda [&]: a nested def sees pos automatically
        return 1 if pos[k] < pos[k - 1] else 0   # cond ? a : b  ->  a if cond else b

    breaks = 1
    for k in range(2, n + 1): breaks += isBad(k)

    out = []
    for q in range(m):
        a, b = int(next(tok)), int(next(tok))
        u, v = x[a], x[b]

        edges = set()                       # set<int>: only iterated, order doesn't matter here
        for w in (u, v):
            if w >= 2: edges.add(w)
            if w + 1 <= n: edges.add(w + 1)

        for k in edges: breaks -= isBad(k)

        pos[u], pos[v] = pos[v], pos[u]     # swap(pos[u], pos[v])
        x[a], x[b] = x[b], x[a]

        for k in edges: breaks += isBad(k)

        out.append(breaks)
    print('\n'.join(map(str, out)))

Gotchaa and b in a query are array positions, not values — the values that move are u = x[a], v = x[b], and they must be read before the swap. The set is not decoration: when u and v differ by 1 the candidate lists overlap, and counting a shared edge twice desynchronises breaks permanently.
Recognize"a derived count, plus point updates, report after each" → find the fixed-size neighbourhood of conditions one update can reach, subtract old, apply, add new.

4 · Per-value frequency counting

Position is irrelevant here. Both problems reduce the array to "how often does each value occur" and then answer from that table alone — a run count after sorting, or a product over the frequencies. If a sliding window feels natural, the contiguity question has not been asked yet.

Distinct Values

\(O(n \log n)\)
The ask

Question. You are given a list of \(n\) integers. How many different values does it contain?

Input
\(n\), then \(x_0, \dots, x_{n-1}\).
Output
One integer: the number of distinct values.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le x_i \le 10^9\)
Sample
2 3 2 2 3 → 2
Breakdown
  1. State it exactly: \[ \text{ans} = \big|\, \{ x_0, x_1, \dots, x_{n-1} \} \,\big| \]
  2. Sort the list into \(y_0 \le y_1 \le \dots \le y_{n-1}\). Equal values now sit next to each other in runs, and the answer is the number of runs.
  3. Every run except the first begins at an index where the value changes.
  4. Simplest form: \[ \text{ans} = 1 + \sum_{i=1}^{n-1} \big[\, y_i \ne y_{i-1} \,\big] \qquad (n \ge 1) \]
Key observations
  1. Sorting puts equal values next to each other, so "have I seen this before?" becomes the local test \(y_i \ne y_{i-1}\).
  2. The sorted list is a sequence of runs. The answer is the number of runs, which is \(1 +\) the number of neighbouring unequal pairs.
  3. The only edge case is the seed: an empty list has \(0\) runs, not \(1\). Hence the n > 0 guard.
  4. A hash set is \(O(n)\) only on average. CSES has an anti-hash test that sends every key to one bucket, which makes it \(O(n^2)\).
  5. Sorting only compares values, so no input can slow it down: \(O(n \log n)\) on every test.
Brute force → why it dies
naiveFor each \(i\), scan \(x_0..x_{i-1}\) for an earlier copy, or use unordered_set.
cost \(O(n^2)\) for the scan. The hash set is \(O(n)\) on average but \(O(n^2)\) in the worst case.
dies at \(n = 2\cdot 10^5\) gives about \(2\cdot 10^{10}\) steps. The unordered_set version really did TLE on CSES's anti-hash test.
therefore sort, then count runs: \(O(n \log n)\) worst case, safe against adversarial input.
Diagram
Implementation

Ten lines and no container beyond the input vector. The seed int distinct = n > 0 ? 1 : 0; carries the "first run is free" idea and the empty-input case at once; the loop then adds a run per boundary. Keeping the header comment's note about the unordered_set TLE is deliberate — the choice of sort here is a correctness-under-judge decision, not a stylistic one.

Distinct Subsequences

\(O(n \log n)\)
The ask

Question. You are given an array of \(n\) integers. Count its non-empty subsequences in which all elements are distinct. A subsequence keeps the original order but does not have to be contiguous. Print the count modulo \(10^9 + 7\).

Input
\(n\), then \(x_0, \dots, x_{n-1}\).
Output
One integer: the count \(\bmod\ (10^9 + 7)\).
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le x_i \le 10^9\)
Sample
1 2 1 3 → 11
Breakdown
  1. Let \(f_v\) be the number of times value \(v\) appears. A valid subsequence uses each value at most once, so for each distinct \(v\) it does one of: \[ \text{skip } v, \quad \text{or take exactly one of its } f_v \text{ copies} \;\Longrightarrow\; f_v + 1 \text{ options} \]
  2. Choices for different values are independent, so multiply. This includes the subsequence that skips everything: \[ \#\{\text{valid, including empty}\} = \prod_{v} (f_v + 1) \]
  3. Simplest form: remove the empty one: \[ \text{ans} = \Big( \prod_{v} (f_v + 1) \Big) - 1 \pmod{10^9 + 7} \] Sample: \(f_1 = 2,\ f_2 = 1,\ f_3 = 1\), so \(3 \cdot 2 \cdot 2 - 1 = 11\).
Key observations
  1. Contiguity does not matter, so this is not a sliding-window problem despite the name.
  2. A valid subsequence uses each value at most once, so it is fully described by one choice per distinct value.
  3. A value with frequency \(f\) has exactly \(f + 1\) options: skip it, or take one of its \(f\) copies.
  4. It is not \(2^f\) per value. That treats each copy as a separate yes/no and allows two copies of the same value.
  5. Choices for different values are independent, so the count is a product. The all-skip choice is the empty subsequence, hence the final \(-1\).
Brute force → why it dies
naiveList all \(2^n\) subsequences and test each for a repeated value.
cost \(O(2^n \cdot n)\).
dies at \(n = 2\cdot 10^5\) gives \(2^{200000}\). It is already dead by \(n = 40\).
therefore Count per distinct value instead of per subsequence: one frequency map and one product, \(O(n \log n)\).
Diagram
Implementation

The array is never stored — values go straight into map<int, ll> freq as they are read, which also handles values up to \(10^9\) without any coordinate compression. The product runs over f + 1, not f, and mcorr is applied exactly once at the end: msub can return a negative residue, and correcting after every operation instead of once is the usual way this template gets misused.

// Problem: Distinct Subsequences
// Link: CSES 2429
// Pattern: per-value option counting — a value with frequency f has (f+1)
// independent options (exclude, or include one of its f occurrences);
// multiply across distinct values, subtract 1 for the empty subsequence
// Time: O(n log n)  Space: O(n)
//
// Count subsequences (not necessarily contiguous) where every element is
// distinct, modulo 1e9+7.
//
// Example:
//     1 2 1 3 -> 11

#include <iostream>
#include <map>
using namespace std;

const ll MOD = 1000000007;

ll mmul(ll a, ll b) { return (a % MOD * (b % MOD)) % MOD; }
ll msub(ll a, ll b) { return (a % MOD - b % MOD) % MOD; }
ll mcorr(ll a) { return (a % MOD + MOD) % MOD; }

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n;
    cin >> n;

    map<int, ll> freq;
    for (int i = 0; i < n; i++) {
        int v;
        cin >> v;
        freq[v]++;
    }

    ll ans = 1;
    for (auto& [val, f] : freq) {
        ans = mmul(ans, f + 1);
    }

    ans = mcorr(msub(ans, 1));
    cout << ans << '\n';
    return 0;
}

5 · Monotonic stack

The one family here that keeps a list of running state rather than a scalar. It applies when an element, once passed, can be proved useless to every future element — then the survivors form a monotone stack and each index is pushed and popped at most once.

Nearest Smaller Values

\(O(n)\)
The ask

Question. You are given an array of \(n\) integers. For each position, find the nearest position to its left that holds a strictly smaller value. Print \(0\) if there is none.

Input
\(n\), then \(x_1, \dots, x_n\) (positions are 1-based).
Output
\(n\) integers: the answer for each position.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le x_i \le 10^9\)
Sample
2 5 1 4 8 3 2 5 → 0 1 0 3 4 3 3 7
Breakdown
  1. State it exactly: \[ \text{ans}_i = \max \{\, j \lt i : x_j \lt x_i \,\}, \qquad \text{or } 0 \text{ if the set is empty} \]
  2. Domination: if \(j \lt i\) and \(x_j \ge x_i\), then for every later \(k \gt i\), index \(i\) is closer than \(j\), and \[ x_j \lt x_k \;\Longrightarrow\; x_i \le x_j \lt x_k \] so \(i\) always beats \(j\). Index \(j\) can never be an answer again.
  3. The indices that survive have strictly increasing values. Keep them on a stack, smallest value at the bottom.
  4. Simplest form, for each \(i\) in order: \[ \text{pop while } x_{\text{top}} \ge x_i; \qquad \text{ans}_i = \text{top (or } 0\text{)}; \qquad \text{push } i \]
Key observations
  1. If \(j \lt i\) and \(x_j \ge x_i\), then \(j\) can never be the answer for any position after \(i\): \(i\) is nearer and not larger. So \(j\) is dead.
  2. The indices still alive, from bottom to top, have strictly increasing values. That is a monotonic stack of indices.
  3. The answer for \(i\) is whatever is on top after popping every value \(\ge x_i\). An empty stack means no smaller value exists.
  4. The pop test is \(\ge\), not \(\gt\). An equal value is not smaller, so it must go too.
  5. Each index is pushed once and popped at most once, so the inner while costs \(O(n)\) in total, not per element.
Brute force → why it dies
naiveFor each \(i\), walk left until a smaller value appears.
cost \(O(n^2)\). A strictly decreasing array makes every walk reach the front.
dies at \(n = 2\cdot 10^5\) gives about \(2\cdot 10^{10}\) steps on that input.
therefore Keep only the live indices on a stack and drop dominated ones for good: \(O(n)\) amortised, \(O(n)\) space.
Diagram
Implementation

This file is the CSES/CPH shape — full macro block, no comments, output printed inside the scan rather than buffered. The array is 1-indexed (v(n + 1), loop from 1), which is what makes the empty-stack case print 0 for free: index 0 is never pushed, so "no candidate" and "index 0" can never be confused. The stack holds indices, and s.top() is printed directly because the index is what the problem asks for; the values are only ever reached through v[s.top()].

import sys
tok = iter(sys.stdin.read().split())

def solve():
    n = int(next(tok))
    v = [0] * (n + 1)
    for i in range(1, n + 1):
        v[i] = int(next(tok))
    s = []                                  # stack<ll>: a list; top = s[-1], push = append, pop = pop()
    out = []
    for i in range(1, n + 1):
        while s and v[s[-1]] >= v[i]:       # !s.empty() -> s  (empty list is False)
            s.pop()
        if not s:
            out.append(0)
        else:
            out.append(s[-1])
        s.append(i)
    print(' '.join(map(str, out)))

solve()
GotchaThe pop condition is v[s.top()] >= v[i]. With > an equal-valued index survives and gets reported as "smaller", which is wrong and only shows up on inputs with duplicates. Also note i is pushed after its answer is printed — pushing first makes every position its own answer.
Recognize"nearest smaller / greater element to the left or right" → monotonic stack of indices, pop everything the new element dominates.
