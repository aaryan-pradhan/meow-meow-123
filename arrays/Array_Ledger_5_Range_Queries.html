The Ledger · Arrays

Range Queries & Binary Search

Two ways of not touching the array element by element. The first five problems precompute a structure over the array — a prefix table or a segment tree — so any range collapses to O(1) or O(log n). The last two never index the array at all: they binary search the answer, and the array only appears inside a monotone feasible(x) predicate. Reach for this page when a problem says "q queries" or "minimise the maximum".

Recognition rules

The judgment calls that separate these problems from each other. Every rule must be demonstrated by at least two entries on this page.

1

Ask two questions in order: does the array change? and does the aggregate have an inverse? Both "no updates" and "invertible" → prefix table, no tree (Static Range Sum Queries, \(\text{prefix}[b] - \text{prefix}[a-1]\)). Either one fails → segment tree. Static Range Minimum Queries is static too, but you cannot subtract a value back out of a min, so it still builds the tree — it just never calls update.

2

Across Static Range Minimum, Dynamic Range Sum, Dynamic Range Minimum and Josephus the build / update / query bodies are byte-identical. Exactly two things vary per problem: the merge body and the identity in node(). Write the scaffold from muscle memory, then think about those two lines only.

3

The identity must be the neutral element of your merge, because query returns a default-constructed node() on no-overlap and that node is merged into the real answer. 0 for the sum trees (Dynamic Range Sum, Josephus), 2e18 for the min trees (Static / Dynamic Range Minimum). A 0 identity in a min tree silently answers 0 for every query that partially overlaps.

4

Default to the segment tree, never a Fenwick tree/BIT. The same sum tree that answers Dynamic Range Sum Queries also runs Josephus Queries' findKth descent with six extra lines — one structure covers point update, range sum, range min and order statistics, so there is one thing to remember under interview pressure instead of two.

5

CSES hands you 1-indexed queries; this repo builds trees 0-indexed over \([0, n-1]\). Convert once, at the call site — query(1, 0, n-1, a-1, b-1) in both Dynamic entries and in Static Range Minimum, and order[i] + 1 on the way out of Josephus. Never half-convert inside the recursion. Prefix sums are the one exception: Static Range Sum Queries stores prefix[1..n] 1-indexed precisely so the query needs no shifting at all.

6

"Minimise the maximum" (Array Division) or "maximise the minimum" / "shortest time to reach a target" (Factory Machines) → binary search the answer, not the array. Both files have the identical skeleton: a boolean check(mid), then ans = mid; hi = mid - 1 on success and lo = mid + 1 on failure. The array is never sorted and never indexed by the search — it only feeds the predicate.

7

The predicate is where the bugs live, not the search. Array Division needs the v[i] > mid → return false guard, or a single oversized element is silently packed into a block. Factory Machines needs its if (total >= t) return true inside the loop, or \(\sum_i \lfloor x / k_i \rfloor\) over \(2\cdot 10^5\) machines overflows long long. Both times the fix is one line in check.

Segment tree toolkit

The shared scaffolding behind families 1–3, canonical segment tree scaffold. Reproduce this from memory; then change merge and the identity, and nothing else.

node t[4 * MAXN]the 4·n sizing: the recursion is not a perfect binary tree, and a worst-case n (just over a power of two) pushes the largest used index past 2n. 4·n is the safe bound — here MAXN = 200020, so t[800080], a static global, never a vector resized per test.
node()the default constructor is the identity. sum = 0 for a sum tree; mn = INF = 2e18 for a min tree. Nothing else declares it.
merge(a, b)the only genuinely per-problem line. res.sum = a.sum + b.sum or res.mn = min(a.mn, b.mn). Must be associative; must be neutral under node().
build(id, l, r)leaf l == r copies arr[l]; otherwise recurse into [l, mid] / [mid+1, r] and t[id] = merge(children). Called once as build(1, 0, n - 1) — O(n).
update(id, l, r, pos, val)point set, not add: the leaf is overwritten with val, then every ancestor re-merges on the way back up. Out-of-range guard is pos < l || pos > r. O(log n).
query(id, l, r, lq, rq)three cases, in this order: no overlap → return node() (identity); full containment → return t[id]; else merge of both recursive halves. O(log n).
findKth(id, l, r, k)order statistics over a 0/1 "alive" sum tree. Descend from the root: t[2*id].sum >= k → go left with the same k; else go right with k - t[2*id].sum. One path down, no backtracking, O(log n). k is 1-indexed; the returned position is 0-indexed.
children of id2*id and 2*id + 1, root at id = 1. Index 0 is unused — that is what makes the doubling work.
indexingthe tree is built 0-indexed over [0, n-1]; CSES queries arrive 1-indexed. Subtract 1 at the call site: query(1, 0, n-1, a-1, b-1), update(1, 0, n-1, k-1, u).
vs. Fenwick / BITthis repo does not use one. A BIT is shorter but only does invertible prefix aggregates; the segment tree above does point update, range sum, range min and findKth with the same body. One structure, memorised once.

1 · Static range queries

The array is read once and never changes; only the queries vary. That freedom is worth something only when the aggregate is invertible — a sum can be differenced out of a prefix table, a minimum cannot. So these two problems, identical in shape and identical in constraints, land on completely different structures.

Static Range Sum Queries

\(O(n+q)\)
The ask

Question. You are given an array of \(n\) integers that never changes, and \(q\) queries. Each query \((a, b)\) asks for the sum of the elements from position \(a\) to position \(b\).

Input
\(n,\ q\); then \(x_1, \dots, x_n\); then \(q\) lines \(a\ b\).
Output
For each query, the sum \(x_a + \dots + x_b\).
Limits
\(1 \le n, q \le 2\cdot 10^5,\ \ 1 \le x_i \le 10^9,\ \ 1 \le a \le b \le n\)
Sample
3 2 4 5 1 1 5 3: \((2,4) \to 11,\ (5,6) \to 2,\ (1,8) \to 24,\ (3,3) \to 4\)
Breakdown
  1. State it exactly: \[ \text{ans}(a, b) = \sum_{i=a}^{b} x_i \]
  2. Define prefix sums once: \[ P_0 = 0, \qquad P_i = P_{i-1} + x_i = \sum_{j=1}^{i} x_j \]
  3. A range is a long prefix minus a short prefix: \[ \sum_{i=a}^{b} x_i = \sum_{i=1}^{b} x_i - \sum_{i=1}^{a-1} x_i \]
  4. Simplest form, \(O(1)\) per query: \[ \text{ans}(a, b) = P_b - P_{a-1} \] Sample: \(P = (0, 3, 5, 9, 14, \dots)\), so \((2,4) \to P_4 - P_1 = 14 - 3 = 11\).
Key observations
  1. Addition can be undone by subtraction, so a range sum is the difference of two prefix sums. No structure is needed beyond one array.
  2. Build \(P\) 1-indexed with size \(n + 1\). Then the query indices need no shifting.
  3. \(P_0 = 0\) is the base case, and it is exactly what makes \(a = 1\) work without a special case.
  4. The elements are never needed again, so only \(P\) is stored.
  5. \(2\cdot 10^5 \cdot 10^9 = 2\cdot 10^{14}\) overflows int, so \(P\) is long long.
Brute force → why it dies
naiveFor each query, loop \(i = a..b\) and add.
cost \(O(nq)\), one full scan per query.
dies at \(n = q = 2\cdot 10^5\) gives \(4\cdot 10^{10}\) additions. One sum can reach \(2\cdot 10^{14}\), past int.
therefore One prefix pass, then each query is one subtraction: \(O(n + q)\) time, \(O(n)\) space, long long.
Diagram
Implementation

The input element x is read into a scalar and folded into prefix[i] immediately — the array itself is never stored, so the only allocation is the n+1-long table. The line worth a second look is prefix[b] - prefix[a - 1]: a is 1-indexed, so a == 1 reads prefix[0], which is the zero written by the vector's constructor.

// Problem: Static Range Sum Queries
// Link: CSES 1646
// Pattern: prefix sums — prefix[i] = sum of first i elements (1-indexed),
// answer for [a,b] is prefix[b] - prefix[a-1]
// Time: O(n + q)  Space: O(n)
//
// Array never changes; answer q range-sum queries.
//
// Example:
//     3 2 4 5 1 1 5 3, query (2,4) -> 11, (5,6) -> 2, (1,8) -> 24, (3,3) -> 4

#include <iostream>
#include <vector>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n, q;
    cin >> n >> q;

    vector<long long> prefix(n + 1, 0);
    for (int i = 1; i <= n; i++) {
        long long x;
        cin >> x;
        prefix[i] = prefix[i - 1] + x;
    }

    for (int i = 0; i < q; i++) {
        int a, b;
        cin >> a >> b;
        cout << prefix[b] - prefix[a - 1] << '\n';
    }

    return 0;
}
import sys
tok = iter(sys.stdin.read().split())

def main():
    n, q = int(next(tok)), int(next(tok))
    prefix = [0] * (n + 1)                  # vector<ll> prefix(n + 1, 0)
    for i in range(1, n + 1):
        x = int(next(tok))
        prefix[i] = prefix[i - 1] + x
    out = []
    for i in range(q):
        a, b = int(next(tok)), int(next(tok))
        out.append(prefix[b] - prefix[a - 1])
    print('\n'.join(map(str, out)))

GotchaDo not reach for a segment tree here. Static plus invertible collapses to O(1) per query; building a tree is slower, longer, and more to get wrong. Keep prefix as long long — the total reaches \(2\cdot 10^{14}\).
Recognize"array never changes, answer many range sums" → one prefix pass, answer by subtraction.

Static Range Minimum Queries

\(O((n+q) \log n)\)
The ask

Question. You are given an array of \(n\) integers that never changes, and \(q\) queries. Each query \((a, b)\) asks for the smallest element from position \(a\) to position \(b\).

Input
\(n,\ q\); then \(x_1, \dots, x_n\); then \(q\) lines \(a\ b\).
Output
For each query, \(\min(x_a, \dots, x_b)\).
Limits
\(1 \le n, q \le 2\cdot 10^5,\ \ 1 \le x_i \le 10^9\)
Sample
3 2 4 5 1 1 5 3: \((2,4) \to 2,\ (5,6) \to 1,\ (1,8) \to 1,\ (3,3) \to 4\)
Breakdown
  1. State it exactly: \[ \text{ans}(a, b) = \min_{a \le i \le b} x_i \]
  2. Unlike sums, \(\min\) cannot be undone: knowing \(\min(x_1..x_b)\) and \(\min(x_1..x_{a-1})\) does not give \(\min(x_a..x_b)\). The prefix trick fails.
  3. But \(\min\) can be split freely, because it is associative: \[ \min(x_a, \dots, x_b) = \min\Big( \min(x_a, \dots, x_m),\ \min(x_{m+1}, \dots, x_b) \Big) \]
  4. Simplest form: a segment tree stores the min of fixed blocks. Any range is the min of \(O(\log n)\) stored blocks, with identity \(+\infty\): \[ \text{merge}(u, v) = \min(u, v), \qquad \text{merge}(u, +\infty) = u \]
Key observations
  1. \(\min\) has no inverse. You cannot "un-min" a prefix the way you subtract a prefix sum, so the prefix trick is dead.
  2. \(\min\) is associative, so any range can be built from a few precomputed blocks.
  3. A segment tree splits every range into \(O(\log n)\) stored nodes. It is the same structure used for the dynamic problems, so there is nothing new to memorise.
  4. No updates, so update is never written. Only build and query remain.
  5. The identity is INF = 2e18, not \(0\). A node outside the range is merged into the answer, and \(0\) would win every min.
Brute force → why it dies
naiveFor each query, scan \(a..b\) keeping the minimum. Or precompute the answer for all \(O(n^2)\) ranges.
cost \(O(nq)\) for the scan; \(O(n^2)\) memory for the table.
dies at \(n = q = 2\cdot 10^5\) gives \(4\cdot 10^{10}\) comparisons; the full table would need about \(2\cdot 10^{10}\) entries.
therefore Segment tree with a min merge: \(O(n)\) build, \(O(\log n)\) per query, \(O(n)\) space.
Diagram
Implementation

The only edits to the standing template are node.mn in place of node.sum, the min merge, and the constructor's INF. The easily-misread line is if (l > rq || r < lq) return node(); — that default node is the \(+\infty\) identity, and returning it is how a disjoint subtree declines to affect the answer. n is a file-scope global because build and query take the segment bounds explicitly, not the array length.

arrays/Static_Range_Minimum_Queries.cppverbatim
// Problem: Static Range Minimum Queries
// Link: CSES 1647
// Pattern: segment tree, same template as templates/segment_tree.cpp,
// merge swapped to min (identity = +infinity instead of 0)
// Time: O((n + q) log n)  Space: O(n)
//
// Array never changes; answer q range-minimum queries.
//
// Example:
//     3 2 4 5 1 1 5 3, query (2,4) -> 2, (5,6) -> 1, (1,8) -> 1, (3,3) -> 4

#include <iostream>
using namespace std;
typedef long long ll;

const int MAXN = 200020;
const ll INF = 2e18;

struct node {
    ll mn;
    node() { mn = INF; }
};

node t[4 * MAXN];
ll arr[MAXN];
int n;

node merge(node a, node b) {
    node res;
    res.mn = min(a.mn, b.mn);
    return res;
}

void build(ll id, ll l, ll r) {
    if (l == r) {
        t[id].mn = arr[l];
        return;
    }
    ll mid = (l + r) / 2;
    build(2 * id, l, mid);
    build(2 * id + 1, mid + 1, r);
    t[id] = merge(t[2 * id], t[2 * id + 1]);
}

node query(ll id, ll l, ll r, ll lq, ll rq) {
    if (l > rq || r < lq) return node();
    if (l >= lq && r <= rq) return t[id];
    ll mid = (l + r) / 2;
    node left = query(2 * id, l, mid, lq, rq);
    node right = query(2 * id + 1, mid + 1, r, lq, rq);
    return merge(left, right);
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int q;
    cin >> n >> q;

    for (int i = 0; i < n; i++) cin >> arr[i];
    build(1, 0, n - 1);

    for (int i = 0; i < q; i++) {
        int a, b;
        cin >> a >> b;
        cout << query(1, 0, n - 1, a - 1, b - 1).mn << '\n';
    }

    return 0;
}

tok = iter(sys.stdin.read().split())

INF = 2 * 10**18

class node:                                 # struct node { ll mn; node() { mn = INF; } }
    def __init__(self):                     # __init__ is the constructor; self is "this"
        self.mn = INF

def merge(a, b):
    res = node()
    res.mn = min(a.mn, b.mn)
    return res

def build(id, l, r):
    if l == r:
        t[id].mn = arr[l]
        return
    mid = (l + r) // 2
    build(2 * id, l, mid)
    build(2 * id + 1, mid + 1, r)
    t[id] = merge(t[2 * id], t[2 * id + 1])

def query(id, l, r, lq, rq):
    if l > rq or r < lq: return node()
    if l >= lq and r <= rq: return t[id]
    mid = (l + r) // 2
    left = query(2 * id, l, mid, lq, rq)
    right = query(2 * id + 1, mid + 1, r, lq, rq)
    return merge(left, right)

def main():

    n, q = int(next(tok)), int(next(tok))
    t = [node() for _ in range(4 * n)]      # node t[4*MAXN]: sized from n instead of MAXN
    arr = [int(next(tok)) for _ in range(n)]
    build(1, 0, n - 1)
    out = []
    for i in range(q):
        a, b = int(next(tok)), int(next(tok))
        out.append(query(1, 0, n - 1, a - 1, b - 1).mn)
    print('\n'.join(map(str, out)))

Gotcha"Static" does not mean "no tree" — that shortcut only exists for invertible aggregates. And the identity must be \(+\infty\): leaving the sum tree's node() { sum = 0; } in place makes every partially-overlapping query answer 0, which passes the sample and fails everything else.
Recognize"many range min/max queries, array fixed" → segment tree with the matching merge, build once, no update.

2 · Dynamic range queries

Point updates arrive interleaved with the queries, so nothing precomputed over whole prefixes survives. The segment tree is the answer to both, and the two files differ by three lines — the field name, the merge, and the identity. Read them as one problem solved twice.

Dynamic Range Sum Queries

\(O((n+q) \log n)\)
The ask

Question. You are given an array of \(n\) integers and \(q\) operations, in any order. Each operation is one of two kinds: set position \(k\) to value \(u\), or print the sum of positions \(a\) to \(b\).

Input
\(n,\ q\); then \(x_1, \dots, x_n\); then \(q\) lines: 1 k u or 2 a b.
Output
For each 2 a b, the sum \(x_a + \dots + x_b\).
Limits
\(1 \le n, q \le 2\cdot 10^5,\ \ 1 \le x_i, u \le 10^9\)
Sample
3 2 4 5 1 1 5 3: sum\((1,4) = 14\), sum\((5,6) = 2\), set \(x_3 = 1\), sum\((1,4) = 11\)
Breakdown
  1. Two operations: \[ \text{set: } x_k \leftarrow u, \qquad \text{query: } \sum_{i=a}^{b} x_i \]
  2. Prefix sums fail here: changing \(x_k\) changes every \(P_i\) with \(i \ge k\), which is \(O(n)\) per update.
  3. A segment tree node stores the sum of one block. Position \(k\) lies in only the \(\lceil \log_2 n \rceil + 1\) blocks on its root-to-leaf path. After setting the leaf, each of those parents is recomputed: \[ \text{node} = \text{left child} + \text{right child} \]
  4. Simplest form: update and query both cost \(O(\log n)\), merge is \(+\), identity is \(0\).
Key observations
  1. A prefix table is global. Changing \(x_k\) breaks every \(P_i\) with \(i \ge k\): \(O(n)\) per update.
  2. A segment tree is local. Position \(k\) appears in exactly the \(O(\log n)\) nodes on its root-to-leaf path, and nowhere else.
  3. So an update is one walk down plus one recompute per ancestor on the way back up.
  4. The update sets the value, it does not add to it. The leaf is overwritten; no difference is computed.
  5. Merge is \(+\) and the identity is \(0\): the template unchanged.
Brute force → why it dies
naiveRebuild the prefix table after each update (or skip it and scan \(a..b\) for each query).
cost \(O(n)\) per operation, so \(O(nq)\).
dies at \(n = q = 2\cdot 10^5\) gives \(4\cdot 10^{10}\) operations.
therefore Segment tree with a sum merge: \(O(\log n)\) per update and per query, \(O((n + q) \log n)\) total.
Diagram
Implementation

This is the canonical segment tree with no adaptation at all — only main is new, dispatching on the operation type. In update both recursive calls are always issued; the one whose segment excludes pos returns on its first line, which is what keeps the walk O(log n) despite looking like a full traversal. The re-merge sits after both calls, so a node is recomputed only once its children are final.

// Problem: Dynamic Range Sum Queries
// Link: CSES 1648
// Pattern: segment tree, same as templates/segment_tree.cpp — point
// update (set, not add) + range sum query
// Time: O((n + q) log n)  Space: O(n)
//
// Array supports point updates (set position k to u) interleaved with range
// sum queries.
//
// Example:
//     3 2 4 5 1 1 5 3, sum(1,4)=14, sum(5,6)=2, set(3,1), sum(1,4)=11

#include <iostream>
using namespace std;
typedef long long ll;

const int MAXN = 200020;

struct node {
    ll sum;
    node() { sum = 0; }
};

node t[4 * MAXN];
ll arr[MAXN];
int n;

node merge(node a, node b) {
    node res;
    res.sum = a.sum + b.sum;
    return res;
}

void build(ll id, ll l, ll r) {
    if (l == r) {
        t[id].sum = arr[l];
        return;
    }
    ll mid = (l + r) / 2;
    build(2 * id, l, mid);
    build(2 * id + 1, mid + 1, r);
    t[id] = merge(t[2 * id], t[2 * id + 1]);
}

void update(ll id, ll l, ll r, ll pos, ll val) {
    if (pos < l || pos > r) return;
    if (l == r) {
        t[id].sum = val;
        return;
    }
    ll mid = (l + r) / 2;
    update(2 * id, l, mid, pos, val);
    update(2 * id + 1, mid + 1, r, pos, val);
    t[id] = merge(t[2 * id], t[2 * id + 1]);
}

node query(ll id, ll l, ll r, ll lq, ll rq) {
    if (l > rq || r < lq) return node();
    if (l >= lq && r <= rq) return t[id];
    ll mid = (l + r) / 2;
    node left = query(2 * id, l, mid, lq, rq);
    node right = query(2 * id + 1, mid + 1, r, lq, rq);
    return merge(left, right);
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int q;
    cin >> n >> q;

    for (int i = 0; i < q; i++) {
        int type;
        cin >> type;
        if (type == 1) {
            int k;
            ll u;
            cin >> k >> u;
            update(1, 0, n - 1, k - 1, u);
        } else {
            int a, b;
            cin >> a >> b;
            cout << query(1, 0, n - 1, a - 1, b - 1).sum << '\n';
        }
    }

    return 0;
}

Dynamic Range Minimum Queries

\(O((n+q) \log n)\)
The ask

Question. Same as Dynamic Range Sum Queries, but the query asks for the minimum. There are \(q\) operations: set position \(k\) to \(u\), or print the smallest value from position \(a\) to position \(b\).

Input
\(n,\ q\); then \(x_1, \dots, x_n\); then \(q\) lines: 1 k u or 2 a b.
Output
For each 2 a b, \(\min(x_a, \dots, x_b)\).
Limits
\(1 \le n, q \le 2\cdot 10^5,\ \ 1 \le x_i, u \le 10^9\)
Sample
3 2 4 5 1 1 5 3: min\((1,4) = 2\), min\((5,6) = 1\), set \(x_2 = 3\), min\((1,4) = 3\)
Breakdown
  1. Two operations: \[ \text{set: } x_k \leftarrow u, \qquad \text{query: } \min_{a \le i \le b} x_i \]
  2. After a set, a parent cannot be fixed by a difference (raising a value may make the sibling the new min). It must be recomputed: \[ \text{node} = \min(\text{left child},\ \text{right child}) \]
  3. Simplest form: the same segment tree as the sum version, with merge \(\min\) and identity \(+\infty\). \(O(\log n)\) per operation.
Key observations
  1. Nothing new: this is Static Range Minimum's merge plus Dynamic Range Sum's update. Seeing that is the solution.
  2. The parent is recomputed as the \(\min\) of both children, not patched. Raising a value can make the parent take the sibling's value instead.
  3. That is why a Fenwick tree does not work here while a segment tree does: no inverse, no difference, no prefix trick.
  4. The identity stays INF = 2e18, which is larger than any real value, so it never wins a real query.
Brute force → why it dies
naiveScan \(a..b\) per query; apply sets directly to the array.
cost \(O(1)\) per set but \(O(n)\) per query, so \(O(nq)\).
dies at \(n = q = 2\cdot 10^5\) gives \(4\cdot 10^{10}\) comparisons. No prefix shortcut exists, because \(\min\) has no inverse.
therefore The same tree again, merge \(\min\), identity \(+\infty\): \(O((n + q) \log n)\).

3 · Order statistics on a segment tree

The tree stops being a range-aggregate structure and becomes a searchable index. Store 1 for alive and 0 for removed; then node.sum is a survivor count, and one extra descent turns "which element has rank k right now?" into O(log n). Any repeated remove-by-rank problem lands here.

Josephus Queries

\(O(n \log n)\)
The ask

Question. Children numbered \(1, \dots, n\) stand in a circle. Going around the circle, you repeatedly skip \(k\) children and remove the next one. Print the numbers of the children in the order they are removed.

Input
\(n,\ k\).
Output
\(n\) numbers: the removal order.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 0 \le k \le 10^9\)
Sample
\(n = 7,\ k = 2\) → 3 6 2 7 5 1 4
Breakdown
  1. Number the children still in the circle by rank, \(1..m\), left to right, where \(m\) is how many remain. Ranks stay dense after every removal; the original numbers do not.
  2. Let \(r_t\) be the rank removed at step \(t\), and \(m_t = n - t + 1\) the number present before it. Skipping \(k\) children is a shift by \(k\), wrapping around: \[ r_1 = (k \bmod n) + 1, \qquad r_{t+1} = \big( (r_t - 1) + k \big) \bmod m_{t+1} \;+\; 1 \]
  3. The \((r_t - 1)\) appears because after removing rank \(r_t\), the next child slides into rank \(r_t\). Then the \(\bmod\) removes all full laps, so a huge \(k\) costs nothing.
  4. Simplest form: keep a sum tree over \(0/1\) "still here" flags. "Which child has rank \(r\)?" is a walk down the tree, going left while the left child holds \(\ge r\) children: \[ \text{child}(r) = \min \Big\{\, p : \sum_{i \le p} \text{alive}_i = r \,\Big\} \] Sample: \(r_1 = 3\) removes child \(3\); \(r_2 = (2 + 2) \bmod 6 + 1 = 5\) is child \(6\).
Key observations
  1. Work with ranks among the remaining children, not original numbers. Ranks stay \(1..m\) after every removal; original numbers do not.
  2. With ranks the step is pure arithmetic: \(r \leftarrow (r - 1 + k) \bmod m + 1\). The \(\bmod m\) removes every full lap, so \(k\) up to \(10^9\) costs nothing.
  3. Removing rank \(r\) shifts everyone after it down by one, so the child now standing just after the gap has rank \(r\) again. Hence idx = nextRank - 1 feeds the next +1.
  4. Rank → child number is the only hard step, and a sum tree over \(0/1\) flags does it: walk down, going left while the left child holds at least \(r\) children.
  5. Removal is a point update to \(0\), the same update as the dynamic problems. No new code.
Brute force → why it dies
naiveCircular list or vector: walk \(k \bmod m\) steps each round and erase the child.
cost \(O(n)\) per removal (the walk can be a full lap, and vector::erase is linear anyway), so \(O(n^2)\).
dies at \(n = 2\cdot 10^5\) gives about \(2\cdot 10^{10}\) steps.
therefore Sum tree over the flags plus a find-\(r\)-th walk: \(O(\log n)\) per removal, \(O(n \log n)\) total.
Diagram
Implementation

4 · Binary search on the answer

No structure is built over the array at all. The search runs over the answer space — a cap in seconds, a cap on a block sum — and the array only appears inside a boolean feasible(x). The whole method rests on that predicate being monotone: false up to some threshold, true from there on. Find the phrase "minimise the maximum" or "maximise the minimum" and this is the shape.

Array Division

\(O(n \log C)\)
The ask

Question. You are given an array of \(n\) positive integers. Split it into \(k\) contiguous subarrays so that the largest subarray sum is as small as possible. Print that largest sum.

Input
\(n,\ k\), then \(x_1, \dots, x_n\).
Output
One integer: the largest subarray sum in the best split.
Limits
\(1 \le k \le n \le 2\cdot 10^5,\ \ 1 \le x_i \le 10^9\)
Sample
\(k = 3\), 2 4 7 3 5 → 8 (split [2,4] [7] [3,5], sums \(6, 7, 8\))
Breakdown
  1. State it exactly: over all ways to cut into blocks \(B_1, \dots, B_k\): \[ \text{ans} = \min_{B_1, \dots, B_k} \; \max_{j} \sum_{i \in B_j} x_i \]
  2. Turn it into a yes/no question. For a cap \(c\), let \(g(c)\) be the number of blocks the greedy makes (grow a block until the next element would push it past \(c\)): \[ \text{ok}(c) \iff \max_i x_i \le c \ \text{ and } \ g(c) \le k \]
  3. A larger cap never needs more blocks, so \(\text{ok}\) is monotone: \[ c \le c' \;\Longrightarrow\; g(c') \le g(c) \;\Longrightarrow\; \big(\text{ok}(c) \Rightarrow \text{ok}(c')\big) \]
  4. Simplest form: binary search the smallest good cap in \([\max x,\ \sum x]\): \[ \text{ans} = \min \{\, c : \text{ok}(c) \,\} \] Sample: \(c = 7\) needs \(4\) blocks (no), \(c = 8\) needs \(3\) (yes), so the answer is \(8\).
Key observations
  1. Guess the answer instead of building it: fix a cap \(c\) and ask only "can it be done with every block sum \(\le c\)?"
  2. That test is monotone (a looser cap never needs more blocks), so the good caps form a ray \([c^*, \infty)\) and binary search finds its left end.
  3. For a fixed cap, growing each block until it would overflow uses the fewest blocks possible, so checking \(g(c) \le k\) settles it in one pass.
  4. Any single element larger than \(c\) makes \(c\) impossible, whatever the block count says.
  5. "Exactly \(k\)" and "at most \(k\)" blocks give the same answer here. Values are positive, so splitting a block further never raises the maximum.
Brute force → why it dies
naiveDP over (prefix length, blocks used): \(dp[i][j] = \min_p \max\big(dp[p][j-1],\ x_{p+1} + \dots + x_i\big)\).
cost \(O(nk)\) states, \(O(n)\) choices each, so \(O(n^2 k)\).
dies at \(n = 2\cdot 10^5,\ k \le n\) gives up to \(4\cdot 10^{10}\) states before any choice is tried.
therefore Binary search the cap with an \(O(n)\) greedy check: \(O(n \log C)\), about \(60\) rounds for \(C = 10^{18}\).
Diagram
Implementation

check is the whole problem; solve is the textbook lower-bound search (ans = mid; r = mid - 1 on success). cnt starts at 1 because the first block is already open, so it counts blocks, not cuts. Factory Machines

\(O(n \log C)\)
The ask

Question. A factory has \(n\) machines. Machine \(i\) needs \(k_i\) seconds to make one product. All machines can work at the same time. What is the shortest time to make \(t\) products in total?

Input
\(n,\ t\), then \(k_1, \dots, k_n\).
Output
One integer: the minimum time.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le t \le 10^9,\ \ 1 \le k_i \le 10^9\)
Sample
\(t = 7\), 3 2 5 → 8 (machines make \(2 + 4 + 1 = 7\))
Breakdown
  1. In \(x\) seconds, machine \(i\) makes \(\lfloor x / k_i \rfloor\) products (idling never helps). So the total is: \[ F(x) = \sum_{i=1}^{n} \left\lfloor \frac{x}{k_i} \right\rfloor \]
  2. \(F\) never decreases as \(x\) grows, so the answer is the first \(x\) where it reaches \(t\): \[ \text{ans} = \min \{\, x : F(x) \ge t \,\} \]
  3. An upper bound: the fastest machine alone makes \(t\) products in \(t \cdot \min k_i \le 10^9 \cdot 10^9 = 10^{18}\).
  4. Simplest form: binary search \(x \in [1, 10^{18}]\), computing \(F(x)\) in \(O(n)\), and stop adding once the sum reaches \(t\) so it cannot overflow. Sample: \(F(7) = 2 + 3 + 1 = 6 \lt 7\), \(F(8) = 2 + 4 + 1 = 7\), so the answer is \(8\).
Key observations
  1. "You can freely decide their schedule" is a distraction. A machine never gains by idling, so in \(x\) seconds it makes exactly \(\lfloor x / k_i \rfloor\).
  2. That makes the machines independent: the total is a plain sum, with nothing to assign.
  3. \(F(x)\) never decreases as \(x\) grows, so "\(F(x) \ge t\)" is monotone. Binary search the time.
  4. Upper bound: \(t \cdot \min k_i \le 10^9 \cdot 10^9 = 10^{18}\), which is where hi = 1e18 comes from.
  5. Stop the sum once it reaches \(t\). At \(x = 10^{18}\) over \(2\cdot 10^5\) machines it could reach about \(10^{23}\) and overflow.
Brute force → why it dies
naiveSimulate product by product: a heap of next finish times, popped \(t\) times.
cost \(O(t \log n)\), or \(O(\text{answer})\) if ticking second by second.
dies at \(t = 10^9\) heap pops is too many, and the answer can reach \(10^{18}\), so a per-second loop is hopeless.
therefore Binary search \(x\) with an \(O(n)\) count: \(O(n \log C)\), about \(2\cdot 10^5 \times 60\) operations.
Diagram
Implementation

GotchaThe overflow is real and the code does handle it — but only because the total >= t test sits inside the loop. Hoist it below the loop "for tidiness" and \(2\cdot 10^{5}\) machines with \(k_{i} = 1\) at \(x = 10^{18}\) accumulate \(2\cdot 10^{23}\), wrapping long long negative and making check answer false for a feasible time. Secondary: mid = (lo + hi) / 2 peaks at \(2\cdot 10^{18}\) here, which fits only because hi is \(10^{18}\) and not LLONG_MAX.
Recognize"independent workers / machines in parallel, shortest time to reach a total" → binary search the time, feasibility is \(\sum \lfloor x / \text{rate}\rfloor \ge \text{target}\), capped as it accumulates.
