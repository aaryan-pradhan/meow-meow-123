Sweep & Ordered Set

Every problem here arrives as a list of intervals or a stream of points. Two answers follow. Either you sort once and sweep, carrying one or two scalars past every endpoint — or the structure has to stay sorted while it is edited, and a set/multiset does the work a hand-shifted array cannot. Reach for this page when the input is (start, end) pairs, or when the question is asked again after every insertion.

Recognition rules

The judgment calls that separate these problems from each other. Every rule must be demonstrated by at least two entries on this page.

01

Identical input, different aggregate, different sweep. Restaurant Customers and Union of Painted Bricks both read n pairs (l, r). “How many at once” → split each pair into \(+1/-1\) events and sweep a counter. “How much is covered in total” → sort by l and merge into one open block. Decide which one from the question; the data cannot tell you.

02

When the swept counter returns to its starting value, the answer must be latched mid-sweep. Restaurant Customers' running and Room Allocation's c are both 0 at the last event — every arrival is matched by a departure. Both carry a separate best/k updated inside the loop. Reading the final state gives 0, every time.

03

The comparator's tie-break is the problem's inequality — it is never cosmetic. Room Allocation sorts +1 before \(-1\) at equal time because a departure on day t does not free the room for an arrival on day t. Nested Ranges Check sorts r descending on equal l so the wider range is seen first. Flip either one and the code still compiles, still runs, and is wrong.

04

Use multiset, not set, whenever the stored values are distinct entities that may legitimately collide: Tower of Cubes' tower tops (two towers can share a top height), Traffic Lights' gap lengths (two gaps can share a length). Corollary, in both: remove the one instance that changed with s.erase(s.find(x)), never s.erase(x) — the value form erases every match.

05

Sort once, sweep twice. Nested Ranges Check runs the same sorted array forward with a running max r and backward with a running min r, answering the two symmetric halves of the question; Room Allocation sweeps its event array once to size k and again to assign rooms. A second pass over sorted data is free next to a second data structure.

06

Sentinels and pre-sized pools beat boundary special-cases. Traffic Lights seeds positions with {0, x} so the very first light already has a predecessor and a successor; Room Allocation fills the free pool with all k rooms before assigning any, so an arrival never has to invent one. Both turn an “is it empty?” branch into no branch at all.

07

A running extremum certifies existence, never multiplicity. Nested Ranges Check gets its 0/1 answer from a single scalar per pass, and Union of Painted Bricks' (curL, curR) knows how far the block reaches but not how many segments painted any brick. The moment the question becomes “how many”, one scalar touched once per index cannot exceed 1 and the family needs a Fenwick/segment tree over compressed endpoints instead — which is exactly why Nested_Ranges_Count.cpp is in the excluded box at the foot of this page.

1 · Interval sweep & containment

All three sort the intervals first and then make a single pass carrying one or two scalars — a running count, an open block, or the extreme endpoint seen so far. The input shape is the same every time; what changes is which scalar you carry, and that is chosen by the question. The sort key, and especially its tie-break, is where these problems actually go wrong.

Restaurant Customers

\(O(n \log n)\)
The ask

Question. You know the arrival time \(a_i\) and leaving time \(b_i\) of each of \(n\) customers. What is the largest number of customers in the restaurant at the same time?

Input
\(n\), then \(n\) lines \(a_i\ b_i\).
Output
One integer: the maximum number of customers present at once.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le a_i \lt b_i \le 10^9\); all \(2n\) times are different.
Sample
(5,8) (2,4) (3,9) → 2
Breakdown
  1. State it exactly: \[ \text{ans} = \max_{t} \; \#\{\, i : a_i \le t \le b_i \,\} \]
  2. The count only changes at an arrival or a departure. So only the \(2n\) event times need checking.
  3. Turn each customer into two events, \(+1\) at \(a_i\) and \(-1\) at \(b_i\). Sort all events by time. The count just after event \(e\) is a prefix sum: \[ c_e = \sum_{e' \le e} \delta_{e'}, \qquad \delta \in \{+1, -1\} \]
  4. Simplest form: \[ \text{ans} = \max_{e} \; c_e \] Sample: events \(2{+}, 3{+}, 4{-}, 5{+}, 8{-}, 9{-}\) give counts \(1, 2, 1, 2, 1, 0\), so the answer is \(2\).
Key observations
  1. The count only changes at an endpoint, so the maximum is reached at some arrival \(a_i\). Only the \(2n\) endpoints matter, not the \(10^9\) moments between them.
  2. Who is inside never matters, only how many. So each interval can be split into two independent events, \(a_i \to +1\) and \(b_i \to -1\), and the pairing forgotten.
  3. Sorted by time, the count at any moment is the prefix sum of those \(\pm 1\) values. One pass, one running total.
  4. Every \(+1\) has a matching \(-1\), so the running total ends at \(0\). The answer must be recorded during the sweep, not read at the end.
  5. CSES guarantees all \(2n\) times are different, so an arrival and a departure never tie. That is the only reason the default pair ordering is safe here (see the Gotcha).
Brute force → why it dies
naiveFor each of the \(2n\) event times, scan all \(n\) intervals and count those covering it.
cost \(O(n^2)\) time, \(O(n)\) space.
dies at \(n = 2\cdot 10^5\) gives \(2n \cdot n = 8\cdot 10^{10}\) checks. An array over all moments is worse still, since \(t \le 10^9\).
therefore Replace the intervals by \(2n\) signed events and sort them. The count becomes one prefix sum: \(O(n \log n)\) time (the sort), \(O(n)\) space.
Diagram
Implementation

Events are pair<long long, int>, so the plain sort sorts by time and then by delta with no comparator. The line to read carefully is that one: \(-1 \lt +1\), so at an equal timestamp a departure would be processed before an arrival. That is the opposite of what Room Allocation needs, and it is only harmless here because the statement guarantees distinct times. best is updated every iteration, not after the loop.

// Problem: Restaurant Customers
// Link: CSES 1619
// Pattern: sweep line — split each interval into +1/-1 events, sort by
// time, track running total and its max
// Time: O(n log n)  Space: O(n)
//
// Given n (arrival, leaving) intervals, find the max number simultaneously
// present.
//
// Example:
//     (5,8) (2,4) (3,9) -> 2

#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n;
    cin >> n;

    vector<pair<long long, int>> events;
    events.reserve(2 * n);
    for (int i = 0; i < n; i++) {
        long long a, b;
        cin >> a >> b;
        events.push_back({a, 1});
        events.push_back({b, -1});
    }

    sort(events.begin(), events.end());

    int running = 0, best = 0;
    for (auto& [time, delta] : events) {
        running += delta;
        best = max(best, running);
    }

    cout << best << '\n';
    return 0;
}
import sys
tok = iter(sys.stdin.read().split())

def main():
    n = int(next(tok))
    events = []                             # vector<pair<ll,int>>; reserve() not needed
    for i in range(n):
        a, b = int(next(tok)), int(next(tok))
        events.append((a, 1))
        events.append((b, -1))
    events.sort()                           # tuples sort like pairs: by [0], then [1]
    running, best = 0, 0

GotchaThe running total is 0 at the last event — capture best inside the loop or the answer is always zero. And the default pair sort orders \(-1\) before \(+1\) on a tie, i.e. it assumes a customer who leaves at t frees the table for one arriving at t. That holds here only because all times are distinct; do not copy this comparator into a problem that allows ties.
Recognize“maximum number of intervals active at the same moment” → shred into ±1 events, sort, prefix-sum, latch the max.

Union of Painted Bricks

\(O(N \log N)\)
The ask

Question. On each of \(N\) days, every brick numbered from \(L_i\) to \(R_i\) (inclusive) is painted. Painting a brick again changes nothing. How many different bricks are painted in the end?

Input
\(N\), then \(N\) pairs \(L_i\ R_i\).
Output
One integer: the number of painted bricks.
Limits
Brick numbers up to about \(10^9\) (from the file).
Sample
(2,5) (10,10) (4,5) (3,7) (12,14) → 10
Breakdown
  1. State it exactly: count the whole numbers in the union of the intervals: \[ \text{ans} = \Big|\, \bigcup_{i=1}^{N} \{L_i, L_i + 1, \dots, R_i\} \,\Big| \]
  2. The union is a set of separate blocks. Sort the intervals by \(L\). Keep the current open block \([c_L, c_R]\).
  3. For the next interval \([l, r]\): \[ l \le c_R \;\Rightarrow\; c_R \leftarrow \max(c_R, r), \qquad l \gt c_R \;\Rightarrow\; \text{close the block, start } [l, r] \]
  4. Simplest form: add up the closed blocks (both ends count): \[ \text{ans} = \sum_{\text{blocks}} (c_R - c_L + 1) \] Sample: blocks \([2,7], [10,10], [12,14]\) give \(6 + 1 + 3 = 10\).
Key observations
  1. Brick numbers reach about \(10^9\), so the answer must come from the \(N\) intervals alone, never from an array with one cell per brick.
  2. The union of intervals is a set of separate maximal blocks, and sorting by \(L\) finds them from left to right.
  3. With the list sorted by \(L\), a new interval either starts inside the open block (\(l \le c_R\)), so extend \(c_R = \max(c_R, r)\), or starts after it, which proves the open block is finished.
  4. Both ends are included, so a finished block adds \(c_R - c_L + 1\), not \(c_R - c_L\).
  5. The last block has nothing after it to close it, so it is added once more after the loop. That line is not a duplicate.
  6. \(N \cdot 10^9\) can reach about \(10^{14}\), so the total needs long long.
Brute force → why it dies
naiveA bool painted[] over all bricks, set across each interval; or test every pair of intervals for overlap.
cost \(O(\sum (R_i - L_i))\) time and \(O(\max R)\) space for the array; \(O(N^2)\) for the pairwise version.
dies at \(R \le 10^9\) means a \(10^9\)-cell array (about 1 GB as bool), and a single interval can take \(10^9\) steps to fill.
therefore Work with intervals, not bricks: sort by \(L\) and merge in one pass. \(O(N \log N)\) time, \(O(N)\) space, whatever the brick numbers are.
Diagram
Implementation

Sorting a vector<pair<ll,ll>> orders by L then R for free, and equal L needs no tie-break here — max(curR, r) picks up the right end whichever of them is processed first. seg[0] seeds the open block before the loop, which is why the loop starts at i = 1. The total += after the loop is the second flush, for the block that never met a segment far enough right to close it.

// Problem: Union of Painted Bricks
// Pattern: sort intervals by L, merge overlapping, sum merged lengths
// Time: O(N log N)  Space: O(N)
//
// N days, each day Mantesh paints all bricks in [L_i, R_i] (repaint is a
// no-op). Brick numbers can be up to ~1e9, so a per-brick boolean array
// doesn't fit. Count total distinct bricks painted = size of the union of N
// intervals.
//
// Example:
//     (2,5),(10,10),(4,5),(3,7),(12,14) -> 10

#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n; cin >> n;
    vector<pair<long long, long long>> seg(n);
    for (int i = 0; i < n; i++) cin >> seg[i].first >> seg[i].second;

    sort(seg.begin(), seg.end());

    long long total = 0;
    long long curL = seg[0].first, curR = seg[0].second;
    for (int i = 1; i < n; i++) {
        long long l = seg[i].first, r = seg[i].second;
        if (l <= curR) {
            curR = max(curR, r);
        } else {
            total += curR - curL + 1;
            curL = l;
            curR = r;
        }
    }
    total += curR - curL + 1;

    cout << total << '\n';
    return 0;
}
import sys
tok = iter(sys.stdin.read().split())

def main():
    n = int(next(tok))
    seg = [(int(next(tok)), int(next(tok))) for _ in range(n)]
    seg.sort()
    total = 0
    curL, curR = seg[0]                     # .first, .second unpacked at once
    for i in range(1, n):
        l, r = seg[i]
        if l <= curR:
            curR = max(curR, r)
        else:
            total += curR - curL + 1
            curL = l
            curR = r
    total += curR - curL + 1
    print(total)

GotchaTwo easy losses. The flush after the loop is mandatory — drop it and the final block vanishes from the total. And the contribution is \(\text{curR} - \text{curL} + 1\): these are inclusive brick indices, not real-line coordinates, so every block is one brick short without the +1. long long throughout; the total reaches \(\approx 10^{14}\).
Recognize“how many distinct positions are covered by these ranges, coordinates too large to mark” → sort by left endpoint, merge into one open block, sum inclusive lengths.

Nested Ranges Check

\(O(n \log n)\)
The ask

Question. You are given \(n\) different ranges \([x_i, y_i]\). Range \([a, b]\) contains range \([c, d]\) if \(a \le c\) and \(d \le b\). For each range, decide (1) whether it contains some other range, and (2) whether some other range contains it.

Input
\(n\), then \(n\) lines \(x_i\ y_i\).
Output
Line 1: for each range, 1 if it contains another, else 0. Line 2: 1 if another contains it, else 0. Input order.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le x_i \lt y_i \le 10^9\); no range appears twice.
Sample
[1,6] [2,4] [4,8] [3,6] → 1 0 0 0 / 0 1 0 1
Breakdown
  1. State both questions exactly: \[ \text{contains}_i = \big[\, \exists j \ne i : l_i \le l_j \text{ and } r_j \le r_i \,\big], \qquad \text{inside}_i = \big[\, \exists j \ne i : l_j \le l_i \text{ and } r_i \le r_j \,\big] \]
  2. Sort by \(l\) ascending, and for equal \(l\) by \(r\) descending. Then every range before \(i\) has \(l_j \le l_i\), and every range after has \(l_j \ge l_i\). One of the two inequalities is now free.
  3. Only the \(r\) test is left, and a running max or min answers "does one exist": \[ \text{inside}_i = \big[\, r_i \le \max_{j \text{ before } i} r_j \,\big], \qquad \text{contains}_i = \big[\, r_i \ge \min_{j \text{ after } i} r_j \,\big] \]
  4. Simplest form: one forward pass keeping maxr, one backward pass keeping minr, both on the same sorted order.
Key observations
  1. Containment is two inequalities. Sorting by \(l\) ascending makes the first one automatic for every earlier range, so only \(r\) is left to test.
  2. Forward pass: range \(i\) is inside an earlier one iff \(r_i \le\) the largest \(r\) seen so far. One number replaces the whole prefix.
  3. The backward pass is the mirror image. Scanning right to left, every later range already has \(l \ge l_i\), so \(i\) contains something iff \(r_i \ge\) the smallest \(r\) seen so far.
  4. Equal \(l\) is the one case where "earlier in the array" stops meaning "starts no later". Break ties by \(r\) descending. The wider range then comes first, so it is already in maxr when the narrower one is tested, and the narrower one is already in minr when the backward pass reaches the wider one. One sort order serves both passes.
  5. Ranges are guaranteed different, so a range never counts as its own witness. No \(i \ne j\) check is needed.
  6. A running max or min answers "does one exist". It cannot answer "how many". See rule 07 and the excluded box.
Brute force → why it dies
naiveTest every ordered pair \((i, j)\) against both inequalities.
cost \(O(n^2)\) time, \(O(n)\) space.
dies at \(n = 2\cdot 10^5\) gives \(4\cdot 10^{10}\) pairs against a 1 s limit.
therefore Sort by (\(l\) ascending, \(r\) descending) so one inequality is free, and turn the other into a running max or min. Two linear passes: \(O(n \log n)\) total, from the sort.
Diagram
Implementation

v is vector<pair<pll, ll>>: the range in .fr and its original index in .sc, which is how answers get written back in input order after the sort scrambles it. The one line a reader misreads is the output: ans1 is built by the forward maxr pass and means “is contained by something”, ans2 by the backward minr pass and means “contains something” — and they are printed in the reverse order to which they are computed, ans2 first, because the statement asks for “contains” on line one. minr is seeded from the INF macro, a double 1e18, which is safe only because \(r \le 10^{9}\).

2 · Heap-backed interval assignment

The sweep still finds the number, but now it also has to hand back an assignment. The textbook shape keeps a min-heap of (departure day, room) and pops it when the next arrival clears the earliest departure. This solution reaches the same O(n log n) from the other side: sweep ±1 events to learn k, then keep the free rooms in a plain stack — once k is fixed, every free room is interchangeable, so the heap's ordering is work nobody reads.

Room Allocation

\(O(n \log n)\)
The ask

Question. A hotel gets \(n\) customers. Customer \(i\) stays from day \(a_i\) to day \(b_i\) (inclusive) and needs one room. Two customers can use the same room only if the first one leaves strictly before the second one arrives. What is the minimum number of rooms, and which room does each customer get?

Input
\(n\), then \(n\) lines \(a_i\ b_i\).
Output
The minimum number of rooms \(k\); then the room number (\(1..k\)) of each customer, in input order. Any valid assignment is accepted.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le a_i \le b_i \le 10^9\)
Sample
[1,2] [2,4] [4,4] → 2 / 1 2 1
Breakdown
  1. Sharing rule, exactly: \[ i \text{ then } j \text{ can share a room} \iff b_i \lt a_j \] So two customers clash exactly when their closed intervals \([a_i, b_i]\) and \([a_j, b_j]\) overlap, touching ends included.
  2. On any day \(t\), everyone present needs a different room. That gives a lower bound: \[ k \ge \max_{t} \; \#\{\, i : a_i \le t \le b_i \,\} \]
  3. The bound is reached. Process events in time order, with arrivals before departures on the same day. An arriving customer takes any free room. A leaving customer returns theirs.
  4. Simplest form: \(k\) is the peak of the \(\pm 1\) sweep (as in Restaurant Customers, with ties broken \(+1\) first), and the free rooms are kept on a stack.
Key observations
  1. "Leaves strictly before the other arrives" means the closed intervals must not even touch. A room freed on day \(t\) is usable from day \(t + 1\), not day \(t\).
  2. So two customers clash exactly when their day intervals overlap, and the answer is the maximum number present at once, \(k\). It is the same \(\pm 1\) sweep as Restaurant Customers.
  3. \(k\) is a lower bound (that many people are present at once) and it can be reached, because handling events in time order never needs more rooms than the running peak.
  4. Which free room a customer gets does not matter. The free rooms need no order at all: a stack is enough, no heap or priority queue.
  5. Sorting \(+1\) before \(-1\) at the same day handles the strictness with no extra code. On day \(t\), the arrivals take rooms before that day's departures give any back.
  6. The pool starts with all \(k\) rooms, and \(k\) came from this same sweep. So rooms.back() is never called on an empty vector.
Brute force → why it dies
naiveTake customers by arrival; for each, scan every room opened so far for one whose last guest left before this arrival, else open a new room.
cost \(O(n \cdot k)\), which is \(O(n^2)\) when the intervals nest.
dies at \(n = 2\cdot 10^5\) with \(k\) up to \(n\) gives \(4\cdot 10^{10}\) room checks.
therefore One sorted event list, swept twice: once to find \(k\), once to assign rooms. The room scan becomes an \(O(1)\) pop_back/push_back on a stack of free rooms. \(O(n \log n)\) overall, all from the sort.
Diagram
Implementation

Events are array<ll,3> of {time, ±1, customer index}, and the comparator's second line, return a[1] > b[1], is the entire strictness rule: +1 sorts ahead of \(-1\). The same sorted vector is then swept twice. rooms is filled \(k, k-1, \dots , 1\) precisely so that back() is room 1 — it is a stack, not a heap, and pop_back/push_back are the whole allocator. Nothing keys on departure order, because nothing needs to.

3 · Ordered-set greedy maintenance

Here the sorted structure is not built once and read — it is edited at every step. Each element arrives, a predecessor/successor lookup finds the one place it interacts with, and one element is removed while one or two are inserted. In every problem here the container must be a multiset, because the values it stores are separate entities that can collide, and the answer is read straight off the container (size(), *rbegin()) rather than accumulated.

Tower of Cubes

\(O(n \log n)\)
The ask

Question. You get \(n\) cubes in a fixed order, with sizes \(c_1, \dots, c_n\). Each cube must either go on top of an existing tower whose top cube is strictly larger, or start a new tower. What is the minimum number of towers?

Input
\(n\), then \(c_1, \dots, c_n\).
Output
One integer: the minimum number of towers.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le c_i \le 10^9\)
Sample
3 8 2 1 5 → 2
Breakdown
  1. Only the top of each tower matters. Keep the multiset \(T\) of tops. Cube \(c\) may go on a tower with top \(t\) iff: \[ t \gt c, \qquad \text{after which that top becomes } c \]
  2. Among the tops that fit, choose the smallest. Any later cube that fits under it also fits under the bigger tops, so this keeps the most options open: \[ t^{*} = \min \{\, t \in T : t \gt c \,\} \]
  3. Update the multiset: \[ t^{*} \text{ exists} \;\Rightarrow\; T \leftarrow T - \{t^{*}\} + \{c\}, \qquad \text{otherwise} \;\Rightarrow\; T \leftarrow T + \{c\} \]
  4. Simplest form: \(t^{*}\) is upper_bound(c), and the answer is \(|T|\) at the end. Sample: tops go \(\{3\}, \{3, 8\}, \{2, 8\}, \{1, 8\}, \{1, 5\}\), so \(2\) towers.
Key observations
  1. A tower's history does not matter; only its current top can accept a cube. The whole state is the multiset of tops.
  2. Two towers can have the same top, so use multiset, not set.
  3. Among all tops \(\gt c\), place the cube on the smallest. Every later cube that fits under it also fits under the larger tops, so it is the least useful one to keep. Tightest fit first is the key step.
  4. "Smallest top strictly greater than \(c\)" is exactly upper_bound(c). lower_bound could return a top equal to \(c\), which cannot take it.
  5. Each cube inserts one value and erases at most one, so the multiset grows by one exactly when no tower fits. Its final size() is the number of towers.
Brute force → why it dies
naiveKeep the tops in a vector; for each cube scan all towers for the tightest fit.
cost \(O(n \cdot \text{towers})\), which is \(O(n^2)\) when the input is increasing and every cube starts its own tower.
dies at \(n = 2\cdot 10^5\) gives about \(2\cdot 10^{10}\) checks. A sorted vector does not help, since each insert still shifts \(O(n)\) elements.
therefore A multiset: upper_bound, erase and insert are each \(O(\log n)\), so \(O(n \log n)\) total.
Diagram
Implementation

Three multiset calls per cube and no bookkeeping at all. tops.erase(it) takes the iterator, which removes exactly that one element — the value overload would remove every top of that height. The insert is outside the if on purpose: both branches end by putting c into the multiset, and the only difference is whether an old top was erased first. The three // this takes O ( log n ) time comments are the author's own.

// Problem: Tower of Cubes
// Link: CSES 1073
// Pattern: patience-sorting-style greedy — multiset of tower tops, place
// each cube on the tightest-fitting tower (smallest top strictly > cube)
// Time: O(n log n)  Space: O(n)
//
// Process cubes in given order. Each cube either starts a new tower or goes
// on top of an existing tower whose current top is strictly larger.
// Minimize the number of towers.
//
// Example:
//     3 8 2 1 5 -> 2

#include <iostream>
#include <set>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n;
    cin >> n;

    multiset<int> tops;
    for (int i = 0; i < n; i++) {
        int c;
        cin >> c;
        auto it = tops.upper_bound(c);
        // this takes O ( log n ) time
        if (it != tops.end()) {
            tops.erase(it);
            // this takes O ( log n ) time
        }
        tops.insert(c);
        // this takes O ( log n ) time
    }

    cout << tops.size() << '\n';
    return 0;
}

from bisect import bisect_right, insort
tok = iter(sys.stdin.read().split())

def main():
    n = int(next(tok))
    tops = []                               # multiset<int> -> a list kept sorted
    for i in range(n):
        c = int(next(tok))
        j = bisect_right(tops, c)           # upper_bound(c): index of first element > c
        # this takes O ( log n ) time
        if j != len(tops):                  # it != tops.end()
            tops.pop(j)                     # erase(it)
            # ponytail: list.pop(j) is O(n), not O(log n); fine to read, slow at n = 2e5
        insort(tops, c)                     # insert(c), keeps the list sorted (also O(n))
    print(len(tops))

Gotchaupper_bound, not lower_bound — the rule needs a top strictly greater, and a top equal to c cannot take it. multiset, not set — two towers may share a top. And erase(it) by iterator, never erase(value), which would delete every tower with that top at once.
Recognize“minimum number of piles / towers / sequences, each must stay monotonic, input order is fixed” → multiset of pile tops, tightest-fit placement, answer is size().

Traffic Lights

\(O(n \log n)\)
The ask

Question. A street runs from position \(0\) to position \(x\). Traffic lights are added one at a time, at \(n\) different positions \(p_1, \dots, p_n\). After each addition, print the length of the longest part of the street with no traffic light.

Input
\(x,\ n\), then \(p_1, \dots, p_n\).
Output
\(n\) integers: the longest gap after each addition.
Limits
\(1 \le x \le 10^9,\ \ 1 \le n \le 2\cdot 10^5,\ \ 0 \lt p_i \lt x\), all different.
Sample
\(x = 8\), lights 3 6 2 → 5 3 3
Breakdown
  1. Let \(C = \{0, x\} \cup \{\text{lights so far}\}\), sorted as \(q_0 \lt q_1 \lt \dots \lt q_m\). The answer is the largest gap: \[ \text{ans} = \max_{k} \big( q_{k+1} - q_k \big) \]
  2. A new light \(p\) falls inside exactly one gap \((lo, hi)\), where \(lo\) and \(hi\) are its neighbours in \(C\). That gap is replaced by two: \[ hi - lo \;\longrightarrow\; (p - lo) \;+\; (hi - p) \]
  3. So keep two structures: the set \(C\) to find \(lo, hi\), and a multiset \(G\) of gap lengths.
  4. Simplest form, for each new light: \[ G \leftarrow G - \{hi - lo\} + \{p - lo,\ hi - p\}, \qquad \text{ans} = \max G \] Sample: gaps \(\{8\} \to \{3, 5\} \to \{3, 3, 2\} \to \{2, 1, 3, 2\}\), maxima \(5, 3, 3\).
Key observations
  1. The lights cut the street into gaps between neighbouring cut points. Adding one light destroys exactly one gap and creates exactly two.
  2. The destroyed gap is the one around \(p\): from its predecessor \(lo\) to its successor \(hi\) among the current cut points. That is one upper_bound and one step back.
  3. Treating \(0\) and \(x\) as cut points from the start means every new light has both a predecessor and a successor. There is no first-light or last-light special case.
  4. The maximum gap never grows, but it cannot be kept as a single number. When the largest gap is split, the answer becomes the next largest, which only the full collection knows.
  5. Gap lengths can repeat even though positions cannot, so use a multiset. The current maximum is *gaps.rbegin(), found in \(O(1)\).
Brute force → why it dies
naiveKeep the positions in a vector; after each addition, re-sort (or rescan) and take the largest neighbouring difference.
cost \(O(n^2)\) for the rescan, \(O(n^2 \log n)\) if re-sorting.
dies at \(n = 2\cdot 10^5\) gives about \(2\cdot 10^{10}\) differences recomputed, almost all unchanged.
therefore Two ordered containers with separate jobs: a set of positions for \(O(\log n)\) neighbour lookup, and a multiset of lengths for \(O(1)\) max. \(O(n \log n)\) total.
Diagram
Implementation

positions.upper_bound(p) gives the first cut point strictly above p — hi is read off it before the iterator is stepped back to give lo, which is the one line worth slowing down for. The if (it != positions.begin()) guard can never actually fire: 0 is always in the set and p > 0, so upper_bound is never begin() — it is defensive, not load-bearing. The two containers are updated in lockstep, and the answer is printed straight from *gaps.rbegin() with no separate maximum tracked anywhere.

// Problem: Traffic Lights
// Link: CSES 1163
// Pattern: set of boundary positions (with 0, x sentinels) for
// predecessor/successor lookup, multiset of gap lengths for O(1) max
// Time: O(n log n)  Space: O(n)
//
// Street 0..x, lights added one at a time at distinct positions. After
// each addition, print the longest gap with no light.
//
// Example:
//     x=8, lights 3 6 2 -> 5 3 3

#include <iostream>
#include <set>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    long long x;
    int n;
    cin >> x >> n;

    set<long long> positions = {0, x};
    multiset<long long> gaps = {x};

    for (int i = 0; i < n; i++) {
        long long p;
        cin >> p;

        auto it = positions.upper_bound(p);
        // this is the first element > p, so the previous element is the largest <= p

        long long hi = *it ; 
        
        if (it != positions.begin()) {
            it--;
        }

        long long lo = *it;

        gaps.erase(gaps.find(hi - lo));
        // all in O of log n time, since multiset is implemented as a balanced BST
        gaps.insert(p - lo);
        gaps.insert(hi - p);
        positions.insert(p);

        cout << *gaps.rbegin() << ' ';
    }
    cout << '\n';

    return 0;
}
import sys
from bisect import bisect_right, bisect_left, insort
tok = iter(sys.stdin.read().split())

def main():
    x, n = int(next(tok)), int(next(tok))
    positions = [0, x]                      # set<ll> -> sorted list (Python has no ordered set)
    gaps = [x]                              # multiset<ll> -> sorted list
    out = []
    for i in range(n):
        p = int(next(tok))
        j = bisect_right(positions, p)
        # this is the first element > p, so the previous element is the largest <= p
        hi = positions[j]                   # *it
        if j != 0:                          # it != positions.begin()
            j -= 1                          # it--
        lo = positions[j]
        gaps.pop(bisect_left(gaps, hi - lo))    # gaps.erase(gaps.find(hi - lo)): remove ONE copy
        # ponytail: sorted-list insert/erase is O(n), C++ multiset is O(log n)
        insort(gaps, p - lo)
        insort(gaps, hi - p)
        insort(positions, p)
        out.append(gaps[-1])                # *gaps.rbegin() = largest
    print(' '.join(map(str, out)))

Gotchagaps.erase(gaps.find(hi - lo)) removes one instance; gaps.erase(hi - lo) removes every gap of that length and quietly destroys the answer — two gaps sharing a length is the normal case, not a corner case. Also seed positions with {0, x} and gaps with {x} up front; without the sentinels the first light has no bracketing pair to look up. Note the local is named lo, not prev, because prev collides with std::prev under using namespace std.
Recognize“insert cut points one at a time, report the longest remaining segment after each” → set of positions for predecessor/successor, multiset of lengths for the max.

Concert Tickets

\(O((n+m) \log n)\)
The ask

Question. There are \(n\) concert tickets with prices \(h_1, \dots, h_n\). Then \(m\) customers arrive one after another. Customer \(j\) will pay at most \(t_j\), and gets the most expensive remaining ticket whose price does not exceed \(t_j\). That ticket is then gone. Print what each customer pays, or \(-1\) if they get nothing.

Input
\(n,\ m\); then \(h_1, \dots, h_n\); then \(t_1, \dots, t_m\).
Output
\(m\) lines: the price paid, or -1.
Limits
\(1 \le n, m \le 2\cdot 10^5,\ \ 1 \le h_i, t_j \le 10^9\)
Sample
prices 5 3 7 8 5, customers 4 8 3 → 3 8 -1
Breakdown
  1. Let \(H\) be the multiset of unsold prices. Customer \(j\) gets: \[ \text{pay}_j = \max \{\, h \in H : h \le t_j \,\}, \qquad \text{or } -1 \text{ if no such } h \]
  2. Then exactly one copy of that price is removed: \[ H \leftarrow H - \{\text{pay}_j\} \]
  3. Simplest form: "largest \(\le t\)" is the element just before the first one \(\gt t\): \[ \text{pay}_j = \text{prev}\big(\text{upper\_bound}(t_j)\big) \]
Key observations
  1. "Largest value \(\le t\)" is a predecessor query: upper_bound(t), then one step back.
  2. Tickets with equal prices are still different tickets, so use a multiset.
  3. Selling removes exactly one copy, so erase by iterator, not by value.
Brute force → why it dies
naiveScan all unsold tickets for each customer.
cost\(O(n \cdot m)\)
dies at\(n = m = 2\cdot 10^5\) gives \(4\cdot 10^{10}\).
thereforeBalanced search tree (multiset) with predecessor lookup and erase: \(O((n+m) \log n)\).
Diagram
Implementation

it == h.begin() after upper_bound means every price exceeds t. Otherwise it-- lands on the answer, and h.erase(it) removes that single element.
