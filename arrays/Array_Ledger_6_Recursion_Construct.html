Recognition rules

The judgment calls that separate these problems from each other.

1

n ≤ 20 and the question is "best over all subsets" → recurse take/skip, no DP needed: Apple Division. n ≤ 8 and the question is "count the valid placements" → recurse one row at a time: Chessboard and Queens.

2

"Print all … in alphabetical order" → sort, then next_permutation. It skips duplicates for free, so no set: Creating Strings.

3

Output length is \(2^{n}\) or \(2^{n}-1\) → the answer is a recursion on the output, not a search: Gray Code, Tower of Hanoi. Build the list for n−1, then glue.

4

"Print YES/NO, and an example if YES", n up to \(10^{9}\) or t up to \(10^{5}\) → there is a closed-form feasibility test. Find it first, construct second: Coin Piles, Raab Game I.

5

Rearrange characters under a symmetry constraint → count characters, check the parity condition, emit greedily: Palindrome Reorder.

1 · Exhaustive recursion

The constraint is tiny on purpose. Enumerate every choice, score the leaf, keep the best or the count. The only design question is what to carry down the recursion and what to recompute at the bottom.

Apple Division

\(O(2^{n}\cdot n)\)
The ask

Question. There are \(n\) apples with weights \(p_1, \dots, p_n\). Split them into two groups so that the difference between the two groups' total weights is as small as possible. Print that difference.

Input
\(n\), then \(p_1, \dots, p_n\).
Output
One integer: the minimum difference.
Limits
\(1 \le n \le 20,\ \ 1 \le p_i \le 10^9\)
Sample
3 2 7 4 1 → 1 (groups \(\{2,3,4\} = 9\) and \(\{1,7\} = 8\))
Breakdown
  1. Let \(S = \sum_i p_i\). Choosing group 1 as a subset \(T\) fixes group 2 as the rest, which weighs \(S - \sum_T p\): \[ \text{diff}(T) = \Big|\, \sum_{i \in T} p_i - \Big(S - \sum_{i \in T} p_i\Big) \Big| = \Big|\, S - 2 \sum_{i \in T} p_i \,\Big| \]
  2. So the problem is a minimum over all subsets: \[ \text{ans} = \min_{T \subseteq \{1, \dots, n\}} \Big|\, S - 2 \sum_{i \in T} p_i \,\Big| \]
  3. There are only \(2^n \le 2^{20} \approx 10^6\) subsets, so try them all: for each apple, decide "in \(T\)" or "not in \(T\)".
Key observations
  1. Choosing group 1 fixes group 2. So the search is over subsets, \(2^n\) of them. Each split is seen twice (\(T\) and its complement), which costs nothing.
  2. \(n \le 20\) gives \(2^{20} \approx 10^6\) leaves. Cheap.
  3. Sums reach \(20 \cdot 10^9 = 2\cdot 10^{10}\), so use ll, not int.
  4. The bitmask only carries the choice. The same recursion works with two running sums passed down; the mask version re-adds them at the leaf.
Brute force → why it dies
naiveTry all \(2^n\) subsets. Here that is the solution.
cost\(O(2^n \cdot n)\) here, because each leaf re-adds the mask.
dies atNothing: \(n \le 20\) gives about \(2\cdot 10^7\) operations.
thereforeAccept the extra factor \(n\). Carrying two running sums would give \(O(2^n)\), which is the version to write if \(n\) were \(30\).
Implementation

rec takes index i and the mask of everything chosen so far. Both branches are unconditional; the work happens only at i == n. ans starts at INF.

Chessboard and Queens

\(O(8! \cdot 8)\)
The ask

Question. Place eight queens on an \(8 \times 8\) chessboard so that no two attack each other (same row, column or diagonal). Some squares are reserved and cannot hold a queen, but reserved squares do not block attacks. How many valid placements are there?

Input
Eight lines of eight characters: . free, * reserved.
Output
One integer: the number of valid placements.
Limits
The board is always \(8 \times 8\).
Sample
the board in the file → 65
Breakdown
  1. Eight queens, eight rows, at most one per row, so exactly one per row. A placement is a list of columns \(c_0, \dots, c_7\), where \(c_i\) is the column of the queen in row \(i\).
  2. State it exactly: \[ \text{ans} = \#\big\{\, (c_0, \dots, c_7) : (i, c_i) \text{ free},\ \ c_i \ne c_j,\ \ |c_i - c_j| \ne |i - j| \ \ \forall i \ne j \,\big\} \]
  3. Fill rows top to bottom. When placing row \(r\), only rows above it can clash, so check the column and the two upward diagonals.
  4. Simplest form, a recursion over rows: \[ f(8) = 1, \qquad f(r) = \sum_{\substack{c \,:\, (r, c) \text{ free} \\ \text{and safe}}} f(r + 1), \qquad \text{ans} = f(0) \]
Key observations
  1. Exactly one queen per row is forced (8 queens, 8 rows, no two in a row). So the recursion goes over rows and only picks the column.
  2. Because rows are filled top-down, only squares above the current row can clash. check looks at the column and the two upward diagonals and nothing else.
  3. A reserved square blocks placement but not attacks. So it is tested only on v[row][col]; it never appears in check.
  4. Marking reserved squares as 2 and queens as 1 keeps both meanings in one grid, and check compares against 1.
Brute force → why it dies
naiveChoose any 8 of the 64 squares and test each choice.
cost\(\binom{64}{8} \approx 4.4\cdot 10^9\) choices, each checked in \(8^2\) steps.
dies atThe 1 s limit, by about three orders of magnitude.
thereforeOne queen per row cuts it to at most \(8^8 \approx 1.7\cdot 10^7\) paths, and clash checks prune far below \(8! = 40320\).
Diagram
Implementation

rec(row) returns the count for rows row..7 instead of mutating a global, so the base case is a plain return 1. Place, recurse, unplace.

Creating Strings

\(O(n!\cdot n)\)
The ask

Question. You are given a string of length \(n\). Print every different string that can be made by rearranging its characters, in alphabetical order. Print the count first.

Input
One string \(s\) of lowercase letters.
Output
The count \(k\), then the \(k\) strings in alphabetical order.
Limits
\(1 \le n \le 8\)
Sample
aabac → 20, then aaabc, aaacb, …, cbaaa
Breakdown
  1. There are \(n!\) orderings of the positions. Swapping equal letters gives the same string, so each distinct string is counted \(\prod_c \text{cnt}_c!\) times: \[ k = \frac{n!}{\prod_{c} \text{cnt}_c!} \] Sample: \(\frac{5!}{3!\, 1!\, 1!} = \frac{120}{6} = 20\).
  2. next_permutation steps to the next larger distinct arrangement in alphabetical order, and returns false after the largest one.
  3. Simplest form: sort \(s\) (the smallest arrangement), then step until it returns false. That visits each of the \(k\) strings once, already in order.
Key observations
  1. next_permutation walks the arrangements in alphabetical order and skips duplicates automatically. It returns false once the string is the last (descending) one.
  2. So the string must be sorted first, so the walk starts at the smallest arrangement and covers all of them.
  3. Use do … while, not while: the sorted string itself is the first answer and must be recorded before any call.
  4. The count must be printed before the strings, so they are stored in a vector rather than printed as they are made.
Brute force → why it dies
naiveRecurse over positions and insert every result into a set<string> to remove duplicates.
cost\(O(n! \cdot n \log(n!))\), plus memory for all \(n!\) strings, duplicates included.
dies atIt survives \(n \le 8\) (\(8! = 40320\)), but it is more code.
thereforeUse the standard library walk: sorted order and duplicate removal both come free.
Implementation

Four lines of logic. The vector exists only because the count has to be printed first.

2 · Recursive construction

The output itself is defined by a recurrence. Solve for n−1, then describe the n case as two copies of it with something glued between or in front. No search, no pruning — every step of the answer is forced.

Gray Code

\(O(n\cdot 2^{n})\)
The ask

Question. A Gray code is a list of all \(2^n\) bit strings of length \(n\) in which any two neighbouring strings differ in exactly one bit. Print one Gray code for the given \(n\).

Input
One integer \(n\).
Output
\(2^n\) lines, the bit strings in Gray order. Any valid list is accepted.
Limits
\(1 \le n \le 16\)
Sample
\(n = 2\) → 00 01 11 10
Breakdown
  1. State it exactly: list \(g_0, \dots, g_{2^n - 1}\), every \(n\)-bit string once, with \[ d(g_i, g_{i+1}) = 1 \quad \text{for all } 0 \le i \lt 2^n - 1, \] where \(d\) counts the positions where two strings differ.
  2. Build \(G_n\) from \(G_{n-1}\): put \(0\) in front of each string, then put \(1\) in front of each string of the reversed list: \[ G_1 = (0, 1), \qquad G_n = 0\,G_{n-1} \;\big\|\; 1\,\overline{G_{n-1}} \] where \(\overline{G}\) means \(G\) in reverse order and \(\|\) means "followed by".
  3. Inside each half, the first bit is fixed, so neighbours still differ in one bit. At the join, both strings come from the same last string of \(G_{n-1}\), so they differ only in the first bit.
Key observations
  1. Take a valid list for \(n - 1\). Put 0 in front of every entry; then put 1 in front of the same list reversed.
  2. Inside each half the first bit is constant, so neighbours still differ in one bit. The \(n - 1\) property carries over.
  3. At the join, the two entries are the last string of the first half and the first string of the reversed half. Both come from the same \((n-1)\)-bit string, so they differ only in the first bit. That is why the second half is reversed.
  4. The base case {"0", "1"} is \(n = 1\), so the loop starts at \(i = 2\).
Brute force → why it dies
naiveBacktrack over the \(2^n\) strings, at each step trying every unused string that differs in one bit.
costExponential with backtracking, plus a visited set of size \(2^n\).
dies at\(n = 16\) gives \(65536\) strings; the search might survive but is pointless.
thereforeThe reflect-and-prefix rule builds the list directly in \(O(n \cdot 2^n)\), with no search.
Diagram
Implementation

Iterative rather than recursive: v holds the (i−1)-bit list and is rebuilt into temp each round. The second loop runs downwards, which is the reflection.

Tower of Hanoi

\(O(2^{n})\)
The ask

Question. There are three stacks and \(n\) disks of different sizes, all on stack 1, smallest on top. Move all disks to stack 3. Each move takes the top disk of one stack and puts it on another, and a larger disk may never be placed on a smaller one. Use the minimum number of moves and print them.

Input
One integer \(n\).
Output
The number of moves \(k\), then \(k\) lines a b (move the top disk of stack \(a\) to stack \(b\)).
Limits
\(1 \le n \le 16\)
Sample
\(n = 2\) → 3, then 1 2, 1 3, 2 3
Breakdown
  1. The largest disk can only move when the other \(n - 1\) disks are all on the third stack. So any solution has three parts: \[ \text{move } n{-}1 \text{ from} \to \text{spare}, \quad \text{move disk } n \text{ from} \to \text{to}, \quad \text{move } n{-}1 \text{ spare} \to \text{to} \]
  2. Count the moves, with \(T(n)\) the minimum for \(n\) disks: \[ T(1) = 1, \qquad T(n) = 2\,T(n-1) + 1 \]
  3. Add \(1\) to both sides: \(T(n) + 1 = 2\,(T(n-1) + 1)\). So \(T(n) + 1\) doubles each step, starting from \(2\): \[ T(n) = 2^n - 1 \]
  4. Simplest form: the recursion \(\text{hanoi}(n, a, b, c)\) = \(\text{hanoi}(n{-}1, a, c, b)\), print \(a \to c\), \(\text{hanoi}(n{-}1, b, a, c)\). Sample: \(T(2) = 3\).
Key observations
  1. The bottom disk can only move once the other \(n - 1\) are all on the spare stack. That one fact forces the whole recursion.
  2. So: move \(n - 1\) from → spare (using "to" as the helper), move disk \(n\) from → to, move \(n - 1\) spare → to (using "from" as the helper).
  3. The roles of the three stacks change at each call. Getting the argument order right in the two recursive calls is the problem.
  4. \(T(n) = 2T(n-1) + 1 = 2^n - 1\), and that is optimal, so nothing needs minimising. Just print.
Brute force → why it dies
naiveBFS over board states to find the shortest path to the goal.
cost\(3^n\) states, about \(4.3\cdot 10^7\) at \(n = 16\), each with a key for the whole board.
dies atMemory, well before time.
thereforeThe optimum is known exactly; print it directly in \(O(2^n)\), which is the size of the output.
Diagram
Implementation

Moves are collected into a global vector<pll> because the count must be printed before them. Parameter order is (nod, from, aux, to).

3 · Constructive answers

A feasibility question with a witness attached. The constraints rule out search entirely, so the work is finding the exact condition, then writing down one example that meets it. If the condition is right, the construction is usually three lines.

Coin Piles

\(O(1)\)
The ask

Question. There are two coin piles with \(a\) and \(b\) coins. In one move you either remove 1 coin from the left pile and 2 from the right, or 2 from the left and 1 from the right. Can you empty both piles? Answer \(t\) test cases.

Input
\(t\), then \(t\) lines \(a\ b\).
Output
For each test, YES or NO.
Limits
\(1 \le t \le 10^5,\ \ 0 \le a, b \le 10^9\)
Sample
(2,1) → YES, (2,2) → NO, (3,3) → YES
Breakdown
  1. Let \(x\) be the number of (1 left, 2 right) moves and \(y\) the number of (2 left, 1 right) moves. Emptying both piles means: \[ x + 2y = a, \qquad 2x + y = b, \qquad x, y \ge 0 \text{ integers} \]
  2. Solve the two equations: \[ x = \frac{2b - a}{3}, \qquad y = \frac{2a - b}{3} \]
  3. Integer: adding the equations gives \(3(x + y) = a + b\), so \(3 \mid (a + b)\), and then both numerators are multiples of \(3\). Non-negative: \(2b \ge a\) and \(2a \ge b\).
  4. Simplest form: \[ \text{YES} \iff (a + b) \bmod 3 = 0 \ \text{ and } \ 2 \min(a, b) \ge \max(a, b) \]
Key observations
  1. Every move removes exactly \(3\) coins, so \((a + b) \bmod 3 = 0\) is necessary.
  2. Solving the system gives \(x = (2b - a)/3\) and \(y = (2a - b)/3\). Both must be \(\ge 0\), which is exactly \(2 \min(a, b) \ge \max(a, b)\).
  3. With divisibility by \(3\), that inequality is also enough. The two conditions together are the full answer.
  4. \(a = b = 0\) passes both and is correct (zero moves).
Brute force → why it dies
naiveTry every count of one move type, or BFS over states \((a, b)\).
cost\(O(a)\) per test at best, \(O(a \cdot b)\) for BFS.
dies at\(a, b \le 10^9\) with \(t \le 10^5\) gives up to \(10^{14}\) steps.
thereforeSolve the \(2 \times 2\) system once, on paper. Both checks are \(O(1)\).
Implementation

One if. The whole derivation lives in the condition.

Raab Game I

\(O(n)\)
The ask

Question. Two players each have cards \(1, 2, \dots, n\). In each round both put down one card; the higher card scores a point, equal cards score nothing. After all \(n\) rounds, player 1 has \(a\) points and player 2 has \(b\). Decide whether this is possible, and if so print one game: the order in which each player played their cards. Answer \(t\) test cases.

Input
\(t\), then \(t\) lines \(n\ a\ b\).
Output
NO, or YES followed by two lines: player 1's cards and player 2's cards, round by round.
Limits
\(1 \le t \le 1000,\ \ 1 \le n \le 100,\ \ 0 \le a, b \le n\)
Sample
\((4,1,2)\) → YES; \((2,0,1)\) → NO; \((3,0,0)\) → YES; \((2,1,1)\) → YES; \((4,4,1)\) → NO
Breakdown
  1. With \(p_i, q_i\) the cards of round \(i\), state it exactly: \[ \#\{ i : p_i \gt q_i \} = a, \qquad \#\{ i : q_i \gt p_i \} = b \]
  2. Each round gives at most one point, so \(a + b \le n\).
  3. Both players hold the same cards, so \(\sum_i p_i = \sum_i q_i\). If \(a \gt 0\) and \(b = 0\), player 1 is never lower and sometimes higher, so \(\sum p_i \gt \sum q_i\), a contradiction. The same holds with the roles swapped: \[ (a = 0) \iff (b = 0) \]
  4. Simplest form: otherwise build it. Let \(m = a + b\). Rounds \(i = 1..b\): \(p = i,\ q = a + i\) (player 2 wins). Rounds \(j = 1..a\): \(p = b + j,\ q = j\) (player 1 wins). Rounds with cards \(m+1..n\) are ties. Each side uses every card \(1..n\) exactly once.
Key observations
  1. \(a + b \le n\), because each round gives at most one point.
  2. If exactly one of \(a, b\) is zero, it is impossible. Both hands have the same total, so a player who never loses and sometimes wins would have a larger total. Hence one-sided wins force all ties: \(a = b = 0\).
  3. Otherwise build it directly: leave \(n - a - b\) rounds as ties (same card on both sides), and arrange the rest as a cyclic shift.
  4. The construction pairs \(i \leftrightarrow a + i\) for the first \(b\) rounds (player 2 wins) and \(b + j \leftrightarrow j\) for the next \(a\) rounds (player 1 wins). Every card \(1..n\) appears exactly once on each side.
Brute force → why it dies
naiveTry every order of player 2's hand against player 1 playing \(1, 2, \dots, n\).
cost\(O(n!)\).
dies at\(n \le 100\), \(t \le 1000\). Instantly.
thereforeProve the two impossibility rules, then print one example in \(O(n)\).
Diagram
Implementation

One pass over i = 1…n choosing which of the three regions i falls in. The inline comments record the index arithmetic for each region.

Palindrome Reorder

\(O(n + 26)\)
The ask

Question. You are given a string of capital letters. Reorder its letters so that it becomes a palindrome (reads the same forwards and backwards). Print any such palindrome, or NO SOLUTION if none exists.

Input
One string of length \(n\), letters A–Z.
Output
A palindrome using exactly these letters, or NO SOLUTION.
Limits
\(1 \le n \le 10^6\)
Sample
AAAACACBA → AACABACAA
Breakdown
  1. A palindrome has \(s_i = s_{n-1-i}\). So positions pair up \(i \leftrightarrow n-1-i\), except the middle one when \(n\) is odd.
  2. Each pair uses two copies of one letter, so every letter count is even, except possibly the one letter in the middle: \[ \text{possible} \iff \#\{\, c : \text{cnt}_c \text{ is odd} \,\} \le 1 \]
  3. Simplest form: put the odd letter (if any) in the middle, then for each letter put \(\text{cnt}_c / 2\) copies on the left and the same on the right, mirrored. Sample: counts \(A{:}6,\ B{:}1,\ C{:}2\); only \(B\) is odd, so \(B\) goes in the middle.
Key observations
  1. A palindrome pairs position \(i\) with \(n - 1 - i\). Every letter except a possible middle one appears an even number of times.
  2. So the whole test is: at most one letter has an odd count.
  3. Construction: put the odd letter (if any) in the middle, then for each letter push half its copies to the front and half to the back. A deque does exactly that.
  4. Only the 26 counts matter; the original order is irrelevant.
Brute force → why it dies
naiveTry every rearrangement and test each one.
cost\(O(n! \cdot n)\).
dies at\(n \le 10^6\). Hopeless past \(n = 10\).
thereforeCount the 26 letters, check one parity condition, build it greedily in \(O(n)\).
Implementation

The deque is built outward-in: the odd letter is seeded first, then each pair is pushed to both ends at once, so the result is symmetric by construction.

import sys
from collections import deque
tok = iter(sys.stdin.read().split())

def solve():
    s = next(tok)
    n = len(s)
    v = [0] * 26
    for i in range(n):
        v[ord(s[i]) - ord('A')] += 1        # s[i] - 'A' -> ord() turns a char into its code
    odd, index = 0, -1
    for i in range(26):
        if v[i] % 2 == 1:
            odd += 1
            index = i
    if odd > 1:
        print("NO SOLUTION")
        return
    dq = deque()                            # deque<char>
    if index != -1:
        dq.append(chr(ord('A') + index))    # 'A' + index -> chr() turns a code back into a char
    v[index] -= 1                           # trap: index == -1 -> v[-1] is v[25] ('Z') in Python, not UB.
                                            # Harmless here: v[25] stays even-or-odd consistent for the loop below
    for i in range(26):
        while v[i] > 0:
            dq.appendleft(chr(ord('A') + i))    # push_front
            dq.append(chr(ord('A') + i))        # push_back
            v[i] -= 2
    print(''.join(dq))
