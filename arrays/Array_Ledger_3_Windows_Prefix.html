Windows & Prefix Sums

These problems all maintain a window or a prefix-sum table over a subarray, counting or maximizing under constraints that arise from element identity (distinct values) or arithmetic (target sum, divisibility). The two techniques — sliding window and prefix sums — are distinguished by whether the constraint is monotone in window size.

Recognition rules

The judgment calls that separate these problems from each other. Every rule must be demonstrated by at least two entries on this page.

1

Monotonicity dictates the tool. A sliding window works if adding an element always makes a valid state strictly worse (or closer to invalid). If negative values or arbitrary divisibility exist, monotonicity breaks, so Subarray Sums II and Subarray Divisibility must use prefix sums instead.

2

CSES anti-hash tests mean unordered_map on plain integer keys will TLE. Playlist, Distinct Subarrays, Distinct Values Subarrays II, and Subarray Sums II all rely on std::map (or sorting where possible) to prevent worst-case hash collisions.

3

Counting all valid subarrays starting at tail is exactly head - tail + 1. Distinct Subarrays and Distinct Values Subarrays II accumulate this value at every outer step, whereas Playlist simply takes the max of this length.

4

Negative prefix sums require modulo fixing. Subarray Divisibility forces the use of (pre[i] % n + n) % n to map negative remainders back to positive ones. Normal sum constraints just lookup pre[i] - x.

5

Tracking the exact number of distinct elements in a map requires strict cleanups. In Distinct Values Subarrays II, when freq[v[t]] hits 0, it must be erased so freq.size() stays accurate. Playlist does not need this because it only checks freq[x] == 0.

1 · Duplicate-free window

Maintaining a two-pointer window where elements are distinct or bounded by a distinct count. The constraint is monotone in window size, allowing a greedy slide.

Playlist

\(O(n \log n)\)
The ask

Question. You are given a playlist of \(n\) songs, where song \(i\) has id \(x_i\). What is the longest stretch of consecutive songs in which no id repeats?

Input
\(n\), then \(x_0, \dots, x_{n-1}\).
Output
One integer: the length of the longest such stretch.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le x_i \le 10^9\)
Sample
1 2 1 3 2 7 4 2 → 5 (the stretch 1 3 2 7 4)
Breakdown
  1. State it exactly: \[ \text{ans} = \max \big\{\, r - l + 1 \;:\; x_l, x_{l+1}, \dots, x_r \text{ are all different} \,\big\} \]
  2. If a window has no repeats, every smaller window inside it has none either. So for each left end \(l\), the good right ends are \(l, l+1, \dots, R(l)\) for some \(R(l)\).
  3. Moving \(l\) right only removes a song, so \(R(l)\) never moves left: \[ l \lt l' \;\Longrightarrow\; R(l) \le R(l') \]
  4. Simplest form: two pointers tail \(= l\) and head \(= R(l)\), both only moving right: \[ \text{ans} = \max_{l} \big( R(l) - l + 1 \big) \]
Key observations
  1. A window with no repeats stays repeat-free when it shrinks. So for each left end, the valid right ends form one unbroken range.
  2. Extend head while the next song is not in the window, that is while freq[a[head+1]] == 0.
  3. At each left end, record the length \(\text{head} - \text{tail} + 1\) and keep the maximum.
  4. Then move tail one step right and lower its song's count, which makes room to extend again.
Brute force → why it dies
naiveCheck every pair \((l, r)\) and test the window for repeats with a set.
cost\(O(n^3)\), or \(O(n^2)\) if the set grows with \(r\).
dies at\(n = 2\cdot 10^5\) gives about \(2\cdot 10^{10}\) windows.
thereforeTwo-pointer sliding window with a frequency map: each pointer moves at most \(n\) times, \(O(n \log n)\).

arrays/Playlist.cppverbatim
// Problem: Playlist
// Link: CSES 1141
// Pattern: two-pointer window (tail/head), freq map keeps window duplicate-free
// Time: O(n log n)  Space: O(n)
//
// map (not unordered_map) to sidestep CSES's anti-hash test on plain int keys.
//
// Longest contiguous subsequence with no repeated song id.
//
// Example:
//     1 2 1 3 2 7 4 2 -> 5   (window: 1 3 2 7 4)

#include <iostream>
#include <vector>
#include <map>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n;
    cin >> n;

    vector<int> a(n);
    for (auto& x : a) cin >> x;

    map<int, int> freq;
    int tail = 0, head = -1;
    long long ans = 0;

    while (tail < n) {
        while (head + 1 < n && freq[a[head + 1]] == 0) {
            head++;
            freq[a[head]]++;
        }
        ans = max(ans, (long long)(head - tail + 1));

        if (tail > head) {
            tail++;
            head = tail - 1;
        } else {
            freq[a[tail]]--;
            tail++;
        }
    }

    cout << ans << '\n';
    return 0;
}
import sys
tok = iter(sys.stdin.read().split())

def main():
    n = int(next(tok))

    a = [int(next(tok)) for _ in range(n)]   # for (auto& x : a) cin >> x

    freq = {}
    tail, head = 0, -1
    ans = 0

    while tail < n:
        while head + 1 < n and freq.get(a[head + 1], 0) == 0:
            head += 1
            freq[a[head]] = freq.get(a[head], 0) + 1
        ans = max(ans, head - tail + 1)

        if tail > head:
            tail += 1
            head = tail - 1
        else:
            freq[a[tail]] -= 1              # key surely exists here, so plain [] is safe
            tail += 1

    print(ans)

Recognize"longest contiguous subarray with distinct elements" → distinct-element window.

Distinct Subarrays

\(O(n \log n)\)
The ask

Question. You are given an array of \(n\) integers. Count the subarrays (contiguous blocks) in which every element is different.

Input
\(n\), then \(x_0, \dots, x_{n-1}\).
Output
One integer: the number of such subarrays.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le x_i \le 10^9\)
Sample
1 2 1 3 → 8
Breakdown
  1. State it exactly: \[ \text{ans} = \#\big\{\, (l, r) : l \le r,\ \ x_l, \dots, x_r \text{ all different} \,\big\} \]
  2. As in Playlist, for each left end \(l\) the good right ends are exactly \(l, \dots, R(l)\). That is \(R(l) - l + 1\) subarrays starting at \(l\).
  3. Count by left end. Each subarray is counted once, at its own left end: \[ \text{ans} = \sum_{l=0}^{n-1} \big( R(l) - l + 1 \big) \]
  4. Simplest form: the same two pointers as Playlist, but add the window length instead of taking a maximum. Sample: \(R = (1, 3, 3, 3)\), so \(2 + 3 + 2 + 1 = 8\).
Key observations
  1. Use the same repeat-free window as Playlist.
  2. If \([\text{tail}, \text{head}]\) is the longest repeat-free window starting at tail, then every subarray that starts at tail and ends anywhere up to head is also repeat-free.
  3. There are \(\text{head} - \text{tail} + 1\) of them. Adding this for every tail counts each valid subarray exactly once.
Brute force → why it dies
naiveList all subarrays and check each one for repeats.
cost\(O(n^3)\)
dies at\(n = 2\cdot 10^5\) gives \(\frac{n(n+1)}{2} \approx 2\cdot 10^{10}\) subarrays before any checking.
thereforeAdd up window lengths during one two-pointer scan: \(O(n \log n)\). The answer can reach \(2\cdot 10^{10}\), so use long long.
Diagram
Implementation

The core difference is ans += head - tail + 1.

Distinct Values Subarrays II

\(O(n \log n)\)
The ask

Question. You are given an array of \(n\) integers and a number \(k\). Count the subarrays that contain at most \(k\) different values.

Input
\(n,\ k\), then \(x_1, \dots, x_n\).
Output
One integer: the number of such subarrays.
Limits
\(1 \le k \le n \le 2\cdot 10^5,\ \ 1 \le x_i \le 10^9\)
Sample
\(k = 2\), 1 2 3 1 1 → 10
Breakdown
  1. State it exactly, where \(D(l, r)\) is the number of different values in \(x_l..x_r\): \[ \text{ans} = \#\{\, (l, r) : l \le r,\ D(l, r) \le k \,\} \]
  2. \(D\) can only grow when the window grows. So for each \(l\), the good right ends are \(l, \dots, R(l)\), and \(R(l)\) never moves left as \(l\) increases.
  3. Count by left end: \[ \text{ans} = \sum_{l} \big( R(l) - l + 1 \big) \]
  4. Simplest form: extend head while the next value keeps \(D \le k\): \[ x_{h+1} \text{ already in the window} \quad \text{or} \quad D \lt k \] Sample: window lengths \(2, 2, 3, 2, 1\) sum to \(10\).
Key observations
  1. Growing a window can only keep or increase the number of different values, so the valid right ends for each left end form one range.
  2. You can safely add \(x_{h+1}\) if freq.size() < k, or if it is already in the window.
  3. freq.size() is used as \(D\), so a key whose count drops to \(0\) must be erased, not just decremented.
Brute force → why it dies
naiveFor each \(l\), grow \(r\) with a set and stop when it holds more than \(k\) values.
cost\(O(n^2)\)
dies at\(n = 2\cdot 10^5\) (with \(k = n\)) gives about \(2\cdot 10^{10}\) steps.
thereforeTwo pointers with an exact count of different values: \(O(n \log n)\).

2 · Prefix + map

When constraints involve negative numbers or divisibility, monotonicity breaks down (the sum can go up and down). Two pointers die. Prefix sums mapped by frequency solve this by tracking what was seen.

Subarray Sums II

\(O(n \log n)\)
The ask

Question. You are given an array of \(n\) integers (they can be negative) and a target \(x\). Count the subarrays whose sum is exactly \(x\).

Input
\(n,\ x\), then \(a_1, \dots, a_n\).
Output
One integer: the number of such subarrays.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ -10^9 \le x, a_i \le 10^9\)
Sample
\(x = 7\), 2 -1 3 5 -2 → 2
Breakdown
  1. State it exactly: \[ \text{ans} = \#\Big\{\, (l, r) : 1 \le l \le r \le n,\ \ \sum_{k=l}^{r} a_k = x \,\Big\} \]
  2. Use prefix sums \(P_0 = 0,\ P_r = a_1 + \dots + a_r\). Then every block sum is a difference: \[ \sum_{k=l}^{r} a_k = P_r - P_{l-1} \]
  3. So the condition becomes a lookup of an earlier prefix: \[ P_r - P_{l-1} = x \iff P_{l-1} = P_r - x \]
  4. Simplest form: scan \(r = 1..n\), with \(c[v]\) = how many of \(P_0, \dots, P_{r-1}\) equal \(v\): \[ \text{ans} = \sum_{r=1}^{n} c\big[P_r - x\big], \qquad \text{then } c[P_r] \mathrel{+}= 1 \] Sample: \(P = (0, 2, 1, 4, 9, 7)\). At \(r = 4\), \(9 - 7 = 2\) was seen once; at \(r = 5\), \(7 - 7 = 0\) was seen once. Total \(2\).
Key observations
  1. With negative numbers, adding an element can make the sum go down. So the window sum is not monotone and two pointers do not work.
  2. A block \(a_l..a_r\) sums to \(x\) exactly when \(P_r - P_{l-1} = x\).
  3. Rearranged: \(P_{l-1} = P_r - x\). So just count how many earlier prefixes equal \(P_r - x\).
Brute force → why it dies
naiveTry every pair \((l, r)\) and add up the block.
cost\(O(n^2)\) with a running sum.
dies at\(n = 2\cdot 10^5\) gives about \(2\cdot 10^{10}\) pairs.
thereforeOne pass with a count map of prefix sums: \(O(n \log n)\). Prefix sums reach \(2\cdot 10^{14}\), so use long long.
Diagram
Implementation

Keep pre[0] = 0 to naturally handle prefixes starting at the first element.

Subarray Divisibility

\(O(n)\)
The ask

Question. You are given an array of \(n\) integers (they can be negative). Count the subarrays whose sum is divisible by \(n\).

Input
\(n\), then \(a_1, \dots, a_n\).
Output
One integer: the number of such subarrays.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ -10^9 \le a_i \le 10^9\)
Sample
3 1 2 7 4 → 1 (the block 1 2 7, sum \(10\))
Breakdown
  1. State it with prefix sums \(P_0 = 0,\ P_r = a_1 + \dots + a_r\): \[ \text{ans} = \#\big\{\, (l, r) : n \mid (P_r - P_{l-1}) \,\big\} \]
  2. A difference is divisible by \(n\) exactly when both numbers leave the same remainder: \[ n \mid (P_r - P_{l-1}) \iff P_r \equiv P_{l-1} \pmod n \]
  3. Group the \(n + 1\) prefixes \(P_0, \dots, P_n\) by remainder. Let \(c_t\) be how many have remainder \(t\). Any two in the same group give one valid subarray.
  4. Simplest form: \[ \text{ans} = \sum_{t=0}^{n-1} \binom{c_t}{2} = \sum_t \frac{c_t (c_t - 1)}{2} \] Sample: remainders of \(P\) are \(0, 3, 4, 1, 3, 2\). Only remainder \(3\) appears twice, so the answer is \(1\).
Key observations
  1. \(P_r - P_{l-1} \equiv 0 \pmod n\) is the same as \(P_r \equiv P_{l-1} \pmod n\).
  2. So any two prefixes with the same remainder mod \(n\) form a divisible subarray.
  3. In C++, % of a negative number is negative. Fix it with (pre[i] % n + n) % n so every remainder is in \([0, n-1]\).
Brute force → why it dies
naiveTry every pair \((l, r)\) and test the block sum.
cost\(O(n^2)\)
dies at\(n = 2\cdot 10^5\) gives about \(2\cdot 10^{10}\) pairs.
thereforeCount prefixes by remainder: \(O(n)\) with an array of size \(n\).
Diagram
Implementation

Since remainders are exactly 0..n-1, a direct vector<ll> freq(n) provides \(O(n)\) lookup without maps.

3 · Positive-only window

When elements are strictly positive, the sum is monotonically increasing with length, allowing us to safely slide a two-pointer window.

Subarray Sums I

\(O(n)\)
The ask

Question. You are given an array of \(n\) positive integers and a target \(x\). Count the subarrays whose sum is exactly \(x\).

Input
\(n,\ x\), then \(a_1, \dots, a_n\).
Output
One integer: the number of such subarrays.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le x, a_i \le 10^9\)
Sample
\(x = 7\), 2 4 1 2 7 → 3 (2 4 1, 4 1 2, 7)
Breakdown
  1. State it exactly, with \(S(l, r) = a_l + \dots + a_r\): \[ \text{ans} = \#\{\, (l, r) : S(l, r) = x \,\} \]
  2. All \(a_i \ge 1\), so the sum strictly grows as the window grows: \[ S(l, r+1) = S(l, r) + a_{r+1} \gt S(l, r) \] So for each \(l\) at most one \(r\) works: the last \(r\) with \(S(l, r) \le x\). Call it \(R(l)\).
  3. Removing \(a_l\) only lowers the sum, so \(R(l)\) never moves left as \(l\) grows.
  4. Simplest form, two pointers: \[ \text{ans} = \sum_{l} \big[\, S(l, R(l)) = x \,\big] \]
Key observations
  1. All elements are positive, so extending the window strictly increases the sum.
  2. Extend while \(\text{sum} + a_{h+1} \le x\).
  3. If the sum then equals \(x\) exactly, count it. Then drop the left element and continue.
Brute force → why it dies
naiveTry every pair \((l, r)\).
cost\(O(n^2)\)
dies at\(n = 2\cdot 10^5\) gives about \(2\cdot 10^{10}\) pairs.
