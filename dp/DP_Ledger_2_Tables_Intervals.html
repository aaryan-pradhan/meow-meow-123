Recognition rules

The judgment calls that separate these problems from each other.

1

Two sequences or a right/down grid → dp[i][j] over prefixes, three neighbours at most: Edit Distance, Longest Common Subsequence, Minimal Grid Path.

2

An action removes or cuts a contiguous piece and leaves smaller contiguous pieces → state is the range or the shape, smaller first: Removal Game, Rectangle Cutting, Mountain Range.

3

\(n \le 2\cdot 10^{5}\) rules out comparing every pair of earlier states; sort and binary-search the one transition that matters: Increasing Subsequence, Projects.

4

When one number is not enough to rank partial answers, store the ranking key itself and compare lexicographically: the pair (rides, weight) in Elevator Rides, the prefix string in Minimal Grid Path.

1 · Two-prefix table

State is a prefix of each of two sequences (or the two coordinates of a monotone grid path). Decide by looking at the last element on each side.

Edit Distance

\(O(n\cdot m)\)
The ask

Question. The edit distance between two strings is the fewest operations needed to turn one into the other, where one operation adds a character, removes a character, or replaces a character. Compute the edit distance between strings \(s\) and \(t\).

Input
String \(s\) (length \(n\)), then string \(t\) (length \(m\)), letters A–Z.
Output
One integer: the edit distance.
Limits
\(1 \le n, m \le 5000\)
Sample
LOVE, MOVIE → 2 (replace L with M, add I)
Breakdown
  1. Let \(dp[i][j]\) be the edit distance between the first \(i\) characters of \(s\) and the first \(j\) of \(t\). Turning a prefix into the empty string, or back, costs its length: \[ dp[i][0] = i, \qquad dp[0][j] = j \]
  2. Look at the last characters \(s_i\) and \(t_j\). If they are equal, they cost nothing: \[ s_i = t_j \;\Rightarrow\; dp[i][j] = dp[i-1][j-1] \]
  3. Otherwise the last operation was add \(t_j\), remove \(s_i\), or replace \(s_i\) by \(t_j\): \[ s_i \ne t_j \;\Rightarrow\; dp[i][j] = 1 + \min\big( \underbrace{dp[i][j-1]}_{\text{add}},\ \underbrace{dp[i-1][j]}_{\text{remove}},\ \underbrace{dp[i-1][j-1]}_{\text{replace}} \big) \]
  4. Simplest form: \(\text{ans} = dp[n][m]\). Row \(i\) reads only rows \(i\) and \(i - 1\), so two rows of length \(m + 1\) are enough.
Key observations
  1. Look at the last characters. If they are equal, they cost nothing: drop both.
  2. If not, the last operation was add (\(j - 1\)), remove (\(i - 1\)) or replace (both). Take the cheapest and add \(1\).
  3. Row \(i\) reads only rows \(i\) and \(i - 1\).
Brute force → why it dies
naiveRecurse on the three operations without memoisation.
cost\(O(3^{n+m})\)
dies at\(n, m = 5000\): hopeless. Even the full table is \(25\cdot 10^6\) ll values, about 200 MB.
thereforeState = pair of prefixes, two rolling rows: \(O(n \cdot m)\) time, \(O(m)\) memory.
Diagram
Implementation

dp[(i&1)] is the current row, dp[(i-1)&1] the previous one. The add term reads the current row at j-1, already written this pass. Answer sits in parity slot n & 1.

Longest Common Subsequence

\(O(n\cdot m)\)
The ask

Question. You are given two arrays \(a\) (length \(n\)) and \(b\) (length \(m\)). A subsequence keeps elements in order but may skip some. Find the length of the longest subsequence that appears in both arrays, and print one such subsequence.

Input
\(n,\ m\); then \(a_1..a_n\); then \(b_1..b_m\).
Output
The length, then one longest common subsequence.
Limits
\(1 \le n, m \le 1000,\ \ 1 \le a_i, b_j \le 10^9\)
Sample
3 1 3 2 7 4 8 2 and 6 5 1 2 3 4 → 3, 1 2 4
Breakdown
  1. Let \(dp[i][j]\) be the LCS length of \(a_1..a_i\) and \(b_1..b_j\), with \(dp[0][j] = dp[i][0] = 0\).
  2. If the last elements are equal, match them: \[ a_i = b_j \;\Rightarrow\; dp[i][j] = 1 + dp[i-1][j-1] \]
  3. If not, at least one of them is not used, so drop one: \[ a_i \ne b_j \;\Rightarrow\; dp[i][j] = \max\big( dp[i-1][j],\ dp[i][j-1] \big) \]
  4. Simplest form: the length is \(dp[n][m]\). To print one LCS, walk back from \((n, m)\) repeating the same choice: equal → take it and go to \((i-1, j-1)\); else move to the larger neighbour.
Key observations
  1. Equal last elements can always be matched with each other, so take them.
  2. If they differ, at least one of them is unused: drop \(a\)'s last or \(b\)'s last.
  3. Printing the sequence retraces the same choices from \((n, m)\), so the whole table must be kept.
Brute force → why it dies
naiveList the subsequences of \(a\) and test each against \(b\).
cost\(O(2^n \cdot m)\)
dies at\(n = 1000\) gives \(2^{1000}\).
thereforePrefix-pair table, \(10^6\) cells, then walk back for the sequence.
Diagram
Implementation

print recurses back from (n, m): on a match it recurses first and prints after, so output comes out in forward order. On a mismatch it follows the larger neighbour.

Minimal Grid Path

\(O(n^{3})\)
The ask

Question. You are given an \(n \times n\) grid with a letter in each square. Walk from the top-left square to the bottom-right square, moving only right or down. The letters you pass spell a string. Print the alphabetically smallest string you can get.

Input
\(n\), then \(n\) lines of \(n\) letters A–Z.
Output
The smallest string (length \(2n - 1\)).
Limits
\(1 \le n \le 3000\)
Sample
AACA / BABC / ABDA / AACA → AAABACA
Breakdown
  1. Let \(S(i, j)\) be the smallest string spelled by a path from \((0, 0)\) to \((i, j)\). Every such path has the same length \(i + j + 1\).
  2. The last step came from above or from the left. For strings of equal length, the smaller prefix gives the smaller whole string, so: \[ S(i, j) = \min\big( S(i-1, j),\ S(i, j-1) \big) + g[i][j] \]
  3. Simplest form (this code): store \(S\) per cell, \(O(n)\) per comparison, so \(O(n^3)\) total.
  4. Faster: walk diagonal by diagonal (\(i + j = d\)). Keep only the cells whose prefix equals the current minimum. The next letter is the smallest letter among their right/down neighbours, and only neighbours with that letter stay. That is \(O(n^2)\).
Key observations
  1. Every path to \((i, j)\) has the same length, so comparing prefixes alphabetically is fair.
  2. The best string to \((i, j)\) extends the smaller of the two best strings that lead into it.
  3. Storing whole strings makes each cell cost \(O(n)\).
Brute force → why it dies
naiveList every path's string.
cost\(O\big(\binom{2n}{n} \cdot n\big)\)
dies at\(n = 3000\): astronomically many paths.
thereforeBest prefix per cell (this code): \(O(n^3)\). The diagonal frontier described above keeps only the cells that tie for the minimum: \(O(n^2)\).
Diagram
Implementation

lexi treats "" as "no candidate" so the border branches can reuse it. For interior cells both neighbours exist and the smaller string is extended by grid[i][j].

Rectangle Cutting

\(O(a\cdot b\cdot (a+b))\)
The ask

Question. You have an \(a \times b\) rectangle and want to cut it into squares. Each move takes one rectangle and cuts it into two rectangles, straight across, so that all side lengths stay integers. What is the minimum number of moves?

Input
Two integers \(a,\ b\).
Output
One integer: the minimum number of cuts.
Limits
\(1 \le a, b \le 500\)
Sample
\(3 \times 5\) → 3
Breakdown
  1. Let \(dp[i][j]\) be the fewest cuts for an \(i \times j\) rectangle. A square needs none: \(dp[i][i] = 0\).
  2. The first cut is either horizontal at height \(k\) or vertical at width \(k\). Each makes two independent smaller rectangles: \[ dp[i][j] = 1 + \min\Big( \min_{1 \le k \lt i} \big(dp[k][j] + dp[i-k][j]\big),\ \ \min_{1 \le k \lt j} \big(dp[i][k] + dp[i][j-k]\big) \Big) \]
  3. Simplest form: both pieces are smaller, so fill \(i = 1..a\) and \(j = 1..b\) in increasing order. Answer \(dp[a][b]\). Sample: \(3 \times 5 \to 3 \times 3 + 3 \times 2\); \(3 \times 2 \to 2 \times 2 + 1 \times 2\); \(1 \times 2 \to 1 \times 1 + 1 \times 1\). That is \(3\) cuts.
Key observations
  1. A cut splits one rectangle into two independent rectangles.
  2. Squares are the only base case. There is no greedy rule for where to cut.
  3. Both pieces are strictly smaller, so fill by increasing \(i\), then \(j\).
Brute force → why it dies
naivePlain recursion over every cut.
costexponential
dies at\(a, b = 500\): the same sub-rectangle appears exponentially often.
thereforeStore one answer per shape: \(2.5\cdot 10^5\) shapes \(\times \le 1000\) cuts \(=\) \(2.5\cdot 10^8\) simple operations.
Diagram
Implementation

Two inner loops try every horizontal and every vertical cut. dp is indexed by exact dimensions, so no swap is needed; row i = 0 stays INF but is never read.

Removal Game

\(O(n^{2})\)
The ask

Question. There is a list of \(n\) numbers. Two players take turns; on each turn a player removes either the first or the last number and adds it to their score. Both play to maximise their own score. What is the first player's score?

Input
\(n\), then \(x_1, \dots, x_n\).
Output
One integer: the first player's final score.
Limits
\(1 \le n \le 5000,\ \ -10^9 \le x_i \le 10^9\)
Sample
4 5 1 3 → 8
Breakdown
  1. What remains is always a block \([l, r]\). Its length tells whose turn it is: \(n - (r - l + 1)\) numbers are gone, so it is player 1's turn iff that count is even.
  2. Let \(dp[l][r]\) be player 1's final score from block \([l, r]\). The total is fixed, so player 2 maximising their own score means minimising player 1's: \[ \text{P1's turn: } dp[l][r] = \max\big( x_l + dp[l+1][r],\ x_r + dp[l][r-1] \big) \] \[ \text{P2's turn: } dp[l][r] = \min\big( dp[l+1][r],\ dp[l][r-1] \big) \]
  3. Simplest form: fill blocks from length \(1\) up to \(n\). Answer \(dp[1][n]\). Sample: player 1 takes \(3\). Whichever end player 2 takes, \(5\) is then an end, and player 1 takes it: \(3 + 5 = 8\).
Key observations
  1. What is left is always a contiguous block \([l, r]\).

Mountain Range

\(O(n \log n)\)
The ask

Question. There are \(n\) mountains in a row with heights \(h_1, \dots, h_n\). You start on any mountain. You can glide from mountain \(a\) to mountain \(b\) if \(a\) is strictly taller than \(b\) and than every mountain between them. What is the largest number of mountains you can visit?

Input
\(n\), then \(h_1, \dots, h_n\).
Output
One integer: the maximum number of mountains on one route.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le h_i \le 10^9\)
Sample
20 15 17 35 25 40 12 19 13 12 → 5
Breakdown
  1. Let \(f(l, r)\) be the longest route that stays inside \([l, r]\). Let \(m\) be the position of the tallest mountain in \([l, r]\) (the leftmost if tied).
  2. No route can cross \(m\), because nothing glides over a mountain that tall. So routes live in \([l, m-1]\), in \([m+1, r]\), or start at \(m\).
  3. From \(m\) you can reach the tallest mountain of either side, since everything in between is lower. That adds \(1\), unless the side's tallest equals \(h_m\) (then it cannot be glided to): \[ \text{side}(S) = \begin{cases} 1 + f(S) & \text{if } \max_S h \lt h_m \\ f(S) & \text{if } \max_S h = h_m \end{cases}, \qquad \text{side}(\varnothing) = 1 \]
  4. Simplest form: \[ f(l, r) = \max\big( \text{side}([l, m-1]),\ \text{side}([m+1, r]) \big), \qquad \text{ans} = f(1, n) \] \(m\) is found with a max segment tree in \(O(\log n)\), and each position is the split point once.
Key observations
  1. From anywhere in \([l, r]\) you can never cross its tallest mountain \(m\).
  2. Starting at \(m\), you can reach the tallest mountain of either side, because everything between is lower.
  3. If that side's tallest equals \(h_m\), you cannot glide to it. That side is solved on its own, without the \(+1\).
Brute force → why it dies
naiveDP over every start, scanning the reachable targets.
cost\(O(n^2)\)
dies at\(n = 2\cdot 10^5\) gives \(4\cdot 10^{10}\).
thereforeSplit recursively at the block's maximum, found with a max segment tree: \(O(n \log n)\).
Diagram
Implementation

The segment tree node carries mx and its index. merge prefers the right index on ties. Empty queries return node() with mx = 0, safe because heights ≥ 1.

Increasing Subsequence

\(O(n \log n)\)
The ask

Question. You are given an array of \(n\) integers. Find the length of its longest increasing subsequence: the longest subsequence (order kept, elements may be skipped) in which every element is strictly larger than the one before.

Input
\(n\), then \(x_1, \dots, x_n\).
Output
One integer: the length of the longest increasing subsequence.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le x_i \le 10^9\)
Sample
7 3 5 3 6 2 9 8 → 4 (for example \(3, 5, 6, 9\))
Breakdown
  1. After reading some prefix, let \(\text{tails}[k]\) be the smallest last value of any increasing subsequence of length \(k + 1\). A smaller last value is always at least as good, since more later values can extend it.
  2. \(\text{tails}\) is strictly increasing: \(\text{tails}[0] \lt \text{tails}[1] \lt \dots\)
  3. A new value \(x\) extends the longest subsequence whose last value is \(\lt x\). So find the first position not below \(x\) and put \(x\) there: \[ p = \min \{\, k : \text{tails}[k] \ge x \,\}, \qquad \text{tails}[p] \leftarrow x \ \ (\text{append if no such } k) \]
  4. Simplest form: \(p\) is lower_bound(x), and the answer is the final length of \(\text{tails}\). Sample: tails goes \(7 \to 3 \to 3,5 \to 3,5 \to 3,5,6 \to 2,5,6 \to 2,5,6,9 \to 2,5,6,8\); length \(4\).
Key observations
  1. For each length, only the smallest possible ending value matters.
  2. tails is strictly increasing, so binary search finds where \(x\) fits.
  3. lower_bound (first \(\ge x\)) keeps it strict: an equal value replaces, it never extends.
Brute force → why it dies
naive\(dp[i] = 1 + \max dp[j]\) over \(j \lt i\) with \(x_j \lt x_i\).
cost\(O(n^2)\)
dies at\(n = 2\cdot 10^5\) gives \(4\cdot 10^{10}\).
thereforetails plus binary search: \(O(n \log n)\).
Diagram
Implementation

it == dp.end() means a[i] beats every tail and extends the longest run; otherwise it lowers an existing tail. dp is not an actual subsequence — only its size is meaningful.

Projects

\(O(n \log n)\)
The ask

Question. There are \(n\) projects. Project \(i\) runs from day \(a_i\) to day \(b_i\) (both included) and pays \(p_i\). You can work on at most one project per day. What is the maximum total money you can earn?

Input
\(n\), then \(n\) lines \(a_i\ b_i\ p_i\).
Output
One integer: the maximum total reward.
Limits
\(1 \le n \le 2\cdot 10^5,\ \ 1 \le a_i \le b_i \le 10^9,\ \ 1 \le p_i \le 10^9\)
Sample
(2,4,4) (3,6,6) (6,8,2) (5,7,3) → 7 (projects 1 and 4)
Breakdown
  1. Sort the projects by start day. Let \(dp[i]\) be the best total using only projects \(i, \dots, n-1\), with \(dp[n] = 0\).
  2. Skip project \(i\), or take it. Taking it rules out every later project that starts on or before day \(b_i\). The next usable one is: \[ \text{nxt}(i) = \min \{\, j \gt i : a_j \gt b_i \,\} \]
  3. So: \[ dp[i] = \max\big( dp[i+1],\ \ p_i + dp[\text{nxt}(i)] \big) \]
  4. Simplest form: starts are sorted, so \(\text{nxt}(i)\) is a binary search (upper_bound on \(b_i\)). Fill \(i = n-1\) down to \(0\); answer \(dp[0]\).
Key observations
  1. Sort by start. Taking project \(i\) jumps to the first project starting after \(b_i\); everything between overlaps it.
  2. Starts are sorted, so that jump target is a binary search.
  3. Days are inclusive: the next start must be \(\gt b_i\), not \(\ge b_i\).
Brute force → why it dies
naiveFor each project, scan all later ones for a compatible next project.
cost\(O(n^2)\)
dies at\(n = 2\cdot 10^5\) gives \(4\cdot 10^{10}\); days up to \(10^9\) rule out a table indexed by day.
thereforeSort, \(\text{nxt}(i)\) by binary search, 1-D DP: \(O(n \log n)\).
Diagram
Implementation

next[i] is computed by a hand-rolled binary search over \([i+1, n-1]\) with default n. The DP then runs right to left; dp[n] = 0 absorbs "no next project".

        (s, e), m = p[i]                    # unpack the nested tuple in one line
        lo, hi, ans = i + 1, n - 1, n
        while lo <= hi:
            mid = lo + (hi - lo) // 2
            (ms, me), mm = p[mid]
            if ms > e:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1
        next_[i] = ans
    dp = [0] * (n + 1)
    for i in range(n, -1, -1):
        if i == n:
            dp[i] = 0
            continue
        ans = dp[i + 1]
        ans = max(ans, p[i][1] + dp[next_[i]])
        dp[i] = ans
    print(dp[0])

4 · Bitmask subsets

n ≤ 20: the state is the set of items already placed.

Elevator Rides

\(O(2^{n}\cdot n)\)
The ask

Question. \(n\) people want to go up in one elevator. Person \(i\) weighs \(w_i\), and the elevator carries at most total weight \(x\) per ride. What is the minimum number of rides?

Input
\(n,\ x\), then \(w_1, \dots, w_n\).
Output
One integer: the minimum number of rides.
Limits
\(1 \le n \le 20,\ \ 1 \le x \le 10^9,\ \ 1 \le w_i \le x\)
Sample
\(x = 10\), weights 4 8 6 1 → 2 (\(\{4, 6\}\) and \(\{8, 1\}\))
Breakdown
  1. State = the set \(M\) of people already sent up. For it, store the best pair (rides used, weight in the last ride), compared first by rides, then by weight. A lighter last ride is never worse. \[ dp[\varnothing] = (1, 0) \]
  2. Choose the person \(i \in M\) who boarded last. With \((r, w) = dp[M \setminus \{i\}]\): \[ \text{add}(r, w, i) = \begin{cases} (r,\ w + w_i) & \text{if } w + w_i \le x \\ (r + 1,\ w_i) & \text{otherwise} \end{cases} \]
  3. Simplest form: \[ dp[M] = \min_{i \in M} \text{add}\big(dp[M \setminus \{i\}],\ i\big), \qquad \text{ans} = \text{rides of } dp[\{1..n\}] \] There are \(2^n \le 2^{20}\) sets and \(n\) choices each, about \(2\cdot 10^7\) steps.
Key observations
  1. \(n \le 20\) gives \(2^{20} \approx 10^6\) subsets. The state is "who has already ridden".
  2. For the same number of rides, a lighter last ride is never worse, so compare the pairs (rides, weight) in that order.
  3. Add person \(i\) last. If they fit: same rides, heavier last ride. If not: one more ride holding just \(w_i\).
Brute force → why it dies
naiveTry every order of people and fill rides greedily.
cost\(O(n! \cdot n)\)
dies at\(n = 20\): \(20! \approx 2.4\cdot 10^{18}\).
thereforeThe order only matters through the set used so far: \(2^n \cdot n \approx 2\cdot 10^7\).

Base dp[0] = {1, 0}: one empty open ride. Masks ascend, and mask ^ (1 << i) is always smaller, so it is ready. The tie-break cand.sc < ans.sc is the whole trick.
