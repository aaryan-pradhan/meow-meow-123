Recognition rules

The judgment calls that separate these problems from each other.

1

Order matters (2+3 ≠ 3+2) → sum outside, choices inside. Order doesn't → items outside. Coin Combinations I vs II are the same recurrence with the loops swapped.

2

Unlimited reuse → the take branch stays on the same item (Coin Combinations II) or the item index disappears entirely (Minimizing Coins, Coin Combinations I). Each item once → both branches advance (Book Shop, Money Sums, Two Sets II).

3

Counting problems seed the empty solution with 1 (Dice Combinations, Coin Combinations I/II); min-count problems seed it with 0 and every other state with INF (Minimizing Coins, Removing Digits).

4

If row i only reads row i±1, keep two rows indexed by i & 1 (Coin Combinations II, Book Shop, Array Description). For Book Shop it is the difference between 1.6 MB and 800 MB.

5

A constraint on neighbours (grid traps, \(|a[i]-a[i-1]| \le 1\)) becomes a 0 or a filtered candidate list, never a special case: Grid Paths I, Array Description.

1 · Last move over a sum

The state is the total so far. Split on the final step; the menu of steps is fixed (dice, coins) or derived from the state (digits). No item index.

Dice Combinations

\(O(6n)\)
The ask

Question. Count the number of ways to get a total of \(n\) by throwing a die one or more times. Each throw gives a number from \(1\) to \(6\). Order matters, so \(1+2\) and \(2+1\) are different. Print the count modulo \(10^9 + 7\).

Input
One integer \(n\).
Output
The number of ways \(\bmod\ (10^9 + 7)\).
Limits
\(1 \le n \le 10^6\)
Sample
\(n = 3\) → 4 (\(1{+}1{+}1,\ 1{+}2,\ 2{+}1,\ 3\))
Breakdown
  1. Let \(dp[i]\) be the number of throw sequences with total \(i\).
  2. Split on the last throw \(k\). Before it comes any sequence with total \(i - k\). Different \(k\) give different sequences, so the counts add: \[ dp[i] = \sum_{k=1}^{\min(6,\, i)} dp[i - k] \]
  3. The empty sequence has total \(0\), so \(dp[0] = 1\). This makes a single throw \(k\) count as \(dp[0] = 1\) with no special case.
  4. Simplest form: fill \(dp[1], \dots, dp[n]\) left to right, each from at most \(6\) earlier values, all \(\bmod\ 10^9 + 7\). Sample: \(dp = (1, 1, 2, 4)\) for \(i = 0..3\).
Key observations
  1. Order matters, so split on the last throw \(k\). What comes before it is any sequence with total \(i - k\).
  2. \(dp[0] = 1\) is the empty sequence. It makes \(dp[k]\) count the single throw \(k\) without a special case.
  3. Each value reads at most 6 earlier values, so one forward pass is enough.
Brute force → why it dies
naiveList every throw sequence recursively.
costexponential: the number of sequences itself grows like \(2^n\).
dies at\(n = 10^6\): listing them never finishes.
thereforeSequences with the same total behave the same from then on, so keep one number per total: \(O(6n)\).
Diagram
Implementation

Plain forward loop, i - k >= 0 guards the short prefixes. madd reduces both operands, so it is safe even though every term is already below MOD.

// Problem: Dice Combinations
// Link: https://cses.fi/problemset/task/1633
// Pattern: 1D bottom-up DP
// Time: O(n)  Space: O(n)
//
// Count the number of ways to construct sum `n` by throwing a dice one or
// more times, each throw producing an outcome between 1 and 6. Order
// matters (1+2 and 2+1 are distinct). Answer modulo 10^9+7.
//
// Constraints: 1 <= n <= 10^6

#include <iostream>
#include <vector>
using namespace std;

typedef long long ll;
const ll MOD = 1000000007;

ll madd(ll a, ll b) { ll s = a % MOD + b % MOD; return s % MOD; }

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n;
    cin >> n;

    vector<ll> dp(n + 1, 0);
    dp[0] = 1;
    for (int i = 1; i <= n; i++) {
        for (int k = 1; k <= 6; k++) {
            if (i - k >= 0) dp[i] = madd(dp[i], dp[i - k]);
        }
    }

    cout << dp[n] << '\n';
    return 0;
}

Coin Combinations I

\(O(n\cdot x)\)
The ask

Question. You have \(n\) coin values \(c_1, \dots, c_n\), each usable any number of times. Count the ordered ways to make the sum \(x\) (so \(2{+}2{+}5\), \(2{+}5{+}2\) and \(5{+}2{+}2\) are three different ways). Print the count modulo \(10^9 + 7\).

Input
\(n,\ x\), then \(c_1, \dots, c_n\).
Output
The number of ordered ways \(\bmod\ (10^9 + 7)\).
Limits
\(1 \le n \le 100,\ \ 1 \le x \le 10^6,\ \ 1 \le c_i \le 10^6\)
Sample
coins 2 3 5, \(x = 9\) → 8
Breakdown
  1. Let \(dp[s]\) be the number of ordered sequences of coins with sum \(s\).
  2. Split on the last coin \(c\). Before it comes any sequence with sum \(s - c\): \[ dp[0] = 1, \qquad dp[s] = \sum_{\substack{j = 1 \\ c_j \le s}}^{n} dp[s - c_j] \]
  3. Simplest form: loop over sums \(s = 1..x\) on the outside and coins on the inside, so every coin can be the last coin of every sum.
Key observations
  1. Order matters, so this is Dice Combinations with any set of faces: split on the last coin.
  2. Sum loop outside, coin loop inside. Every coin is allowed as the last step of every sum, so \(2{+}3\) and \(3{+}2\) are both counted.
  3. The base is \(dp[0] = 1\), not \(0\).
Brute force → why it dies
naiveList sequences recursively.
costexponential
dies at\(x = 10^6\), \(n = 100\): the answer is astronomically large, so listing never ends.
thereforeOne count per sum: \(O(n \cdot x) \approx 10^8\) simple additions, which passes.
Diagram
Implementation

Identical skeleton to Minimizing Coins: min(...)+1 becomes madd. madd uses a conditional subtract since both inputs are already reduced.

Minimizing Coins

\(O(n\cdot x)\)
The ask

Question. You have \(n\) coin values \(c_1, \dots, c_n\), each usable any number of times. Make the sum \(x\) using as few coins as possible. Print that number, or \(-1\) if \(x\) cannot be made.

Input
\(n,\ x\), then \(c_1, \dots, c_n\).
Output
The minimum number of coins, or -1.
Limits
\(1 \le n \le 100,\ \ 1 \le x \le 10^6,\ \ 1 \le c_i \le 10^6\)
Sample
coins 1 5 7, \(x = 11\) → 3 (\(5 + 5 + 1\))
Breakdown
  1. Let \(dp[s]\) be the fewest coins with sum \(s\), or \(\infty\) if \(s\) cannot be made.
  2. The last coin is some \(c_j \le s\). The rest must be an optimal way to make \(s - c_j\): \[ dp[0] = 0, \qquad dp[s] = 1 + \min_{c_j \le s} dp[s - c_j] \]
  3. Coins can be reused, so which coins were used before never matters. The state is only the sum.
  4. Simplest form: fill \(dp[1..x]\) in order; answer \(dp[x]\), printing \(-1\) if it is still \(\infty\). Sample: \(dp[11] = 1 + \min(dp[10], dp[6], dp[4]) = 1 + \min(2, 2, 4) = 3\).
Key observations
  1. Coins can be reused, so no coin is ever "used up" and the coin index carries no information. Drop it: the state is just the sum.
  2. The last coin is some \(c\); the rest is an optimal solution for \(s - c\).
  3. Sums that cannot be made must stay that way: INF + 1 must never win a min.
Brute force → why it dies
naiveMemoised rec(i, left): take coin \(i\) (stay) or skip it (move on).
cost\(O(n \cdot x)\) states, recursion depth up to \(x\).
dies at\(x = 10^6\): a recursion \(10^6\) deep overflows the stack, and the \(i\) dimension adds \(10^8\) wasted states.
thereforeKeep only \(dp[s]\), try all coins per sum, bottom-up: \(O(n \cdot x)\) time, \(O(x)\) space.
Diagram
Implementation

dp[left - c] != INF is the sentinel guard; without it INF + 1 just becomes a bigger INF here, but the explicit check keeps the intent unambiguous. Output maps INF back to −1.

// Problem: Minimizing Coins
// Link: https://cses.fi/problemset/task/1634
// Pattern: 1D bottom-up DP, unbounded reuse (min over all coin values per sum)
// Time: O(n*x)  Space: O(x)
//
// Produce sum `x` from `n` coins (positive integer values, each reusable any
// number of times) using the minimum number of coins. Print -1 if
// impossible.
//
// Constraints: 1 <= n <= 100, 1 <= x <= 10^6, 1 <= c_i <= 10^6

#include <iostream>
#include <vector>
using namespace std;

const int INF = 1000000000;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n, x;
    cin >> n >> x;

    vector<int> coins(n);
    for (int i = 0; i < n; i++) cin >> coins[i];

    vector<int> dp(x + 1, INF);
    dp[0] = 0;
    for (int left = 1; left <= x; left++) {
        for (int c : coins) {
            if (c <= left && dp[left - c] != INF) {
                dp[left] = min(dp[left], dp[left - c] + 1);
            }
        }
    }

    cout << (dp[x] == INF ? -1 : dp[x]) << '\n';
    return 0;
}

Removing Digits

\(O(n \log n)\)
The ask

Question. You are given an integer \(n\). In one step you may subtract one of its digits from it. What is the minimum number of steps to reach \(0\)?

Input
One integer \(n\).
Output
The minimum number of steps.
Limits
\(1 \le n \le 10^6\)
Sample
\(27\) → 5 (\(27 \to 20 \to 18 \to 10 \to 9 \to 0\))
Breakdown
  1. Let \(dp[i]\) be the fewest steps from \(i\) to \(0\). From \(i\) you can move to \(i - d\) for any nonzero digit \(d\) of \(i\): \[ dp[0] = 0, \qquad dp[i] = 1 + \min_{\substack{d \in \text{digits}(i) \\ d \ne 0}} dp[i - d] \]
  2. Every step makes the number smaller, so \(dp[i]\) only needs smaller values. Fill \(i = 1..n\) in order.
  3. Simplest form: each \(i\) has at most \(7\) digits, so the whole table costs \(O(7n)\).
Key observations
  1. It is Minimizing Coins where the coins depend on the current value: the digits of \(i\).
  2. Every step strictly decreases \(i\), so filling from \(0\) upwards is a valid order.
  3. A nonzero digit \(d\) of \(i\) always satisfies \(d \le i\), so \(dp[i - d]\) is in range.
Brute force → why it dies
naiveRecursion over all digit choices from \(n\).
costexponential without memoisation.
dies at\(n = 10^6\): the same value is reached along a huge number of paths.
thereforeStore one answer per value: \(O(n \cdot \text{digits})\), at most 7 digits each.
Diagram
Implementation

temp peels digits with % 10; zero digits are skipped since subtracting 0 is not progress. dp starts at INF so the first digit always wins.

2 · Take / skip items

The state is (item index, budget). Each item is taken or skipped; whether "take" stays on the row or advances decides unbounded vs 0/1.

Coin Combinations II

\(O(n\cdot x)\)
The ask

Question. You have \(n\) coin values \(c_1, \dots, c_n\), each usable any number of times. Count the ways to make the sum \(x\) where order does not matter (\(2{+}2{+}5\), \(2{+}5{+}2\) and \(5{+}2{+}2\) are the same way). Print the count modulo \(10^9 + 7\).

Input
\(n,\ x\), then \(c_1, \dots, c_n\).
Output
The number of unordered ways \(\bmod\ (10^9 + 7)\).
Limits
\(1 \le n \le 100,\ \ 1 \le x \le 10^6,\ \ 1 \le c_i \le 10^6\)
Sample
coins 2 3 5, \(x = 9\) → 3 (\(2{+}2{+}5,\ 3{+}3{+}3,\ 2{+}2{+}2{+}3\))
Breakdown
  1. To count each multiset once, decide the coins in a fixed order: first how many of coin \(i\), then move to coin \(i + 1\). Let \(dp[i][s]\) be the number of ways to make \(s\) using only coins \(i, \dots, n-1\).
  2. Either take one more coin \(i\) (stay on coin \(i\), since it can be taken again) or move on to coin \(i + 1\): \[ dp[i][s] = \underbrace{dp[i][s - c_i]}_{\text{take one more } c_i} + \underbrace{dp[i+1][s]}_{\text{done with } c_i} \]
  3. Base cases: with no coins left, only sum \(0\) can be made: \[ dp[n][0] = 1, \qquad dp[n][s] = 0 \ \ (s \gt 0), \qquad \text{ans} = dp[0][x] \]
  4. Simplest form: row \(i\) reads only rows \(i\) and \(i + 1\), so two rows of length \(x + 1\) are enough.
Key observations
  1. Order does not matter, so fix one canonical order: decide coin \(i\) completely, then move on. Each multiset is then built exactly once.
  2. Taking coin \(i\) stays on row \(i\) (it may be taken again). Skipping moves to row \(i + 1\).
  3. Row \(i\) reads only rows \(i\) and \(i + 1\), so two rows are enough.
Brute force → why it dies
naiveReuse Coin Combinations I (sum loop outside).
cost\(O(n \cdot x)\), but the wrong answer.
dies atIt counts \(2{+}3\) and \(3{+}2\) separately: the sample gives \(8\), not \(3\).
thereforePut the coin index on the outside, with two rolling rows: \(O(n \cdot x)\) time, \(O(x)\) memory.
Diagram
Implementation

dp[i&1] is the row being written, dp[(i+1)&1] the row below. The take term reads dp[i&1][left - coins[i]] — the current row, already filled because left ascends. That same-row read is what "reusable" means.

def main():

    coins = [int(next(tok)) for _ in range(n)]

Book Shop

\(O(n\cdot x)\)
The ask

Question. A shop sells \(n\) books. Book \(i\) costs \(h_i\) and has \(s_i\) pages. You can spend at most \(x\) in total and buy each book at most once. What is the maximum number of pages you can buy?

Input
\(n,\ x\); then \(h_1, \dots, h_n\); then \(s_1, \dots, s_n\).
Output
One integer: the maximum total pages.
Limits
\(1 \le n \le 1000,\ \ 1 \le x \le 10^5,\ \ 1 \le h_i, s_i \le 1000\)
Sample
\(x = 10\), prices 4 8 5 3, pages 5 12 8 1 → 13 (books 1 and 3)
Breakdown
  1. State it exactly: \[ \max_{T \subseteq \{1..n\}} \sum_{i \in T} s_i \quad \text{subject to} \quad \sum_{i \in T} h_i \le x \]
  2. Let \(dp[i][b]\) be the most pages from books \(i, \dots, n-1\) with budget \(b\) left. Each book is skip or buy, and both move on to the next book: \[ dp[i][b] = \max\Big( dp[i+1][b],\ \ dp[i+1][b - h_i] + s_i \ \ \big(\text{if } h_i \le b\big) \Big) \]
  3. Base case: with no books left you get \(0\) pages, whatever money is left: \(dp[n][b] = 0\) for every \(b\).
  4. Simplest form: \(\text{ans} = dp[0][x]\), computed with two rolling rows of length \(x + 1\).
Key observations
  1. Each book can be bought once, so both choices (buy, skip) move to row \(i + 1\).
  2. The budget is "\(\le x\)", not "\(= x\)", so the base row is \(0\) for every leftover budget, not only for \(0\).
  3. Only rows \(i\) and \(i + 1\) are in use, so keep two rows and switch by parity.
Brute force → why it dies
naiveTry all \(2^n\) subsets.
cost\(O(2^n \cdot n)\)
dies at\(n = 1000\) gives \(2^{1000}\) subsets.
thereforeState = (next book, budget left): \(10^3 \cdot 10^5 =\) \(10^8\) cells; rolling rows keep memory at \(O(x)\).
Diagram
Implementation

Outer loop runs i from n down, so dp[0][x] is the answer. Inside i == n the left >= 0 test is always true — the -INF branch is dead code, the affordability check lives in the else branch.

Money Sums

\(O(n \cdot \sum x)\)
The ask

Question. You have \(n\) coins with values \(x_1, \dots, x_n\) (each coin used at most once). Find every sum you can make using one or more of the coins. Print how many there are, then the sums in increasing order.

Input
\(n\), then \(x_1, \dots, x_n\).
Output
The count \(k\), then the \(k\) sums in increasing order.
Limits
\(1 \le n \le 100,\ \ 1 \le x_i \le 1000\)
Sample
4 2 5 2 → 9, then 2 4 5 6 7 8 9 11 13
Breakdown
  1. State it exactly: \[ \Big\{\, \sum_{i \in T} x_i \;:\; \varnothing \ne T \subseteq \{1, \dots, n\} \,\Big\} \]
  2. Let \(R_i(s)\) be true if some subset of coins \(i, \dots, n-1\) sums to \(s\). Each coin is skipped or used: \[ R_n(s) = [s = 0], \qquad R_i(s) = R_{i+1}(s) \ \lor\ R_{i+1}(s - x_i) \]
  3. Every sum is at most \(n \cdot \max x_i = 100 \cdot 1000 = 10^5\), so a table of width \(10^5 + 1\) covers everything.
  4. Simplest form: print every \(s \ge 1\) with \(R_0(s)\) true.
Key observations
  1. This is knapsack with a yes/no value: "can sum \(s\) be made from coins \(i..n-1\)?"
  2. A sum can never exceed \(n \cdot \max x = 100 \cdot 1000\), so a fixed bound of \(10^5\) columns is exact.
  3. Repeated coin values need no special handling: the set of reachable sums absorbs repeats.
Brute force → why it dies
naiveList all subsets and put their sums in a set.
cost\(O(2^n)\)
dies at\(n = 100\) gives \(2^{100}\).
thereforeDistinct sums are \(\le 10^5\), so use \((n + 1) \times 10^5\) booleans: \(10^7\) work.
Diagram
Implementation

vector<bool> keeps the \(10^{7}\) cells at ~1.2 MB. Column 0 is true in every row (the empty subset), and the output loop starts at s = 1 to exclude it.

Two Sets II

\(O(n^{3})\)
The ask

Question. Count the ways to split the numbers \(1, 2, \dots, n\) into two sets with equal sums. Print the count modulo \(10^9 + 7\).

Input
One integer \(n\).
Output
The number of ways \(\bmod\ (10^9 + 7)\).
Limits
\(1 \le n \le 500\)
Sample
\(n = 7\) → 4 (for example \(\{1,3,4,6\}\) and \(\{2,5,7\}\))
Breakdown
  1. The total is \(T = 1 + 2 + \dots + n = \frac{n(n+1)}{2}\). Each set must sum to \(T/2\), so if \(T\) is odd the answer is \(0\).
  2. A split is fixed by choosing one set \(A\). Count subsets with sum \(T/2\), using \(dp[i][s]\) = number of subsets of \(\{1..i\}\) with sum \(s\): \[ dp[0][0] = 1, \qquad dp[i][s] = dp[i-1][s] + dp[i-1][s - i] \]
  3. Each split \(\{A, B\}\) is counted twice, once as \(A\) and once as \(B\). So divide by \(2\). Modulo a prime, dividing by \(2\) means multiplying by the inverse of \(2\): \[ \text{ans} = dp[n][T/2] \cdot 2^{-1} \bmod p, \qquad 2^{-1} \equiv \frac{p+1}{2} = 500000004 \pmod{p} \]
  4. Simplest form: \(T/2 \le 62625\), so the table is about \(500 \times 62625 \approx 3\cdot 10^7\) cells.
Key observations
  1. If \(T\) is odd, the answer is \(0\) immediately.
  2. A split is fixed by choosing \(A\), so count subsets with sum \(T/2\).
  3. Each split is counted twice (\(A\) and its complement), so divide by \(2\). Modulo \(p\) that means multiplying by \(2^{-1}\).
Brute force → why it dies
naiveList all subsets of \(1..n\).
cost\(O(2^n)\)
dies at\(n = 500\) gives \(2^{500}\).
thereforeSubset-sum counting up to \(T/2 \le 62625\): \(n \cdot T/2 \approx 3\cdot 10^7\).
Diagram
Implementation

Forward table: row i uses numbers 1..i and reads row \(i-1\). The inner loop variable sum shadows the outer total, harmlessly since the total is no longer used.

Grid Paths I

\(O(n^{2})\)
The ask

Question. You are given an \(n \times n\) grid in which some squares are traps. Count the paths from the top-left square to the bottom-right square that move only right or down and never step on a trap. Print the count modulo \(10^9 + 7\).

Input
\(n\), then \(n\) lines of \(n\) characters: . empty, * trap.
Output
The number of paths \(\bmod\ (10^9 + 7)\).
Limits
\(1 \le n \le 1000\)
Sample
the \(4 \times 4\) grid in the file → 3
Breakdown
  1. Let \(dp[i][j]\) be the number of paths from cell \((i, j)\) to the bottom-right cell.
  2. A path from \((i, j)\) starts by going down or right. These are different paths, so the counts add. A trap has no paths: \[ dp[i][j] = \begin{cases} 0 & \text{if } (i, j) \text{ is a trap} \\ dp[i+1][j] + dp[i][j+1] & \text{otherwise} \end{cases} \]
  3. Base case: \(dp[n-1][n-1] = 1\) if it is not a trap. Cells outside the grid count as \(0\).
  4. Simplest form: fill rows bottom to top and columns right to left, so both neighbours are ready. Answer \(dp[0][0]\).
Key observations
  1. A path from \((i, j)\) starts with either down or right. The two cases do not overlap, so the counts add.
  2. A trap has \(0\) paths. That one rule also covers a trapped start or end cell.
  3. Filling bottom-up, right to left, makes sure both neighbours are already computed.
Brute force → why it dies
naiveDFS over every right/down path.
cost\(O\big(\binom{2n}{n}\big)\)
dies at\(n = 1000\): \(\binom{2000}{1000} \approx 10^{600}\) paths.
thereforeOne count per cell: \(O(n^2) = 10^6\).
Diagram
Implementation

The '*' test comes before the destination test, so a trapped destination correctly yields 0 everywhere. down/right default to 0 at the borders.

Array Description

\(O(n\cdot m)\)
The ask

Question. An array has \(n\) values, each between \(1\) and \(m\), and any two neighbouring values differ by at most \(1\). You are given the array with some values unknown (written as \(0\)). Count the arrays that match. Print the count modulo \(10^9 + 7\).

Input
\(n,\ m\), then \(x_1, \dots, x_n\) (\(0\) = unknown).
Output
The number of matching arrays \(\bmod\ (10^9 + 7)\).
Limits
\(1 \le n \le 10^5,\ \ 1 \le m \le 100,\ \ 0 \le x_i \le m\)
Sample
\(m = 5\), 2 0 2 → 3 (\([2,1,2], [2,2,2], [2,3,2]\))
Breakdown
  1. Value \(v\) is allowed at position \(i\) if \(1 \le v \le m\) and either \(x_i = 0\) or \(x_i = v\).
  2. Let \(dp[i][p]\) be the number of ways to fill positions \(i, \dots, n-1\) when position \(i - 1\) holds \(p\). Only the previous value matters for the future: \[ dp[i][p] = \sum_{\substack{v \text{ allowed at } i \\ |v - p| \le 1}} dp[i+1][v], \qquad dp[n][p] = 1 \]
  3. Position \(0\) has no previous value, so: \[ \text{ans} = \sum_{v \text{ allowed at } 0} dp[1][v] \]
  4. Simplest form: each state tries at most \(3\) values \(p - 1, p, p + 1\), so about \(3 n m \approx 3\cdot 10^7\) steps with two rolling rows.
Key observations
  1. Position \(i\) needs only the previous value from the past, and there are \(m \le 100\) options for it.
  2. A known \(x_i\) gives one candidate, valid or not, so almost no work.
  3. An unknown \(x_i\) tries \(p - 1, p, p + 1\), kept inside \([1, m]\).
Brute force → why it dies
naiveTry every value for every unknown.
cost\(O(m^k)\) for \(k\) unknowns.
dies at\(n = 10^5\), \(m = 100\): up to \(100^{100000}\).
thereforeState = (position, previous value): \(3 \cdot n \cdot m \approx 3\cdot 10^7\), two rolling rows.
Diagram
Implementation

Rows are indexed by i & 1, filled from i = n down. The final answer reads dp[1][j] when a[0] is free — that 1 is the parity slot holding row i = 1, not "value 1".

            if i == n:
                dp[i & 1][prev] = 1
                continue
            ans = 0
            if arr[i] != 0:
                if abs(arr[i] - prev) <= 1: ans = dp[(i + 1) & 1][arr[i]]
                else: ans = 0
            else:
                for j in range(prev - 1, prev + 2):     # j = prev-1 .. prev+1
                    if j >= 1 and j <= m: ans = madd(ans, dp[(i + 1) & 1][j])
            dp[i & 1][prev] = ans
    if arr[0] != 0:
        print(dp[0][arr[0]])
    else:
        ans = 0
        for j in range(1, m + 1):
            ans = madd(ans, dp[1][j])
        print(ans)
