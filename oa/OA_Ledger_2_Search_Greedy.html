Recognition rules

The judgment calls that separate these problems from each other. Every rule is demonstrated by at least two entries on this page.

1

Make something monotone, then binary search. In GPU Idle and Servers & Receivers, feasibility is monotone in the answer. In First Greater Index, the prefix max makes the array sorted so upper_bound works.

2

If every candidate can be listed ahead of time, put them in a map and answer each question with a lookup. 4Sum stores pair sums, Fibonacci Index stores all ≈ 75 terms up to \(10^{15}\), and Second Most Frequent stores counts.

3

When order decides the value, sort once and read the answer off the order. Maximum Profit opens categories cheapest-first. Repeated String Cover outputs its letters sorted (the smallest string). Second Most Frequent sorts (freq, value) pairs.

4

Watch integer division. Repeated String Cover needs a true ceiling, Servers & Receivers needs \(\lfloor \text{slack}/2\rfloor\), and Trapezium Area needs p % q == 0 before trusting p / q.

1 · Binary search on something monotone

Either a yes/no check that stays yes once the answer is big enough, or an array made sorted by a running max. Both turn a linear search into log steps.

Minimize GPU Idle Count

OA · \(O(n \log n)\)
The ask

Question. A string \(s\) of length \(n\) uses only a and b. Its "idle count" is the length of its longest block of equal characters. You may flip at most \(k\) characters (a ↔ b). What is the smallest idle count you can reach?

Input
The string \(s\) and the number \(k\) (switchCount).
Output
The minimum possible longest block.
Limits
Not given in the file.
Sample
aabbbaaaa, \(k = 2\) → 2 (e.g. aabababaa)
Breakdown
  1. Turn it into a yes/no question: \(\text{ok}(x)\) = "can every block be made \(\le x\) with at most \(k\) flips?" If it works for \(x\), it works for \(x + 1\), so binary search the smallest \(x \in [1, n]\).
  2. For \(x \ge 2\), blocks can be fixed separately. A block of length \(L\) is cut by flipping every \((x+1)\)-th character, which needs \[ \text{flips}(L) = \left\lfloor \frac{L}{x + 1} \right\rfloor, \qquad \text{ok}(x) \iff \sum_{\text{blocks}} \left\lfloor \frac{L}{x + 1} \right\rfloor \le k \] Sample, \(x = 2\): blocks \(2, 3, 4\) need \(0 + 1 + 1 = 2 \le 2\). Yes.
  3. \(x = 1\) means a fully alternating string, either abab… or baba…. The exact test compares against both: \[ \text{ok}(1) \iff \min\big( \#\{i : s_i \ne \texttt{abab}\ldots_i\},\ \#\{i : s_i \ne \texttt{baba}\ldots_i\} \big) \le k \]
  4. Simplest form: binary search with an \(O(n)\) check, \(O(n \log n)\) total.
Key observations
  1. If blocks \(\le x\) can be reached with \(k\) flips, then blocks \(\le x + 1\) can too. The test is monotone, so binary search \(x\) over \([1, n]\).
  2. Blocks are independent. A block of length \(L\) needs \(\lfloor L/(x+1) \rfloor\) flips to get under \(x + 1\).
  3. \(x = 1\) means a fully alternating string, so it gets a special case. Note the code's test there, \(k \ge n - 1\), is only a sufficient condition; the exact test counts mismatches against both alternating patterns (step 3).
Brute force → why it dies
naiveTry every \(x\) from \(1\) upward with a linear check.
cost\(O(n^2)\).
dies at\(n = 10^5\) gives \(10^{10}\).
thereforeBinary search on \(x\): \(O(n \log n)\).

Implementation

check(x) counts down a copy of the budget (switchCount = temp). After a flip it sets idle = 1 but keeps p = c, so the next equal character counts as continuing a run. s and temp are globals that check reads.

GotchaThe sample passes, but the check over-counts flips. It flips every x-th equal character instead of every (x+1)-th, and the x = 1 test asks for k ≥ n−1 instead of the cost of alternating. On aaaaa 1 it prints 3, but aabaa gives 2. On aaaa 2 it prints 2, but abab gives 1. A correct check spends ⌊L/(x+1)⌋ flips per run of length L, and for x = 1 uses min(mismatches against abab…, against baba…) ≤ k.
Recognize"minimise the maximum run / load with a limited number of edits" → binary search the maximum, with a greedy feasibility check.

Servers and Receivers

SDE OA · \(O(n \log \text{INF})\)
The ask

Question. There are \(n\) servers and \(m\) receivers. Receiver \(i\) prefers server \(a_i\), where serving it takes \(1\) second; serving it on any other server takes \(2\) seconds. All servers work at the same time, each serving one receiver at a time. What is the minimum time until every receiver is served?

Input
\(n,\ m\), then \(a_1, \dots, a_m\).
Output
One integer: the minimum total time.
Limits
Not given in the file.
Sample
Not given in the file.
Breakdown
  1. Let \(s_j\) be the number of receivers that prefer server \(j\). Fix a deadline \(T\).
  2. A server with \(s_j \gt T\) cannot finish its own receivers; \(s_j - T\) of them must move. A server with \(s_j \lt T\) has \(T - s_j\) spare seconds, enough for \(\lfloor (T - s_j)/2 \rfloor\) moved receivers: \[ \text{need}(T) = \sum_{s_j \gt T} (s_j - T), \qquad \text{spare}(T) = \sum_{s_j \lt T} \left\lfloor \frac{T - s_j}{2} \right\rfloor \]
  3. \(T\) works iff the spare room covers the overflow. A larger \(T\) only helps, so binary search the smallest: \[ \text{ans} = \min \{\, T : \text{need}(T) \le \text{spare}(T) \,\} \]
Key observations
  1. The load \(s_j\) is the number of receivers that prefer server \(j\).
  2. With deadline \(T\), an overloaded server must hand off \(s_j - T\) receivers. A server with spare time \(T - s_j\) can take \(\lfloor (T - s_j)/2 \rfloor\) of them.
  3. \(\text{ok}(T)\) is monotone in \(T\), so binary search for the smallest \(T\).
Brute force → why it dies
naiveTry \(T = 0, 1, 2, \dots\) up to \(2m\).
cost\(O(n \cdot m)\).
dies at\(n = m = 10^5\) gives \(10^{10}\).
thereforeBinary search on \(T\): \(O(n \log \text{INF})\), about \(60 n\).
Diagram
Implementation

s[a[i]]++ builds the loads. check sums the excess (mm) and the halved spare capacity (c). hi = INF (\(10^{18}\)) costs about 60 iterations, though hi = m would be enough.

Array First Greater Index

Eternal · \(O((|a|+|b|) \log |b|)\)
The ask

Question. You are given two arrays \(a\) and \(b\). For each \(a_i\), find the smallest 1-based index \(j\) with \(b_j \gt a_i\). Return all the indices, using \(-1\) when no such \(j\) exists.

Input
Arrays \(a\) and \(b\).
Output
One index (or -1) per element of \(a\).
Limits
Not given in the file.
Sample
Not given in the file.
Breakdown
  1. State it exactly: \[ \text{ans}_i = \min \{\, j : b_j \gt a_i \,\} \quad (\text{or } -1) \]
  2. Use the prefix maximum \(P_j = \max(b_1, \dots, b_j)\). Some \(b_{j'}\) with \(j' \le j\) beats \(a_i\) exactly when \(P_j\) does, so \[ \text{ans}_i = \min \{\, j : P_j \gt a_i \,\} \]
  3. Simplest form: \(P\) never decreases, so this is a binary search: upper_bound(P, a_i). If it reaches the end, nothing in \(b\) is larger: \(-1\).
Key observations
  1. "The first \(j\) with \(b_j \gt x\)" is the same as "the first \(j\) where \(\max(b_1..b_j) \gt x\)".
  2. The prefix max pre never decreases, so upper_bound(pre, x) finds that \(j\).
  3. If it reaches the end, nothing in \(b\) is larger, so the answer is \(-1\).
Brute force → why it dies
naiveScan \(b\) from the left for each \(a_i\).
cost\(O(|a| \cdot |b|)\).
dies at\(10^5\) each gives \(10^{10}\).
thereforePrefix max plus binary search: \(O((|a| + |b|) \log |b|)\).

vector<int> solveFirstGreaterIndex(vector<int>& a, vector<int>& b) {

    if (n == 0) return vector<int>(a.size(), -1);
    vector < ll > pre(n,0) ; 
    pre[0] = b[0] ; 
    for( ll i = 1 ; i < n ; i++)
    {
        pre[i] = max( pre[i-1]  , b[i] ) ; 

    }

        {
            ans.push_back(-1) ; 
        }
        else 
        {
            ans.push_back((it - pre.begin()) + 1 ) ; 
        }
    }
    return ans;
}

from bisect import bisect_right

def solveFirstGreaterIndex(a, b):
    n = len(b)
    if n == 0: return [-1] * len(a)        # vector<int>(a.size(), -1)
    pre = [0] * n
    pre[0] = b[0]
    for i in range(1, n):
        pre[i] = max(pre[i - 1], b[i])
    # pre stores the max from 0 to i
    ans = []
    for x in a:
        j = bisect_right(pre, x)            # upper_bound(pre.begin(), pre.end(), x) as an index
        # this returns the iterator to the first first element in pre that is bigger than a
        if j == n:                          # it == pre.end()
            ans.append(-1)
        else:
            ans.append(j + 1)               # (it - pre.begin()) + 1
    return ans

2 · Precompute into a map

The candidates can be listed ahead of time: pair sums, sequence terms, or counts. Store them once, and each question becomes a find.

4Sum

Accenture · \(O(n^{2} \log n)\)
The ask

Question. You are given an array of \(n\) integers and a target \(x\). Are there four values at distinct positions whose sum is \(x\)? Print YES or NO.

Input
\(n,\ x\), then \(a_1, \dots, a_n\).
Output
YES or NO.
Limits
\(1 \le n \le 1000,\ \ 1 \le x, a_i \le 10^9\)
Sample
\(x = 15\), 3 2 5 8 1 3 2 3 → YES
Breakdown
  1. State it exactly: \[ \exists\ i \lt j \lt k \lt l : \ a_i + a_j + a_k + a_l = x \]
  2. Split into a left pair and a right pair around a pivot index \(i\). At step \(i\), the stored set holds every pair sum with both indices \(\lt i\): \[ H_i = \{\, a_p + a_q : p \lt q \lt i \,\} \]
  3. First query every pair that starts at \(i\), then add the pairs that end at \(i\): \[ \text{query: } x - (a_i + a_j) \in H_i \ \ (j \gt i), \qquad \text{then } H_{i+1} = H_i \cup \{\, a_k + a_i : k \lt i \,\} \]
  4. Simplest form: stored pairs use indices \(\lt i\) and queried pairs use \(\ge i\), so all four indices are distinct automatically. \(O(n^2 \log n)\).
Key observations
  1. Split the four into two pairs and look up one pair's complement among stored pair sums.
  2. At index \(i\): first query the pairs \((i, j)\) with \(j \gt i\), then store the pairs \((k, i)\) with \(k \lt i\).
  3. Stored pairs use indices \(\lt i\) and queried pairs use indices \(\ge i\), so all four are distinct automatically.
Brute force → why it dies
naiveFour nested loops.
cost\(O(n^4)\).
dies at\(n = 1000\) gives \(10^{12}\).
thereforeMeet in the middle on pair sums: \(O(n^2 \log n)\).
Diagram

Fibonacci Index

Accenture · \(O(75 + T \log 75)\)
The ask

Question. The Fibonacci sequence is \(F(0) = 0,\ F(1) = 1,\ F(i) = F(i-1) + F(i-2)\). For each of \(T\) numbers \(N \ge 2\), print the index \(i\) with \(F(i) = N\), or \(-1\) if \(N\) is not a Fibonacci number.

Input
\(T\), then \(T\) integers \(N\).
Output
For each \(N\), its index or -1.
Limits
\(1 \le T \le 10,\ \ 2 \le N \le 10^{15}\)
Sample
\(13 \to 7\); \(34 \to 9\); \(21 \to 8\); \(10 \to -1\)
Breakdown
  1. State it exactly: \[ \text{ans}(N) = i \ \text{ such that } F(i) = N, \quad \text{or } -1 \]
  2. Fibonacci numbers grow like \(\varphi^i / \sqrt{5}\) with \(\varphi = \frac{1 + \sqrt 5}{2} \approx 1.618\). So \[ F(i) \le 10^{15} \iff i \lesssim \log_{\varphi}\!\big(\sqrt{5} \cdot 10^{15}\big) \approx 73.5 \] There are only about \(74\) values to consider.
  3. Simplest form: build a map from \(F(i)\) to \(i\) once, with exact integers, and answer each query with one lookup. (\(N \ge 2\), so the repeated value \(1 = F(1) = F(2)\) never matters.)
Key observations
  1. \(F\) grows like \(\varphi^i\), so \(F(i)\) passes \(10^{15}\) at about \(i = 74\). There are only about \(74\) values.
  2. Build value → index once; each query is then one map lookup.
  3. \(N \ge 2\), so the repeated value \(1\) (\(F(1) = F(2)\)) never matters.
Brute force → why it dies
naiveRegenerate the sequence for each query.
cost\(O(75 \cdot T)\).
dies atNever: \(T \le 10\). The real trap is testing \(N\) with a floating-point formula.
thereforeBuild the map once: the same speed, with exact integers.

The ask

Sample

Maximum Profit

HackerRank · \(O(n \log n)\)
The ask

Question. A shop has \(n\) items; item \(i\) has category \(c_i\) and price \(p_i\). The items are sold one by one in an order you choose. Selling an item earns its price times the number of different categories sold so far (including this item's category). Maximise the total profit.

Input
The arrays category and price.
Output
One integer: the maximum total profit.
Limits
Not given in the file.
Sample
category = [3,1,2,3], price = [2,1,4,4] → 29
Breakdown
  1. Let \(D\) be the number of distinct categories. The multiplier only grows, from \(1\) to \(D\), and it rises by one exactly at the first sale of each category (an "opener").
  2. So the \(D\) openers get multipliers \(1, 2, \dots, D\), and every other item can wait until all categories are open and get \(D\): \[ \text{profit} = \sum_{k=1}^{D} k \cdot o_k \;+\; D \cdot \sum_{\text{other items}} p \] where \(o_k\) is the price of the \(k\)-th opener.
  3. To maximise it, each category's opener should be its cheapest item (the rest then get the full \(D\)), and openers should be sold cheapest first, so small multipliers meet small prices (rearrangement inequality): \[ o_1 \le o_2 \le \dots \le o_D \]
  4. Simplest form, sample: openers \(1, 2, 4\) give \(1 + 4 + 12 = 17\); the other item \(4\) gives \(3 \cdot 4 = 12\); total \(29\).
Key observations
  1. The multiplier only grows, up to \(D\) = the number of distinct categories, and it rises once per category: on that category's first sale.
  2. The \(D\) opening sales get multipliers \(1..D\). Every other item can wait until all categories are open and get \(D\).
  3. Open each category with its cheapest item, and open the categories cheapest-first, so the small multipliers go to the small prices.
Brute force → why it dies
naiveTry every selling order.
cost\(O(n! \cdot n)\).
dies at\(n = 12\) gives about \(5\cdot 10^9\).
thereforeGroup, sort, and use the closed form: \(O(n \log n)\).
Diagram
Implementation

map<ll, vector<ll>> groups prices by category. After sorting, v[0] is a category's opener and fst collects the openers. (i + 1) * fst[i] pays the rising multiplier, and every v[i] with i ≥ 1 pays fst.size(). The hardcoded main prints the sample's 29.

    for i in range(len(c)):

Repeated String Cover

Harness · \(O(n + |\text{data}|)\)
The ask

Question. You are given an integer \(n\) and a string data of lowercase letters. Build a string \(s\) of length exactly \(n\). Repeat \(s\) the fewest times needed to reach length at least \(|\text{data}|\); the result must contain every letter at least as many times as data does. Print the alphabetically smallest such \(s\), or -1 if none exists.

Input
\(n\), then data.
Output
The smallest valid \(s\), or -1.
Limits
\(1 \le n \le 10^5,\ \ 1 \le |\text{data}| \le 10^5\)
Sample
Not given in the file.
Breakdown
  1. The number of copies is fixed: \[ r = \left\lceil \frac{|\text{data}|}{n} \right\rceil \]
  2. Every copy of \(s\) has the same letter counts, so letter \(c\) with count \(f_c\) in data must appear in \(s\) at least \[ \text{need}_c = \left\lceil \frac{f_c}{r} \right\rceil \text{ times}, \qquad \text{possible} \iff \sum_{c} \text{need}_c \le n \]
  3. Simplest form: fill the \(n - \sum \text{need}_c\) spare places with a (the smallest letter), then print all letters in sorted order, the smallest arrangement.
Key observations
  1. Letter \(c\) must appear \(\lceil f_c / r \rceil\) times in \(s\), because each copy of \(s\) contributes the same count.
  2. If \(\sum \text{need} \gt n\), it is impossible.
  3. Fill the spare places with 'a' and write all letters in sorted order. A sorted string is the smallest arrangement.
  4. When \(n \ge |\text{data}|\), \(r = 1\): \(s\) is data sorted, with extra 'a's at the front.
Brute force → why it dies
naiveTry strings in alphabetical order and test each one.
cost\(O(26^n)\).
dies at\(n = 10^5\): hopeless.
thereforeCount, divide rounding up, and print in sorted order: \(O(n + |\text{data}|)\).
Diagram
Implementation

The file defines its own integer ceil(ll, ll), which hides std::ceil for these arguments. In the n > ds branch, data is sorted descending and popped from the back, so it comes out ascending.

The ask
